## 本阶段完成的路径

首页点 **09:21–09:26** → 这个时段的应用贡献 → 天气 → 详细活动 → 一次查询阻止 → 原处调整 → 保存/生效反馈 → 后续活动或恢复处理 → 返回原记录与原时段。

- 手机首屏同时显示整体收发变化、查询/连接结果和首批熟悉应用；已经知道应用时可直接进入。
- 时段页默认显示收发总贡献，另可切换收到、发出、查询。只有查询、没有传输时默认显示查询贡献。未知归属独立保留。
- 图使用同一收发量尺；点击整列时段即可深入，另有可读的文字入口。手机贡献页压缩选区图，应用贡献前置；平板与 Linux 宽窗并排，窄窗逐层。
- 时间范围进入 URL，返回时恢复来源范围。应用、统计目标、地图、地区与记录保留各自范围；当前配置与历史结果分别表达。
- 记录中进入未生效处理时，配置页继续显示刚才的应用、目标及决定，重试后可直接回原活动核对。

## 样例与精确性

按已接受前提，Android 与 Linux 的应用身份、DNS/IP/连接能力均作为目标产品功能建模。浏览器只操作本标签页 `sessionStorage`；新 `scope` 值可隔离演示会话。阶段二使用新的存储前缀，避免阶段一旧样例污染预览。

| URL 参数                                     | 样例                                                  |
| -------------------------------------------- | ----------------------------------------------------- |
| 不指定 `view`                                | 有收发变化、查询阻止、已知应用与未知归属              |
| `view=dns-only`                              | 20 次查询被阻止，已记录传输 0 B，无连接               |
| `view=dns-gap`                               | 上述场景中 09:24–09:26 记录不完整，缺失记录不进入计数 |
| `view=gap`                                   | 收发活动中存在同一覆盖缺口                            |
| `view=quiet`                                 | 只有少量真实样例活动，没有异常判定                    |
| `view=no-activity`                           | 观测范围完整，但没有活动                              |
| `scenario=save-error` / `scenario=unapplied` | 保存失败 / 保存完成但尚未生效                         |
| `period=recent&window=15,20`                 | 最近30分钟中的09:21–09:26；分钟偏移基于样例时钟09:41  |

收发量来自明确的前端样例字段；图按记录时段聚合，**不是实时网速，也不是逐包采集证据**。DNS 次数、连接条数、传输字节分别计算。未知应用不伪装成系统应用，也不提供依赖已知应用身份的控制。地理位置来自本地样例，查询不会自动成为地图连接。缺口时只报告已保留的部分，不作前后比较或安全评分。

“查看后续活动”和读取动作不产生请求或记录。总览画面外的“加入一条样例新活动”按钮才生成确定的模拟活动，按当前模拟配置得出结果，并在记录中标明“样例新活动”。没有关联证据时不生成 DNS→连接关系；DNS 阻止时不伪造已建立连接。配置变化不改写原历史记录。

## 本轮乔布斯式审核

依用户要求，两位指定 `gpt-6-sol / xhigh` 子代理实际浏览手机、平板与 Linux 宽/窄窗口，按熟悉、直觉、聚焦、精确、克制、连贯与完成度作一次有界审核，不代言人物本人。已落实：

1. 刻度曾写成“4 MB/段”，零数据还出现“1 B/段”：移除易被误读为实测的刻度数值，说明收发使用同一刻度。
2. 时段贡献默认“发出”无法解释下载高峰：普通时段默认收发总贡献；只有查询时默认查询贡献。
3. 手机贡献页重复图表与多入口挤压所选应用：压缩选区图，贡献应用前置，其余深入入口放到列表之后。
4. 未生效处理脱离天气的决定：配置页保留应用、目标、查询范围与原活动入口，重试后返回核对。
