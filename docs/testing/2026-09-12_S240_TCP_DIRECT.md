# S240: real HEV/lwIP TCP4/6 Direct evidence

Executed on 2026-09-12 for SAKAMOTO-240. This records the TCP transport
increment of ADR-0007, not release readiness, a throughput/p99 qualification,
underlay migration, or the broader S241/S243 fault/lifecycle matrix.

## Product implementation

The unchanged offline HEV export remains pinned by
`third_party/hev/upstream-manifest.json`: tunnel
`3911f79434d9a27c3ae4e6e07df5cefe2c3d5c70`, lwIP
`8c69dfbe537835d5f2a5fd8c08c859f667b108ea`, task system
`b1afa0e21fb4ed5a69560e78e54baf0efdebe171`. Product changes are explicit
patches and `third_party/hev/product/` files; no POC or removed C++ source is
imported. The original license headers and APK notices remain packaged.

- `0010-owner-tcp-state.patch` moves TCP PCB lists, timers, counters, current
  input/output PCB and input scratch state into the explicitly selected owner
  context. TLS holds only the current-context pointer. A bounded owner timer
  drives the pinned lwIP TCP timer; there is no global lwIP lock or idle poll.
- `0011-direct-tcp-session.patch` extends the actual HEV TCP session, ring and
  socket splice implementation for Direct egress. The HEV ring retains
  socket-received bytes until lwIP acknowledges them. Writes are bounded by
  the negotiated MSS; transient output rejection leaves lwIP able to retry.
  The Direct build does not require a SOCKS server.
- A SYN-created transport owns the early SYN-ACK provenance. Its protected
  kernel socket connects only after successful Android bind/protect and the
  inner handshake. Refusal and peer reset close the transport and use normal
  lwIP return packets; they do not rewrite Policy Verdict as DROP.
- Graceful close can release the HEV task/ring/socket while the closing or
  TIME_WAIT PCB retains only its minimal transport facts. VPP FlowEntry and
  the S222 observation tracker remain independently owned and lived.
- TCP4/6 use the existing packet-in/packet-out copy boundary, canonical owner,
  native graph submission, return credits and TUN-origin completion. The
  completion result now occupies reserved metadata bits, preserving the TCP
  sequence/window facts and the 56-byte packet / 32-byte completion layouts.
- Quiesce prohibits new forwarding, drains accepted native work and destroys
  remaining owner-local TCP state. It may allocate/free a local abort RST pbuf
  without submitting that RST after the output gate closes.

## Regression and robustness checks

- Current-source standalone HEV suite: 18/18 passed. TCP4/6 tests alternate
  two contexts with identical inner tuples on one host thread, transfer
  73,728 bytes per context, cross ring/window boundaries, reject and lose
  output, and exercise retransmission, FIN, client/server close and refusal.
  The TCP kernel peers run in isolated user/network namespaces.
- UBSan with `halt_on_error=1`: 17/17 execution tests passed.
- ASan, non-PIE host executables, leak detection enabled: 17/17 execution
  tests passed. HEV's assembly coroutine stack switches still produce ASan's
  `__asan_handle_no_return` warning; this is not complete sanitizer coverage
  of custom-stack transitions. The native lifetime witnesses remain required.
- Linux and Android API 31/AArch64 lwIP archive state audits passed. The
  AArch64 optimized TCP state-name table is eleven read-only relative offsets;
  the audit checks its exact symbol, size and non-writable flags. Other
  writable storage remains restricted to the TLS selector and immutable
  relocation tables. This separate NDK build is a source-state audit, not a
  substitute for the executed APK.
- All 12 APK native libraries passed RELRO, BIND_NOW, non-executable stack and
  no-text-relocation checks.
- Existing shared TCP/UDP/FlowEntry host regressions: 4/4 passed.
- Same-APK real UDP4 owner 0 / UDP6 owner 1 return-DROP/recovery regressions
  passed, generations 1149 / 1150. Each has 18 controlled UDP packets and nine
  returns, with exact native settlement and both shards stopped. Their
  measured maximum stage legs, 6.595 / 4.501 ms, are bounded smoke observations,
  not a p99 claim or S248 performance qualification.
- Twenty corrupted evidence copies were rejected: wrong owner/TLS, wrong
  pbuf owner, missing/duplicate native free, missing/early return credit,
  clobbered TCP facts, incorrect OVS window, missing tracker update, mixed
  generation, forged UID/epoch, replaced transport, unsettled owner, wrong fd,
  TUN write after policy DROP, mutually consistent corrupted raw packets,
  unsuccessful broker bind, kernel-peer byte mismatch and false app report.

## Retained failures and limits

The first TCP macro patch collided with existing struct-field names; unique
context aliases corrected it. APK build-a exposed an old UDP metadata member
in the reassembly node; build-b uses the shared result bits. A burst test then
exposed an oversized transactional `tcp_write` against bounded lwIP capacity;
limiting each splice submission to the negotiated MSS restored real progress.
These failed build/test records are not acceptance.

The initial PIE ASan executable failed intermittently even for a standalone
malloc/free control (22/30 successful runs). A non-PIE control passed 50/50;
the non-PIE Product suite subsequently passed. Sandbox-only socket/namespace
and LeakSanitizer failures required the same suite outside the sandbox; no
Product checks were disabled. An initial standalone NDK probe selected API 28
and was correctly rejected for emulated TLS; Product fixes API 31, which was
then tested. These observations do not assert a diagnosed host-kernel cause.

The debug VPN validation profile continues to report `protectionRunning=false`.
Broader capacity/health classification and underlay invalidation remain the
separate S241/S243 scopes; this evidence neither closes those tasks nor
establishes release protection or full performance acceptance.

Supply the exact pinned OVS checkout, not an arbitrary local branch:

```sh

  --build build-output/s240-20260912/pixel-build-b/build.json \
  --run build-output/s240-20260912/pixel-tcp-matrix-a --ovs <pinned-ovs>
rtk proxy python3 tests/host/s240_tcp_verifier_negative_test.py \
  --build build-output/s240-20260912/pixel-build-b/build.json \
  --run build-output/s240-20260912/pixel-tcp-matrix-a --ovs <pinned-ovs>
rtk proxy env ASAN_OPTIONS=abort_on_error=1:detect_leaks=1:handle_segv=0 \
  ctest --test-dir build-output/s240-20260912/hev-asan-nopie \
  --output-on-failure -j2 -E state-audit
```
