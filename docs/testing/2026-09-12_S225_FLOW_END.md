# S225 owner-local FlowEnd

本切片实现并实测正常 FlowEnd 图闭环。范围是受控 UDP close/expire、TCP reuse
和被改动 graph/free 路径的回归，不是自动 idle expiry 或 allocator 耗尽恢复验收。
任务状态以 Plane SAKAMOTO-225 为准；真实 allocation failure 证据属于 S234。

## 实现

`product_flow_entry.c` 内部统一 close：验证 generation/incarnation → unlink → 保持
旧 entry allocated/immutable → 调用一次 composition delivery。旧槽仍计入容量；
同 tuple 的新 entry 只能使用另一个 free slot。实际附件尚不存在，公共 cleanup 当前
清理 inline state；没有预建附件/订阅管理框架。TCP 双 peer closed 后的新 SYN 也进入
REPLACED END，不再同步释放旧槽。原 entry 大小仍为 216 bytes。

`product_flow_end.c` 分配独立零长度 VPP buffer，将其直接送往当前 owner 的
`product-flow-consumer`。普通包从现有 policy/conntrack 节点进入同一个 consumer。
END 显式跳过 packet parser/selector/policy/handoff、VPN Flow Stack、NFQ/TUN
completion 与所有网络输出；不携带 AdapterObligation 或首包副本。终态数据从仍存活
的 entry 读取。正常 terminal 和受控 consumer 提前 free 都只调用 `vlib_buffer_free`，
pool free callback 才执行最终 entry cleanup/release。

END buffer debt 纳入既有 graph drain。quiesce 在 worker barrier 内取消尚未执行的
受控 close，不取消已经产生的 END；graph 排空后才允许管理 flush 直接清剩余 entry。
pending END 时 flush 返回 WRONG_STATE，不能由 stop 抢先归还被引用槽。
callback 在 plugin init 只注册一次，检查已占用错误；profile/generation 重启只重绑
已经排空的 runtimes。没有新 API/ABI、upstream core patch、retry/pending/emergency
pool 或普通 close 的直接 cleanup fallback。

实际 `vlib_buffer_alloc` 失败会输出明确 fatal 原因并终止 runtime。这里不把该代码
分支存在当作 S234 的压力、撤销接管及恢复证明，也不将普通 FlowEntry 满池升级为 fatal。

## pinned metadata/free 审计

VPP pin：`9258530f3804a152578ce11cc7c8a1e9eab88ed0`。
审计使用本次 Linux/Android build stage 的 `vlib/buffer.h`、`buffer_funcs.h`、
`buffer.c` 和 `vnet/buffer.h`；stage hashes 见 build witness。

| flags 区间 | pinned 分配 |
| --- | --- |
| bits 0–3 | VLIB IS_TRACED、NEXT_PRESENT、TOTAL_LENGTH_VALID、EXT_HDR_VALID |
| USER 1–18，即 bits 31–14 | VNET checksum、VLAN、SPAN_CLONE、loop、local、IP4/6、offload、NAT、header offsets、flow report、DVR、QoS、GSO |
| USER 19–27，即 bits 13–5 | VNET AVAIL1–AVAIL9；本切片未占用 |

USER 标记不能用作最终 free discriminant：`vlib_buffer_free_inline` 的 vector 与
single-buffer 路径都会先将整个 64-byte template 恢复，再调用 `vlib_buffer_pool_put`
中的 free callback。template 包括 flags/opaque，但不包括 opaque2。single/chain
路径只有引用数降至零才进入 pool put；本产品的 END 不允许 chain/clone/ref-sharing，
在 consumer/terminal 检查 `ref_count=1`、零长度、零 current_data 和零 opaque。

独立 END overlay 使用原有全部 56-byte opaque2，最后一个 byte 的 bit 7 为
`is_flow_end`。普通 packet 同字节的 runtime drop reason 保持 <128；fragment flags
不占该位，completion 的 32-byte overlay 不触及该位；写入点有 guard。upstream
对应字节处于 `vnet_buffer_opaque2_t.unused[4]`。所有 alloc（包括非 Product buffers）
先清该位，free 遇普通包只计数、不解析 entry；END free 检查当前 owner/thread、
generation、slot、incarnation、allocated/unlinked/reason，清标记并最终 release。

当前 Product graph 没有调用 native clone/copy/attach 或递增 ref_count 的 END 路径；
END 仅有 delivery → shared consumer → terminal/free 两种出口。没有增加 buffer-id
side table。禁止 clone 是接线约束与 native entry 检查，不声称任意第三方 graph 均可
安全复制此 overlay。新增其他 buffer 消费者必须重做这一审计。

packet stage/verdict、native vectors、端点缺失和 residue；不是只靠 hash 变动判失败。

  4 次 REPLACED）及 restart 112 包；当前 OVS pin 的独立 oracle 均 PASS。

  native terminal 结果，明确为 OS reclaim，不伪造逐项完成。

  original fragments 经过 Product 重组及释放，INPUT 由 kernel 先重组，二者不混淆。
  policy 客户端使用初始 user namespace UID 1000，匹配真实 NFQA_UID，非映射 UID 0。

  各有两个 owner × TCP/UDP × IPv4/6 共 8 条真实 TUN/Direct flow，停止前后数据和

  `192.168.4.5` 与 `fd76:d462:c4e3:0:49f3:929a:a311:d6e7`，不声称公网 IPv6。
- 当前 host 30 个适用 tests PASS，包括 END、TCP/UDP/storage、Root receive pool、
  policy、VAPI 和实际 Rust UDS lifecycle。S192 路由断言更新为共享 consumer。
- Clang 14 non-PIE ASAN+UBSAN 的 END/TCP/UDP/entry 四个 tests 各连续三次 PASS，

  或 undefined-behavior 检查；`detect_leaks=0`，不声称 LeakSanitizer 通过。
