# SAKAMOTO-171 Host Product Spine evidence

Date: 2026-08-28

This record covers the Host-only seam in SAKAMOTO-171. It does not claim an
Android, Root, VPN, packet, or network capability.

Scope exception: this is a Host-only pre-adapter control spine. It intentionally
has no packet adapter, Product VPP graph, or VPN Userspace Flow Stack, so its
Host PASS does not prove ADR-0007 Flow Stack behavior (or any ADR-0006 packet
ownership claim). Those claims require the later packet/adapter slices and
their own VPP/device evidence.

## Source and artifact identity

The product artifact is built from the official FD.io VPP source at the
revision recorded in `src/product/vpp/pinned-vpp-revision.txt`:

```
vpp.source.url=https://github.com/FDio/vpp.git
vpp.revision=9258530f3804a152578ce11cc7c8a1e9eab88ed0
product.api.identity=product_core.api/1.0.0@1b103f1d
product.plugin.allowlist=product_core_plugin.so
control.transport=generated-vapi-c-blocking
```

The reproducible build entrypoint is
`tools/product/build-host-artifact.sh`. It verifies the exact Git revision,
rejects a dirty VPP checkout, builds the plugin using the pinned VPP
`add_vpp_plugin`/generated-VAPI CMake pipeline, copies the VPP executable/core
libraries, and writes hashes to the artifact manifest. It can invoke the
official VPP `build-release` target with `BUILD_VPP_RUNTIME=1`; otherwise
`VPP_INSTALL_PREFIX` must identify an already-built install of that exact
checkout.

The local backup VPP checkout was intentionally not used as an artifact: its
revision is different and its worktree is dirty. The real VPP artifact build
therefore remains `NOT RUN` in this environment; no fixture is counted as a
Product VPP Graph PASS.

Generated/build output is kept out of source tracking: `/target/`,
`/build-output/`, and the legacy root `product_core.api.c` generator output are
ignored. The artifact's generated API JSON is copied under its own manifest
and hashed during the real build. The same manifest also records a
`vpp-libraries.sha256` file; the launcher verifies the complete copied shared
library set, so the VPP executable, headers/generators, and libraries cannot be
silently mixed from different installs.

## Lifecycle and residue contract

`ProductCore` owns one non-`Send`/non-`Sync` session per active generation.
The C session is blocking and mutex-serialized; query never reconnects. A
disconnect leaves a tombstone that reports `STALE_HANDLE`, and the Rust
generation ledger rejects reuse of a retired generation while permitting the
next generation. `run-host-vpp.sh`, `query-host-vpp.sh`, and
`stop-host-vpp.sh` use a runtime-local owner PID, generation marker, explicit
API/CLI/stats socket names, and an exact executable check. The stop helper
removes only those generation-owned files. `host-residue-check.sh` independently
inspects that PID, `/proc/$pid/exe`, the generation marker, each named socket,
startup config, and unknown runtime entries; it never scans by process name. A
VAPI handle is process-local and is therefore not claimed observable after the
owner exits.
