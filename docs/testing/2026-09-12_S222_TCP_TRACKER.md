# S222 TCP tracker evidence

This is the shared owner-local TCP observation tracker, not VPN TCP transport,
stream reassembly, an expiry scheduler or release-performance qualification.
SAKAMOTO-222 owns this increment; SAKAMOTO-240 separately implements TCP Direct.

## Implementation and source

The protocol core adapts OVS v3.1.0 commit
`3c2bea086ef8912d57331173af266f21d36740a0`, `lib/conntrack-tcp.c`, SHA-256
`94f0b7379399334824ebfd9fa3ae7ec14545eb252cfea789efbc6ec0ec23fdb1`.
Its BSD two-clause notice is retained in `product_flow_tcp.c` and
`src/product/NOTICE.tcp`, installed with Linux artifacts and packaged as
`assets/product-tcp-notices.txt` in Android APKs. The TCP file is not
incorrectly relabeled Apache-only. The common OVS baseline attribution remains
in `docs/reference/OVS_CONNTRACK_BASELINE.md`.

`product_tcp_update` accepts only existing parsed facts, state and ORIG/REPLY.
Both peers retain sequence bounds, maximum window, scale/negotiation bits,
phase and accepted flag history. There is no new packet parser, table, lock,
socket operation or clock. The state occupies the existing FlowEntry protocol
union. Invalid updates discard the local candidate; observation counters may
advance, but accepted protocol state and expiry intent do not.

An invalid new TCP candidate returns INVALID facts without allocating an entry
or changing the packet verdict. A new SYN after both old peers have closed
requests replacement. FlowRuntime unlinks the old instance before recycling
its slot, resets policy/accounting/origin state and assigns a new incarnation.
This is the explicitly permitted synchronous S222 stage: no asynchronous
FlowEnd consumer retains the old entry. S225 still owns that later lifecycle.

| Pinned OVS branch | Product behavior and consumed facts | Verification |
| --- | --- | --- |
| `tcp_invalid_flags`, `tcp_valid_new` | Parsed flags; reject illegal combinations and new SYN+ACK; no fake entry | Invalid-new kernel-capture cases; host flags vectors |
| `tcp_new_conn` | seq, payload length, window and parsed scale; SYN_SENT/CLOSED, FIRST_PACKET; loose midstream scale-unknown | SYN/midstream real connections; scale 0..14 and clamp host vectors |
| Early SYN update | Same-side SYN retransmit remains VALID_NEW/FIRST_PACKET; closed pair requests new instance | Real kernel SYN retransmission, RST then same-tuple reconnect |
| Normal sequence/window path | Modular bounds, ACK skew, negotiated scale, exact/±1 RST; peer state and selected timeout update | Every real update replayed through pinned OVS; bidirectional retransmit and wrap host vectors |
| Permissive path | Preserve the OVS loose pickup/close behavior; accepted packet need not refresh | 11,967 permissive/no-refresh differential steps; native replay |
| FIN/RST and timeout selection | FIRST_PACKET/OPENING/ESTABLISHED/CLOSING/FIN_WAIT/CLOSED remain distinct classes | Real FIN/RST and all six classes in native trace; host lifecycle vectors |
| `conn_update_state` mapping | VALID → ESTABLISHED fact; VALID_NEW → NEW, independently of internal handshake phase | Native and host reference comparison |

The optional upstream switch that disables sequence checking is not a new
Product setting. The pinned enabled sequence-check behavior, including its
permissive branch, is retained. INVALID is not malformed L3 or Policy DROP.
Default timeout seconds remain those of the pinned policy table; this task
returns classes/refresh intent and does not start a timer.

Run paths are under `build-output/s222-20260912/`. Counts are NFQUEUE original
captures, including distinct OUTPUT and INPUT obligations on loopback, not
unique application messages. Each normal run includes 12 INVALID captures
and four closed-tuple replacements. Kernel TCP sockets provide handshake,
data, timed SYN retransmission, midstream pickup, FIN, RST and reconnect.
Retransmission is induced by a temporary, narrowly matched downstream SYN
drop; midstream capture starts after the real socket connects. Two raw invalid
sequence/ACK probes target each selected existing test connection; valid
application data still echoes afterward. Invalid-new raw probes are explicitly
separate from successful kernel TCP connections. All traffic is controlled
loopback, and all packet-domain witnesses are NFQ_CAPTURED, not graph injection.

`verify-s222-tcp.py` checks actual wire fields against parser facts, computes
canonical ownership independently, then replays every update through the
unchanged pinned OVS protocol functions in an independent oracle library.
It checks peer state, sequence/window/scale, timeout, refresh, INVALID rollback,
replacement and origin reset, plus native buffer identity, origin verdict and
exactly-once free. Both runs clear entries, completion obligations and queue
lanes, and terminate the owned native processes. Linux additionally proves
all four queue IDs can be bound again; rootless procfs listing denial is not
mistaken for an empty queue table.

Additional checks:

- ASan/UBSan host vectors: handshake, both-direction retransmit, scale,
  wraparound, loose pickup, invalid candidate rollback, FIN/RST and full-pool
  same-tuple replacement passed.
- 131,072 seeded differential steps: 73,080 valid, 53,884 invalid, 4,108
  replacements; peer/state/timeout results agree with the fixed OVS source.
- Seven corrupted evidence copies were rejected: wrong thread, wrong window,
  missing update, duplicate free, implicit drop, mutated INVALID state and
  cross-generation event.
- Existing Linux S221 matrix: 239 endpoint cases, including small capacity,
  collisions and restart, independently passed on build-b. Its verifier now
  explicitly handles invalid-new TCP with no entry instead of assuming every
  successful observation creates or reuses a slot.
- Same-APK real VPN UDP6 owner 1 and UDP4 owner 0 regressions passed, generations
  1144/1145. Native wake behavior and both shard cleanup remain intact.

## Retained diagnostic failures

Build-a's old collision fixture supplied zero TCP header/flag placeholders;
its real on-worker check failed at step 14. Build-b supplies valid midstream
facts and reruns the check. Other retained runner failures concern the wrong
readiness field, pushing a config into a root-owned Android directory, and a
client-exit/log-read race. The latter had all three real server echoes; the
runner now rereads the final log after observing exit. These failed records
were not relabeled as acceptance. The final Linux run adds actual queue-bind
proof because the rootless namespace cannot read the procfs queue listing.
