## Failures and limits retained

Failed attempts are raw evidence, not passing runs: `s303-root-first/` had a Host endpoint launched with the wrong UID; `s303-root-second/` had a stale topology assertion; `s303-root-third/` used a request-conditional echo helper; `s303-root-policy-first/` called the retired policy CLI; `s303-root-final-a/` lost the controlled Host route during its third generation and recovered when Wi-Fi returned; `s303-root-fragment-n1/` called a stale policy helper built for an older native ABI; `s303-vpn-n1-short/` exposed a stale verifier expectation for short-write accounting; `s303-invalid-first/` lost an empty ADB Intent extra and `s303-invalid-second/` misidentified Android's own owner-audit shell as a VPP process; `s303-vpn-final-n1-fault-fragment/` used a graph-validation Activity branch that does not forward the owner CPU extra; `s303-vpn-final-n3-fault-fragment/` did not trigger congestion in one burst. These were runner or environment failures, not observed Product packet-domain defects. The passing interim `s303-root-final-{b,c}/` and `s303-root-fragment-{n1-b,n3}/` runs preceded the reviewer-requested owner-lifecycle/source-binding extensions. The successful final replacements above preserve their raw predecessors.

The actual Product defect found was the Android status replacing a native `cpu_config` placement rejection with generic `product_core_not_ready`. `WorkerCpuPlacement.nativeStartupFailure` now classifies a bounded native CPU configuration line before generation cleanup removes the log, and `RuntimeService` publishes its specific error code and detail. The red/green unit seam is `tests/android/WorkerCpuPlacementTest.java`; the Pixel negative matrix proves the integrated state and cleanup.

`tests/android/android-runtime-contract-test.sh` and the relevant S173/S187/S196 contracts passed. The broad Android `tests/android/runtime-contract-test.sh` stopped at S192's existing reference to removed `crates/product-core/src/policy.rs` (`build-output/s303-android-runtime-contract.log`). Full Host CTest was 62/67 (`build-output/s303-host-ctest.log`): #28/#31/#51 are older source-token contracts, #44 is the pre-existing S192 removed-command fixture, and #64 was sandbox Unix-socket denial; #64 passed with socket access in `build-output/s303-host-socket-escalated.log`. These five are the same S302 baseline failures; no scoped Product runtime test failed. `git diff --check`, Python compilation of changed runners/verifiers and the S231 negative oracle passed.

An earlier restoration audit remains in `build-output/s303-final-device-audit/`.
