## Resolved premises and limits

Initial UI scripts began below or clipped past the controls; after three locator
failures the actual layout was inspected together and fresh Activity/bounds/content
matching fixed the harness. The same old APK then produced a substantive missing-
fields red; the migrated button passed. The unsigned-precision failure and the
hour/day field mapping were resolved at the display boundary with actual response
comparisons; no shared JSON parser/store or native version was replaced.

An auxiliary ActivityRecord check initially expected a page before a headless
query; that query already calls finish, so the premise was false. The original
Root3051 failure/restoration stays in `final-qualified/final-display-result.json`;
the final VPN scene checks visible page→finish→no page→same-generation observation
→reopen directly. A default-user(-2) idle-service cleanup request was rejected by
Android cross-user permission checks; final cleanup used the actual user0 and
observed no service before releasing cached diagnostics. No permission was expanded.

Historical evidence, failures and frozen deliveries remain unchanged. This is
scoped functional qualification, not Product UI/release/performance qualification.
STOP still does not manufacture END; HTTP names are bounded snapshots rather
than a request timeline; DNS attribution and existing coverage gaps remain explicit.
No unresolved S332 product blocker remains.
