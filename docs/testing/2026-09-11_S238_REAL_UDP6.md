Scope: IPv6 UDP through the existing Product HEV/lwIP Packet Interface,
protected Direct socket, shared owner/parser/policy and TUN completion.
This does not establish TCP or multiple active VPN transport owners.

All directories below are under `build-output/s238-20260911/`. Each passed
the device runner and `tests/device/verify-s237.py` against the same build c;

All runs stopped with zero observed buffers, obligations, frames, pbufs and
sessions, balanced socket creation/close and no live native process. Return
metadata preserves IPv6 addresses, family, protocol, owner, generation,
availability and provenance through admission/policy/terminal. Callback output
precedes later native graph execution; completion and free are checked once
per token. No per-packet second map, owner hash or POC transport is introduced.

## Dependency and regression evidence

The pinned offline lwIP build enables IPv6, including real ND6/ICMPv6 code.
ND6 caches, router selection and temporary buffers reside in the explicit
owner context; no fake ND6 implementation substitutes for required functions.
Automatic address configuration, MLD, fragmentation and reassembly stay disabled
in this transport profile. VPP retains the shared parsing/reassembly boundary.

Ten Host tests pass, including a real IPv6 kernel-socket echo, mandatory UDP6
checksum verification, two-context ND6 cache/formatting isolation and the
writable-object audit. A Hop-by-Hop UDP6 case exposed premature base-header
protocol rejection; patch 0009 now allows the existing native IPv6 parser to
validate supported extension chains. The Host `ipv6-extension` case passes;
`ipv6-malformed` rejects a truncated extension without a socket/session/output
or resource residue. These extension cases are Host seam evidence, not claims
of a full real-device IPv6 extension/fragment matrix.

The current NDK API 31 arm64 Release lwIP archive also passes the object-state
audit: only the TLS context selector and the const pool-descriptor relocation
table occupy allowed writable sections. The final APK's twelve native ELF
payloads pass GNU_RELRO, immediate binding, non-executable stack and no-TEXTREL
checks. These checks complement, not replace, device lifecycle evidence.
