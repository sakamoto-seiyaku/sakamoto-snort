# S223：owner-local UDP tracker

证据状态：同源 Linux NFQUEUE 和 Pixel Root 完整矩阵 PASS；任务状态以 Plane SAKAMOTO-223 为准。

## 实现边界

`product_flow_udp.c` 是纯 C 协议更新函数，只消费 shared parser 的 PacketFacts、当前 UDP
state 与 first-observed ORIG/REPLY。状态占 tagged union 中一个字节，FlowEntry 仍为
184 bytes。没有第二张 UDP 表、逐流分配、NAT/zone、transport ownership、clock 或 timer。

`product_flow_entry_observe` 在原有 owner-local runtime 中调用它，返回独立的 tracker
result：CtFacts、更新结果、timeout class 和刷新意图。输入 PacketFacts 只同步借用，
不存入 entry。packet facts 缺失或不完整时返回 Interface error，不以容量 bypass 掩盖。
协议函数无效输入返回 INVALID、不刷新、不半更新协议状态；INVALID 本身不是 Policy DROP。
TCP/ICMP 的协议 union 仍为占位，result 为 NONE/UNKNOWN，不能因创建 entry 就伪称 NEW。

Gate/L4 DROP 仍先于 lookup/update；policy revision 改变只失效 decision。FlowRuntime
继续拥有 key、hash、owner、容量、方向和 per-side counters；tracker 不重新选择 owner，
也不以地址排序、端口大小、INPUT/OUTPUT 推断客户端/服务端。

本项没有消费 timeout 秒数或进行自动 expiry。`refresh_deadline` 是后续统一调度的输出
意图，不是已经存在 deadline/timer 的声明。ct 规则、FlowEnd、TCP/ICMP tracker 与 VPN
transport readiness 都不在本次交付中。

| OVS `conntrack-other.c` 分支 | Product 分支/输出 | timeout class（母本默认秒数） | 验证 |
| --- | --- | --- | --- |

| `other_conn_update` FIRST、非 reply | FIRST→MULTIPLE；NEW / VALID_NEW | OTHER_MULTIPLE（60） | host 同向；真实 `same` |
| MULTIPLE、非 reply | MULTIPLE 保持；NEW / VALID_NEW | OTHER_MULTIPLE（60） | host 同向；真实 `revision`、`same-only` |
| reply 且非 BIDIR | FIRST/MULTIPLE→BIDIR；ESTABLISHED / VALID | OTHER_BIDIR（30） | host 直接/延后回复；真实 `direct-bidir`、`bidir` |

内部 OTHER_MULTIPLE 对应 OVS policy UDP_SINGLE，OTHER_BIDIR 对应 policy UDP_MULTIPLE。
这里的 result/enum 是内部 C 类型，不是新的 wire ABI。

## 真实端点验收

最终目录：Linux `linux-udp-c/final-verification.json`、Pixel `pixel-udp-b/final-verification.json`。
两平台逐项结果相同：

| 单一 hook | endpoint 场景 | captured / completed / freed | entry | 反向端点首见 ORIG |
| --- | ---: | ---: | ---: | ---: |
| OUTPUT | 106 | 178 | 40 | 8 |
| INPUT | 104 | 176 | 40 | 8 |

每组包含 IPv4/IPv6、两个 canonical owners、实际 local/remote 处理。固定地址对的内核
placement 在一组内固定，不声称每个 owner × 每个 family 都同时具有两种 placement；
但两种 family 都有真实 local 和 remote 路径，且两个 owner 都有双栈更新。
不同 hook 使用不同 runtime generation，复用相同 tuple 后重新从 FIRST 开始。

每个数据报只经过一个 hook，避免 loopback 同一报文在 INPUT/OUTPUT 各观察一次而掩盖
FIRST。独立 endpoint 可只接收不回复，也可明确回复；最终保留单包 FIRST、同向 MULTIPLE
以及 BIDIR 流。反向首包从 canonical endpoint B 发出，其首次 trace 仍为 ORIG，后续
endpoint A 回复才为 REPLY。Device Packet Direction 在一组内保持 INPUT 或 OUTPUT，
与两侧 flow direction 独立。

每组七种转换的实际计数：EMPTY→FIRST 40；FIRST→MULTIPLE 20；MULTIPLE 同向保持 52；
MULTIPLE→BIDIR 16；FIRST→BIDIR 16；BIDIR 的 ORIG、REPLY 各 16。每条 tracked token
都核对 CtFacts、update result、timeout class、refresh、incarnation 与 per-side counters。
revision 前后保存分阶段快照；已存在的 UDP 状态与 incarnation 不被清空。

独立 verifier 同时核对 actual VLIB worker vectors、完整 typed key、唯一 owner、buffer、
原 queue/lane/packet ID、completion producer/consumer、NF_ACCEPT/NF_DROP 和 native free。
OUTPUT 中既有流的 Gate DROP 无 tracker trace、不增加 flow counters；INPUT 的本地
datagram 没有 NFQA_UID，不虚构 app-scoped Gate 命中，仍覆盖 revision publication/update。

Stop 后两个 FlowRuntime entries 为零、四条 lane 关闭、queue 释放，buffer/obligation/
handoff/completion debt 为零。本轮 hook 和测试地址删除，owned processes 退出。
Pixel 同 APK 的 RuntimeService generation 1002 start/stop 与 residue projection 另行通过，
Wi-Fi 1→1。独立 native 测试的唯一临时目录保留供追溯，但没有活跃进程、hook 或地址债务。
