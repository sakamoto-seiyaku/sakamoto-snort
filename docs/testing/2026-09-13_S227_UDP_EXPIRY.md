# S227 — 生产 UDP owner-local expiry

父任务 S199；执行验收由 Plane S227 跟踪。本文是本轮实现与真实端点证据，不是发行容量、
VPN ICMP transport、TCP/ICMP 完整到期矩阵或整机性能承诺。

## 运行前固定的范围

基线 commit `22ac0135971ff9073dd950874f63dbc70e522812` 已完成 S226，选择 owner-local
deadline wake。S227 沿用同一预分配 indexed index、每 owner 100 END/batch、至少 100 ms
的工作间隔，以及原生 one-shot timerfd／现有 VPP worker file polling，不改全局 packet wake。
正常 runtime 从空表绑定该驱动，不扫描已有 flow，不需要实验 arm 或测试端口才能挂 timer。
旧 A/B 入口只在显式 `product-flow-expiry { experiment }` 测试启动下开放。

当前只启用 UDP FIRST/MULTIPLE 60 s、BIDIR 30 s；来自既有 OVS pin
`3c2bea086ef8912d57331173af266f21d36740a0`。只有合法 tracker refresh 意图更新 deadline。
timeout 映射独立于 wake/容器，未接入的 TCP class 不返回假 deadline；ICMP 由后续切片加入。
期限使用当前 owner 的 `vlib_time_now` 微秒域，饱和加法不回绕。

同一个 Product source closure 分别构建 Linux 原生插件和 Pixel APK；保存 commit/dirty diff、
source/native/VPP/APK/helper hashes，并实际部署。Pixel Root 与 Linux 独立 rootless netns
均为真实双栈 UDP socket/NFQUEUE，不用 graph injection、FlowEntry 注入或 fake clock。
W2、四条 NFQUEUE 176–179，私有 loopback 规则只捕获测试端点；App 先停止，结束清理自己的
hooks、队列、地址与进程。普通用例 capacity 1024/owner，lookup backlog 用例显式配置
4096/owner；二者都是验证设置，不重新定义发行默认容量。

## 固定真实时间用例

每个小用例每 owner 两条 flow，IPv4/IPv6 各一条；发流器按独立 oracle 的 tuple 建立并
始终保留同一批 socket。`S` 表示服务器收到后不回应，`E` 表示回送原始 nonce；控制命令
不制造或刷新 flow。所有发送和接收都有独立 CLOCK_MONOTONIC 时间与唯一 nonce。

| 用例 | 真实端点动作 | 检查 |
| --- | --- | --- |
| first | t=0 发 S，之后保持 socket 静默 | FIRST deadline=最后 observation+60 s，无新包正常 END |
| renew-first | t=0 S，t=20 s 同 socket 再发 S | FIRST→MULTIPLE，deadline 续至约 t=80 s；过原期限仍存活 |
| shorten | t=0 S，t=10 s 同 socket 发 E 并收到 reply | BIDIR deadline 缩至约 t=40 s，早于原 FIRST 期限 |
| renew-bidir | t=0 E，t=20 s 同 socket 再发 E | BIDIR 续至约 t=50 s；过原 t=30 s 仍存活 |
| bulk | 512/owner 真实 E，之后无测试报文 | 有界 batch、预算耗尽、due backlog、最老 overdue、最终清空 |
| lookup | 4096/owner E，随后刷新每 owner/family 的一个目标；目标真实期限后约 100 ms 再发 E | 利用正常批量 backlog，使尚未物理释放的逻辑过期旧 entry 走 EXPIRED END；新 incarnation 不覆盖旧 slot |
| stop | FIRST flow 尚未到期时，向真实 owner callback 交付受控旧 generation 通知，随后正常停止 | 旧通知拒绝，不改变当前 entries/deadlines；stop 关闭 timerfd 后 drain、管理清理 |

lookup 不暂停 scheduler、不回拨或推进时钟、不用受控 close 代替逻辑过期。若实际 backlog
已先清理目标，不能宣称验证了逻辑过期命中，须保留结果并改进输入时序。旧 generation
通知是明确标识的 native callback 负向输入，不伪称内核自然投递了旧 FD；其他真实到期
用例同时证明有效 timerfd 通知会被正常处理。

## 判定和证据端点

每条正常到期最终释放都由 native free callback 成功归还 entry 后记录，不以唤醒、unlink
或 END 分配替代完成。小用例 p99 ≤1100 ms、max ≤1500 ms；bulk 使用 S226 已通过的
1000/owner 批量上界（最老 overdue ≤2 s、全体释放距最早 deadline ≤3 s）；lookup 的
4096/owner 原始批量使用 ≤6 s／≤7 s。期限本身不为这些容差改变。lookup 新 incarnation
仍按自己的真实 BIDIR 30 s 到期，并另验其正常尾部。

必须核对所有 endpoint nonce、typed key/owner、真实 UDP phase/双向 packet/byte 计数、
每个 deadline 和 generation/slot/incarnation 的唯一 END/release。每 batch ≤100、间隔
≥100 ms；日志记录当前 timer 总量、下一期限、是否仍有 due backlog、最老 overdue 和预算
耗尽次数，不能通过无界扫描计算 backlog。详细测试启动可显式 `trace-all`；正常 release
日志有每 owner/generation 上限，普通 packet 和完整 END graph 路径仍保留既有有界采样。
必须分别说明全量守恒与逐 identity 样本范围。

每代默认启动即为 deadline 模式、两 owner 都有真实 timerfd backing；空表 disarm。
最终 entries/timers/pending END/原包 obligation 清零；正常到期用例不能用 administrative
cleanup 冒充 END。stop 用例允许已 drain 后的管理性 entry 清理，但 timerfd/queue/hook/
native buffer 必须归零。S234 的 END buffer 耗尽仍属于致命 runtime 故障，不新增 emergency
pool 或 retry pool。旧 END 生命周期、Root 故障回收及 VPN 活跃流生命周期做同源码回归。

### 保留的失败与采集修正

1. `linux-a-smoke`、`pixel-a-smoke` 在 seed 之前因 `expiry.owner` 字段读取失败。
   共享 rows helper 丢弃首 token，本 collector 改为保留所有 k=v token；真实 FDinfo 读取
   unit test 先红后绿。失败 run 保留，不改写为 PASS。`pixel-b-smoke` 仅 first/stop
   VALID_PARTIAL，完整结论来自后续 `pixel-c-full`。
2. `linux-c-full` 前五项采完，lookup 准备 8192 个 socket 超过原初始 75 s 等待。
   当时尚无 endpoint phase 输出和测试报文；最小 bind 探针显示 host sandbox broker 的
   `seccomp_do_user_notification` 累计开销，不是端口永久拒绝，也不是 UDP timeout。
   只将首次 socket 准备/首 phase 的等待上界改为 180 s，后续 phase 仍 75 s，未改 helper、
   端口或 Product。完整 `linux-d-full` 实际准备加首 phase 84.124 s；3 个单测固定这个区分。
   原失败 run 的正常 cleanup 与原日志保留，不把其前五项拼成完整 PASS。
3. 旧 S225 Pixel 受控脚本在慢速控制操作中跨越真实 UDP 30 s，自动 END 使原受控计数
   断言失败；cleanup 又被断言短路。`end-pixel-a-regression` 保持 HOLD，额外原始日志和
   后清理记录留在 `post-cleanup/`；只对已核验 argv 的本测试 native/端点 PID 执行清理。
   增加显式受控 END 隔离选项，并将进程关闭移到 finally、其他记录清理继续；真实 stop
   路径强制断言失败的 regression test 先红后绿。最终回归另开 b-isolated，不覆盖失败。
4. S234 verifier 仍写死 S225 的 216-byte entry，两个新 source-bound run 均在此处失败。
   运行时 `sizeof` 与 pressure trace 都是 S226 增加索引字段后的 232 bytes；只同步当前 ABI
   断言，保留 capacity/实际 pool/耗尽与恢复门槛，并增加 runtime/pressure 两个旧尺寸负向。
5. S227 raw negative 的错误最终 budget 累计值最初被接受，补上 final owner 的
   batches/checks/closed/budget/oldest 累计交叉核对；随后所有 40 项负向通过。

这些修正只涉及采集/验收工具，不改变本节 Product source closure。原始失败、成功 run
及各自冻结输入均保留；旧 A/B 实验证据仍属于 S226，S227 不重选 wake winner。
