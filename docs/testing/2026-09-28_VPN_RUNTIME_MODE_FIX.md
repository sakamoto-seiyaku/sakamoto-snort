# VPP runtime mode hotpath 修復驗證（2026-09-28）

`product_vpn_tun_product_mode()` 與 `product_vpn_tun_enabled()` 現在讀取 VPP 進程固定的三態值：disabled、graph validation、Product VPN。`product_core_init()` 在進程啟動時解析 `SAKAMOTO_RUNTIME_PROFILE`、`SAKAMOTO_PRODUCT_VPN_PRODUCT`、`SAKAMOTO_PRODUCT_VPN_GRAPH_VALIDATION` 一次。Root 或無效 profile 保持 disabled；正式 VPN 優先於同時設置的 validation；Product readiness 仍另外要求 TUN、UID resolver、Flow Stack 和 graph ready。RuntimeService 在啟動子進程前設定環境，切換 profile 會先停止舊 VPP 再啟動新進程。

時序已在本輪 pinned VPP 源碼核對：`src/vlib/main.c` 先在 `vlib_call_all_init_functions()` 執行 Product `VLIB_INIT_FUNCTION`，之後的 main-loop-enter 才在 `src/vlib/threads.c` 的 `start_workers` 建立 workers；初始 worker barrier 釋放後才 dispatch `product-adapter-start` process。mode 寫入先於 packet graph 和 worker 讀取，getter 無鎖、無 lazy init、無環境查詢。

原始 [VPN/Root 吞吐與採樣報告](2026-09-28_VPN_ROOT_THROUGHPUT_PROFILE.md) 的有效 VPN TCP 前 20 秒窗口有 VPP 3,938 樣本，其中 `getenv` self 277（7.0%），調用鏈指向 `product_vpn_tun_product_mode()`。本輪也把 `d5f014d` 的原 getter bodies 單獨編成 C translation unit，以 linker wrap 計數：正式 VPN 下 100,000 組 getter 調用增加 **600,000 次 `getenv`**。[對照腳本](../../build-output/vpn-mode-fix-20260928/baseline_getenv.py)與[結果](../../build-output/vpn-mode-fix-20260928/baseline-getenv.json)留在新證據目錄。修復後的 [host 真實 C 回歸](../../tests/host/vpp_runtime_mode_test.py) 測 Root、正式 VPN、validation、雙 flag、錯誤值和缺 profile 等八種新進程配置；每個進程初始化後改環境、重複 init、再調用 getter 各 100,000 次，查詢數均不增加。插件 init seam、Product VPP contract、Android runtime contract、S69 VPN matrix 和 platform boundary contract 均通過。
