# S314: VPN original-path TCP DNS

S314 connects the existing VPN Direct TCP path to the shared bounded DNS
framer, request correlation, whole-rule policy and normal SQLite observation
path introduced by S310–S313. It preserves the original resolver and DNS bytes.
No proxy, replacement answer, DNS cache or association consumer is introduced.
The authoritative scope is the [approved DNS specification](../product/APPLICATION_DNS_SPEC.md).

The current R5 qualification reconstructs all 104 planned groups with the limits
below. Delivery status belongs to
[SAKAMOTO-314](http://192.168.4.22:2080/work/projects/f55a54bf-1693-42a3-9e38-50128f4b3a7e/issues/1eea8535-1655-4c57-95ff-33ac167e2a0d).

## Shared processing and native lifetime

VPN TCP uses the same owner-local bounded parser and per-message DNS policy as
Root TCP. The selected HEV input context supplies the actual transport session,
underlay epoch and Flow incarnation. A narrowly matched, zero-epoch SYN/ACK can
establish the initial return anchor before the first DNS payload. Later payload
returns still require the exact stamped session, incarnation and epoch. The
existing Flow advancement and Adapter Completion owners remain unchanged.

Normal DNS ABI v7 accepts the VPN adapter profile while retaining all other
decoder guards. Packet UID availability and reliable DNS caller identity remain
separate. A first cold VPN query can correctly remain Unknown; subsequent
reliable queries and their responses must preserve the complete correlation
context and separate query/current-response policy lineage.

A split frame also separates its first observed caller identity from the UID
fact on the completing packet. For an Unknown DNS caller, independent generic
policy uses the current packet UID without upgrading the caller or rewriting
the retained question. A pure generic winner for a retained question or answer
cannot become a verdict or a new DNS rejection record for a packet travelling
in the opposite direction. That packet continues through ordinary current
policy. Existing whole-rule DNS restrictions, including mixed Boolean rules,
remain intact.

The [matched-ABI regression receipt](../../build-output/s314-vpn-tcp-20261023/semantic/current-packet-generic-matched-abi-green/receipt.json)
joins both failures against sealed R4 source to the R5 fixes. It covers both UID
availability transitions, IPv4/IPv6, PRE/POST policy, query/response identity and
retained-history behavior. The manual graph harness now derives its compilation
definition from the linked policy archive's actual CMake configuration. Earlier
receipts with a mismatched conditional struct layout remain unqualified causal
evidence; they are not used to establish these fixes.

An actual N1-stop/N3-start exposed a native VAPI allocation crash. A source-linked
regression with the pinned VPP libraries proved that observation initialization
could replace the process main heap, and a fresh thread could crash querying an
existing VAPI session. The fix bootstraps one shared process client heap and
selects/restores it for the observation consumer and every locked VAPI
operation and cleanup boundary. The
[positive lifecycle receipt](../../build-output/s314-vpn-tcp-20261023/semantic/client-heap-positive-r1/result.json)
covers 96 real RuleConfig queries across caller threads and fresh sessions plus
one real observation record. It does not claim to reproduce the exact Android
allocation size. The original N1-stop/N3-start subsequently passed on R4.

The final R5 Host suite passes 75/75 in one invocation; the HEV suite passes
38/38. Their [independent audit](../../build-output/s314-vpn-tcp-20261023/coordination/root-full-suite-r5-audit.json)
preserves the exact logs and artifact environment.

## Fixture failures and cleanup boundaries

Raw HOLD attempts remain unchanged. They include transport/read failures, an
App source-port collision with an orphaned Android tuple, and delayed ordinary
App completion reports. The fixture now observes all four kernel socket tables
before selecting a free source port, reserves each attempted port within the
runner, and never kills a socket to recycle it. Kernel orphan closing state is
distinct from Product-owned session, buffer, timer, broker and hook cleanup.

A bounded diagnostic without starting Product proved that Android could freeze
the cached main App while it held a completed socket. A successful run-as
release-file touch left it frozen and unchanged; normal own-App foreground
resumed completion in 288ms. The shared fixture now brings its normal Activity
forward after all captures, then touches the exact release marker within one
ten-second deadline. Native stop remains independent, and probe ownership is
cleared only after a real completion report. The existing actor and collection
budgets are preserved. This result does not retroactively classify every older
release timeout as a freezer failure.

The UI route also checks actual Awake state, a dismissed keyguard, the focused
own-App window and the captured own-App button before any tap or scroll. A
zero-exit wake command alone is insufficient. The remote UI capture is bounded
to eight seconds inside the remaining local budget; a foreign lock-screen
snapshot cannot trigger scrolling or a configuration action. The ordinary
guarded route passed without starting Product, then all ten previously
unproved N3 Root UDP cases passed through it.

A later task-owned control diagnostic reproduced connection stalls without
starting Product or sending DNS. Six fresh Linux ADB clients were independently
matched by PID, descriptor and socket inode to TCP `SYN_SENT` connections to the
existing Windows ADB listener. The [causal audit](../../build-output/s314-vpn-tcp-20261023/coordination/root-adb-syn-sent-causal-audit.json)
qualifies those six connection-establishment failures; it does not assign that
cause to every historical UI timeout. The raw diagnostic's successful sentinel
status and separate cleanup error are retained, with effective HOLD treatment.

An optional task-local connection relay makes at most six bounded upstream
connection attempts before forwarding any request bytes. A connected stream is never reconnected
or replayed. It preserves the repository ADB wrapper, existing server and USB
transport, exact output and remote exit status. Retries consume existing caller
deadlines; the matrix's 65-second connection lifetime and restoration's optional
125-second lifetime retain the existing 120-second restoration transfer limit.
Local cleanup never substitutes for Android exit and resource witnesses.
The [16 current Host checks](../../build-output/s314-vpn-tcp-20261023/semantic/adb-route-portable-r6/receipt.json)
exercise once-only delivery, failed connections, half-close, partial ownership,

[Standards](../../build-output/s314-vpn-tcp-20261023/reviews/standards-r5-adb-route.md)
and [Spec](../../build-output/s314-vpn-tcp-20261023/reviews/spec-r5-adb-route.md)

remote completion witnesses and zero remaining relay resources. Product stayed
stopped at generation2682 throughout that qualification. It retains its original
