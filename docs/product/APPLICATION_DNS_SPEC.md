## Problem Statement

应用既可以自己查询 DNS，也可以通过系统解析器、已有缓存或代理取得目标地址。只识别 DNS 协议，不能在查询前按应用过滤；只记录 IP，也不能证明后续连接访问了哪个域名。用户需要 Root 与 VPN 对同一政策给出一致、可解释的控制机会，同时保留原有解析器、自建 DNS 和内网解析用途。

规格形成时（2026-10-22），主线已有 VPP-native C 规则、FlowOwner、协议识别、TLS／QUIC SNI 和常态观察基础，尚未交付本规格所需的共享 DNS 查询／答复处理、代理、答案缓存或 DoT／DoH 客户端。已有系统名字解析、Fake-IP 映射或 DNS 协议标签不构成这些能力。

逐项临时设想容易忽略查询、答复、缓存、调用者和传输控制点之间的关系。本规格参考 Portmaster 已有的查询前检查、结果后复查、名单处理、上游尝试和结果采集流程，按现有 Root／VPN 与统一规则架构适配，并避开核对到的源码缺口。

## Solution

在现有 VPP runtime 与 FlowOwner 内形成一个共享 DNS Core Module。Root 与 VPN 的 Adapter 提供真实报文、调用者及网络上下文，负责各自转发、接管和回送；报文语义、政策、请求／答复对应、结果处理由共享实现承担。启用产品代理后，同一核心再使用有界事务、答案缓存和普通 DNS／DoT／DoH 上游。

未启用替换时，允许的普通 DNS 查询继续发往原解析器；启用明确作用于该路径的替换后，才进入产品代理。原调用应用可靠时执行其当前适用完整规则；原应用未知时允许 DNS 应用政策阶段的解析，不等候或猜测调用者。随后业务连接独立使用自身应用与实际取得的域名事实判断。

第一条交付闭环覆盖 Root／VPN、IPv4／IPv6、普通 UDP／TCP DNS 的原路径过滤、结果记录及干净停止。后续交付可选代理、缓存与普通／加密上游。完整首版仍包含已选 CNAME、连接域名来源和有资格的关联回退；施工先后不缩减范围。关联跨应用使用范围继续明确暂缓，其决定不成为全部 DNS 工作的前置。

## Implementation Decisions

### 1. Module 与权威

DNS Core Module 在既有 VPP runtime、FlowOwner 和事件推进中运行。共享其报文处理、DNS 政策、请求／答复对应、结果资格及代理事务逻辑；报文 codec、framing、缓存和运输实现保持私有。Adapter 负责 Root／VPN 的入口、原上下文、平台 socket 操作及交付。

对外 Interface 以 DNS 输入事件、可信上下文及实际处理结果为中心，不把 parser、TLS helper 或 cache 容器逐一公开。原路径提供实际可取得的消息／字节观察事件及进度，代理提供完整消息；两者可以到达不同事实就绪点，但不拥有两套规则语义。

VPP 仍是唯一配置、保存和规则编译权威。Rust 消费有界正常观察并存入既有 SQLite 通路；Java 承担平台授权、选网及 supervision。没有新增 DNS daemon、Rust 异步执行器、专用后台 DNS 线程或全局可变缓存要求。

普通启动自动完成所选路径需要的入口、监听／路由和 VPN protect／选网接入；用户不需要手工填本地代理地址或执行平台接线。启用替换仍由用户明确选择上游配置，自动接线不授权替换原解析器。

### 2. 输入事实和决定身份

输入保留运行 generation、owner、流 incarnation／本地会话身份、请求 token、设备与流方向、原始应用证据、原目的 resolver、网络代际、解析路由视图、传输及完整问题语义。平台值同时携带可用性和来源。

socket UID 已知不等于原调用 App 可靠。系统代查及未能证明原 App 的请求在 DNS 应用政策阶段允许，不等待 resolver 或通过进程名、当前流 UID、IP 关联猜测。已有通用包规则继续按其真实事实执行。异步归属信息不得回写已经完成的查询决定；更新请求身份必须有现有平台合同提供的同请求／incarnation 证据。

请求和答复使用有界对应表。不能仅凭 16 位 DNS ID 匹配：还必须核对会话／tuple、方向、Question、传输和解析上下文。重传、ID 复用和多个可能请求保留实际状态；对应不可靠时不得套用猜测的原 App 答复政策或产生可执行关联。

查询检查、答复检查和后续连接各自记录当时的 snapshot／rule identity。等待上游不冻结旧允许；答复交付前重新取得当前有效政策。历史结果不被后来的重评改写。

### 3. 统一完整规则与 QName／CNAME

查询以实际 QName 为候选；答复从原名追踪本次真实相连的 CNAME，保留各名字及来源。无关 additional、MX／SRV 目标、文本字段和 HTTPS hints 不自动成为查询别名、SNI 或可执行地址关联。

按统一 Rank 逐条取完整规则，再逐个候选名字求值。每次完整求值的全部域名条件绑定同一个名字，其他条件使用该控制点的真实上下文与可用性。任一候选完整满足规则时，该规则参与本阶段胜出；不先合并不同名字的名单位图再执行任意 AND 树。

Observe 模式保留胜出规则、声明动作及归属，实际政策动作仍是允许；不会据声明的 DROP 生成代理拒绝答复或阻断原路径。

同时选用多个名单采用 any-match，相当于相应条件的 OR；显式 AND、OR、NOT 保持原表达式。当前 DomainList 条件对应 PM 的名单 endpoint：别名名单命中可以产生本条规则声明的 ALLOW 或 DROP。不会因名单只含一个域名而改变成 PM 直接域名 endpoint 的“别名仅拒绝”操作。兼容例外以明确的高 Rank 普通允许规则表达。

缺失事实保持不可用，NOT 不将其变真；可用真分支可以使 OR 成立。DNS 包的地址、UDP／TCP 和端口仍指当前 DNS 运输事实，不是未来业务目的地址或 443 端口。答复 RDATA 不填入包目的地址，QName 不填入 SNI。带显式 SNI 条件的完整规则继续保持其协议适用性要求。

政策前置只能使用当时足以使完整规则成立的事实，不能裁掉业务条件后仅凭名字拒绝。查询阶段的胜出结果也不预测未来连接：一个随后连接可能满足的高优先级规则，不会追溯撤销已经合法完成的 DNS 阶段决定。

### 4. 普通 DNS 原路径

未启用上游替换时，Root 沿原内核转发，VPN 沿现有 Direct 运输；应用选择的公网／内网 resolver 和原有解析路径保持。共享核心在允许转发前检查可得查询事实，在返回时检查实际可得答复事实，允许的原报文不作政策性改写。

UDP 以完整 datagram 判断。原路径 TCP 使用 owner-local、有界、双向、可前移的 DNS framing／观察状态，处理两字节长度、拆段、合并帧、重复、乱序及同连接连续请求。只保存受预算约束的协议字节副本；原 NFQ／TUN 包不为识别扣留或重放，单次处理也不等更多字节。

首次取得足以证明查询或答复应拒绝的完整规则事实时，DROP 当前原包，并在当前政策下阻断该 TCP 流后续数据。该包／连接中的其他查询可能受到连带影响；不选择性删除 TCP 字节、不主动 RST、不生成原路径 DNS 拒绝答复。已转发字节不撤回，policy revision 变化仍按当前政策重评。

半途观察、缺段、冲突重叠、复制长度不足或超预算必须记录实际覆盖不足，不能报完整检查或伪造 NoMatch。DNS 专属事实不可得时，保留现有通用规则和既有处理故障／可安全转发合同；已经决定的政策拒绝不因观察资源不足被改成允许。Root 既有 fail-open 与 VPN 既有运输失败责任不被新增 DNS 观察重新定义。

### 5. 可选代理与拒绝／失败结果

代理路径由 Root 的本地 socket 入口、VPN 的本地 HEV／lwIP 会话交付完整 DNS 消息及原上下文。VPN 必须在建立原目的 Direct 上游之前选择代理会话；Root 接管普通 UDP／TCP 53 时保留可验证的原调用者／原目的上下文和合法反向回送。固定 VPN DNS 地址只属于代理启用路径。

本规格采纳 PM 成熟流程中的及时阻断反馈，并作明确适配：**原路径继续 DROP；代理的查询或答复政策拒绝返回 REFUSED。** 这项规格选择取代此前“代理政策拒绝也一律静默 DROP”的技术决定。REFUSED 是产品适配，不是 PM 默认合成阻断地址的原样行为。

查询拒绝发生在 cache lookup／合并／上游派发之前。答复拒绝不交付原始答案、地址或替代 IP，只生成本请求的明确拒绝结果，不新增／刷新可执行关联。代理 TCP 会话可以继续处理其他允许查询；不因一条被拒查询自动关闭整条会话。

解析运输全部失败或总期限耗尽且无合格有效答案时返回 SERVFAIL；保留已选上游配置。合法上游 NXDOMAIN、NODATA、REFUSED 或 SERVFAIL 按实际 DNS 结果处理，不为寻找正答案而改问别的 resolver，来源与本地产生的政策拒绝分别记录。

结构坏且可以安全答复的请求返回 FORMERR，未支持 opcode 返回 NOTIMP；无法安全取得回复身份时记录无答复原因。普通 QUERY 的多 Question 按 DNS 标准拒绝，不以遍历多个问题扩展政策含义。原路径的未支持／不可观察消息保留其原内容和真实覆盖记录。未知 RR 类型不属于这一拒绝理由。

生成的错误答复沿正常 reply／return Interface 交付，不再次当作新的 App DNS 查询。它没有另设全局允许特权；实际回送失败或独立适用的包规则阻断仍有真实交付结果。政策允许、答复准入和 App 实际收到不是同一个事实。

### 6. DNS 消息、缓存和运输兼容

普通 QUERY 支持标准单 Question、QNAME／QTYPE／QCLASS 和常见 flags／EDNS；A／AAAA、TXT、MX、SRV、HTTPS 及未知 RR 均保持可转发数据。完整 wire codec 不用地址数组重新拼一个简化答案，不因缺少类型专属提取器丢弃记录。

按已选 HEV 调度与小型共享 DNS 路线，优先窄复用 c-ares 的成熟 wire parser／encoder，按实际需要补 TTL／外部 cache 接点；不默认深 fork 整个 channel，也不将 mapped-DNS 的地址映射 parser 扩成通用 codec。若现有私有 cache 无法保持窄接点，则使用有界 owned-wire cache；正式依赖 pin、export 与接口闭包必须在对应实施任务验证，研究记录不视为已集成。

压缩指针、标签／消息长度、记录边界、循环和 CNAME 链均有显式上限。只将从实际 QName／CNAME 链可靠提取的地址记录用于关联。未知 EDNS 选项可以按消息语义透传；不能证明安全复用时不缓存、不合并，不能通过忽略选项扩大缓存命中。

代理 TCP 支持连续 framed 消息及多个有界在途事务，按请求身份回送，不依赖答复顺序。普通 UDP 上游的 TC 触发对同一 resolver 的 TCP 继续处理，保持原总期限。代理回送 UDP 时尊重客户端容量；需要截断时产生合法 TC 结果并支持 TCP 重试，不把截断片段当完整成功答案准入关联。

cache 仅保存有效解析数据，不保存允许／拒绝。上游原始有效答案可在 App 答复政策检查前进入数据 cache；某 App 拒绝交付不要求驱逐其他请求仍可合规使用的数据。每个请求／waiter 独立完成查询政策和最后答复政策。

正缓存按有效剩余 TTL，经过时间使用单调时钟。TTL 为零不延长缓存；不套用 PM 的固定输出 17 秒或最低 60 秒。NXDOMAIN／NODATA 仅按可验证 SOA 的负缓存合同存储；本地产生的 REFUSED／SERVFAIL、运输错误和策略决定不作为答案缓存。过期成功答案不作静默 stale fallback。

DoH 在入 cache／交付前计入 HTTP Age，并继续扣除本地经过时间；剩余 TTL 不低于零。协议要求的 TTL／ID／Question 回送处理与政策性改写分开：缓存命中恢复本请求的身份和可验证 Question 语义，不能因大小写、EDNS 或其他影响答案的差异错误命中。

### 7. 解析视图、路由与内网

解析上下文包含网络代际、明确解析路由、上游配置版本和实际 resolver 身份。缓存与同问题合并同时核对影响答案的完整问题语义，不能只有 QName／QType，也不能把 resolver A 的结果标成 B 的视图。

对一条代理路由，按配置顺序检查各候选自己的合格有效 cache／可用上游。一个候选仍有有效 cache 时，不要求网络连接成功才可使用；另一候选的 cache 只在其自身资格下复用。健康状态改变不伪造视图变更，用户修改 resolver／路由或换网则使受影响上下文切代际。

上下文变更使旧事务、答案 cache 和受影响活跃关联失去新视图资格。旧答复、bootstrap、broker 或 TLS 事件不得回写、回复为新视图结果或重新激活状态。原请求尚有合法回复通路时以解析失败结清，否则记录取消／运输结果；不把旧请求自动转成未授权的普通 DNS fallback。

加密替换覆盖捕获到的公共 resolver 普通查询，而非仅产品 DNS 地址。保留局域网／自建 DNS 和已有明确解析范围；不凭名字像公网、地址是私网或搜索域清单，承诺自动识别全部内网域。

Local DNS Resolution Exception 选择原网络或明确本地 resolver，既可精确名字，也可名字及后代。精确匹配优先，其次最长标签后缀；相同范围的冲突配置拒绝发布。它只选择解析路径，查询和连接仍执行当前政策。平台发现不到的范围由显式配置补充。

mDNS／UDP 5353 保持原系统／网络处理，不进入产品 DNS 查询域名过滤或加密代理。普通单播名字以 .local 结尾不自动等于 mDNS。既有通用应用／IP 规则和可观察协议记录继续执行；多播可达性必须用实际模式验证。

### 8. 上游、主备、bootstrap 与 TLS

上游支持明确选择的普通 UDP／TCP DNS、DoT 和 DoH。未启用替换时不主动改变原路径；启用后的候选只来自用户配置和该路由已有的明确网络选择，不添加隐藏的公共 resolver、明文后备或 factory default。

同一请求正常只询问一个候选；连接、授权、TLS、HTTP、超时或无效 DNS 消息等故障可按顺序尝试后备。有效 DNS 结果不触发寻找正答案；取消、停止和视图失效不记成 resolver 健康故障。普通 UDP 因 TC 改 TCP 是同候选的协议继续处理。

参考 PM 的失败恢复流程，失败标记必须有界失效，不能永久饿死主项。初次失败冷却 5 秒，连续失败最多 30 秒；冷却结束后由下一条合格查询触发一次正常尝试，成功回答恢复其原配置顺序。没有需求时不新增常驻网络探测或轮询；所有尝试受原查询总期限约束。

IP 端点直接使用配置地址；域名端点优先配置连接 IP，否则通过原系统／网络取得服务地址。bootstrap 仅服务产品连接所选上游，不递归进入产品代理，不为别的 App 同名查询提供政策豁免。地址、身份和网络代际分别保留；证书与服务身份校验始终执行，IP 形式验证其适用身份。

复用同一 Mbed TLS 项目补全 TLS／X.509／CA／RNG 能力，使用只读可信锚及有效平台支持。沿已有 socket 授权、protect／bind 和 fd／timer 事件推进，不在 worker 等 Java，不把 writable 当 TLS 已认证完成。

首个 DoH 运输 profile 采用有界 HTTPS POST、application/dns-message 与 HTTP/1.1，每连接一个在途 exchange；ALPN 只声明已实现协议。必须处理合法 HTTP framing、部分读写、错误状态、Content-Type、Age 和关闭。不开自动 redirect、压缩或 HTTP proxy。只支持 HTTP/2 的 endpoint 明示为未合格，不能悄悄降级或删除 DoH 需求。

### 9. 状态归属、合并、取消与停止

所有可变事务、观察 framing、关联和 cache 状态沿既有 owner 管理，代码共享不等于跨 owner 共享可变容器。直接使用现有 generation／incarnation、事件和正常 return/completion；不为 DNS 增设第二套身份权威或顺手开展暂停的 UID resolver 职责重构。

同问题合并仅在完整问题与解析视图等价、且各请求先通过当前查询政策后进行。每个 waiter 保留自己的原 App、ID、会话、期限、答复渠道及最终政策检查。取消一个 waiter 不取消其他活跃 waiter；全部取消后晚结果不能重新建立请求或向已结束通路写回。

每个请求在完成、拒绝、失败、取消或超时中只选择一次终结结果。上游原始数据 cache 的独立所有权与 waiter 的交付所有权分开；晚结果是否还可存数据也必须满足仍存在的合法同代际事务和预算，不能靠一个已销毁请求继续执行。

停止先拒绝新 DNS 接入，再取消活跃 DNS 工作和 waiter，沿既有 runtime 停止合同回收 fd、timer、消息、观察 framing、关联与等待身份。借用的 NFQ／VPP／HEV 内存不跨异步边界；原包义务不等上游完成才释放。旧 token 的事件只能被拒绝／清理，不得访问已释放对象。

干净停止由真实资源与 completion 结果证明。现有停止期限内未结清须报告失败，不用“进入 quiesce”或“队列看起来为空”冒充资源归零。

### 10. Domain-IP Association

真实解析结果、政策是否允许交付、关联是否合格分别处理。查询拒绝无成功答案；答复拒绝仅保留解析／政策观察，不新增或刷新可执行关联。允许交付但 return 失败也不能报告 App 已收到答案；关联准入与实际输出结果保持各自证据。

只从 owner 可连回原 QName／真实 CNAME 链的可靠地址记录建立关联。来源保留实际原 App 已知／未知、resolver、网络代际和结果身份，不自动提升无关 additional、SVCB／HTTPS 地址 hints 或文本内容。

用户决定（2026-10-31）：无论是否启用 DNS 替换，允许交付的原路径答案和产品代理答案都默认产生关联事实；关联是否参与决策由用户政策决定。关联事实按 FlowOwner 保存，DNS 配置变更不清除它，网络视图变化和该代理路由视图变化才排除对应 pair。

暂定有效窗口为两小时，与答案 TTL 独立。每次取得有效且允许交付的实际答案或当前视图有效 cache 答案，刷新本次实际返回的域名／地址 pair；业务连接和 fallback lookup 不刷新。

新答案含新地址时不立即删除旧 pair，也不给新答案缺少的旧 pair 续期。例如 9 点取得甲、10 点取得乙，甲到 11 点、乙到 12 点，各自仍受容量驱逐和上下文资格限制。换网或受影响 resolver 视图失效时排除旧的活跃关联，不保证 Android／App 因此重新查询。

只有一个合格域名候选才提供间接回退；没有或多个候选时域名不可用，保留观察证据，其他独立适用规则继续执行。一个候选也不是实际连接身份的证明。

关联跨应用／profile 的可见和使用范围继续后置。规格定义产生的事实、来源、期限及消费资格 Interface，不暗选“全部共享”或“只供本 App”。在该范围未选定时，不启用靠猜测范围运行的关联执法，也不把它作为查询过滤、代理或直接协议域名工作的阻塞条件；该部分验收明确保留范围限制。

### 11. 后续连接的域名事实

业务连接使用自身原 App。TLS／QUIC／DTLS 的 SNI 识别 pending 时先不作连接域名动作；保持其他规则及为识别所需包的正常前进。取得真实 SNI 时以它为准，关联不提供第二条冲突拒绝。结束但无可用 SNI 时才尝试有资格的关联，保留真实失败／耗尽／确认无 SNI 的区别。

DTLS 需要自己的真实握手／分片事实，不把已有 DTLS 标签当成 SNI 提取成功。直接 HTTP、SOCKS 与 DNS 来源不填入显式 SNI 条件。

可见明文 HTTP 逐请求按有效 request-target authority／Host 语义取得目标并重评当前政策，包括代理连接上连续的不同请求。IP 型目标按所请求目标 IP 尝试合格关联，不查代理服务器 IP。取得目标后若拒绝，沿现有 DROP 阻断该 TCP 连接后续流量，接受同连接其他请求受影响；不作选择性 HTTP 请求删除、错误页或主动 RST。首版明文请求解析从 HTTP/1.x profile 交付；加密 HTTP 继续走可见 SNI／合格关联路径，不宣称可读加密 authority。

SOCKS4a 与域名地址 SOCKS5 提供真实目标域名；普通 SOCKS4、IP 型 SOCKS5 按请求的远端目标 IP 尝试关联。保留请求来源、有效目标与外层代理端点的区别，不把协商标签当作目标已提取。

同网络的现有连接已经取得合格 DNS 线索后，不因原关联两小时到期清除其连接内事实；继续按当前政策重评。新流不能借用过期关联，旧流保存事实不延长 lookup 资格。真实直接协议域名仍保持其优先关系，已完成历史结果不回写。

### 12. 常态观察与控制配置

复用现有 bounded 正常观察与 SQLite，新增 DNS 请求／决定／解析结果所需记录，不再建另一个历史 store。允许、拒绝、Unknown、cache 命中和有限失败均可表达，不靠默认逐包 trace 证明覆盖。

保留请求／答复阶段、原调用者可靠性、QName／别名来源、问题类型、解析路由／resolver、cache 来源、真实 RCODE／错误、rule／snapshot identity、实际交付结果和关联准入原因。既有记录的缺失、丢失及背压必须可说明；导出不阻塞 packet／owner。

配置在 VPP 的原有保存、编译、发布和失效合同中扩展，包含替换启用、上游身份及连接地址、有序候选、内网例外和生效视图。不可用 endpoint／冲突例外拒绝配置或明确报告未生效；不因管理 API 活着就声明 DNS 可用。

产品自身加密上游完整可用后才允许推荐外部加密 DNS 阻断规则；推荐仍由用户选择启用。此规格不自动新增或启用这些规则，也不声称能解密外部 App 的 DoH／DoT。已有显式通用规则沿统一语义执行。

### 13. 有界运行默认值

以下为实施起点的有限工程默认值，不是性能或支持设备承诺。每个 owner 的有效配置和高水位必须可观察，启动时计算总上界；不得随请求／实验目录新建无上限容器。调整默认值属于可核验的实现校准，需同步记录和相应边界测试。

| 范围 | 初始上限／期限 |
| --- | --- |
| 单 DNS 消息 | 65,535 字节；TCP 两字节长度另计 |
| 相连 CNAME | 最多 32 个不同别名，循环立即终止 |
| 单原路径 TCP 流观察保留 | 双向合计最多 192 KiB，且计入 owner 工作字节 |
| 请求／答复对应表 | 每 owner 最多 1,024 项 |
| 代理活跃上游事务／waiter | 每 owner 最多 64／128，合并也消耗 waiter 配额 |
| 代理上游连接／socket | 每 owner 最多 8 个，空闲且无在途工作 30 秒可回收 |
| 答案 cache | 每 owner 同时受 512 项和 2 MiB 限制 |
| DNS owned 工作字节 | 每 owner 最多 8 MiB，覆盖观察、在途消息和等待状态；cache 另计 |
| TLS／HTTP 资源 | 连接数、TLS 配置／缓冲及证书输入同时有界并计量；HTTP 头最多 32 KiB／128 项，DNS body 不超过单消息上限 |
| 单查询总期限 | 10 秒，排队、授权、connect、TLS 和重试共享该期限 |
| 单候选尝试 | 最多 3 秒且不超过剩余总期限；同一候选不无限重试 |
| 普通 UDP 重发 | 允许一次受期限约束的重发；TC 后 TCP 继续不重置总期限 |
| 透明对应／不完整消息 | 10 秒到期清理；不因观察状态到期主动关闭原业务运输 |

所有 deadline 使用单调时钟。先完成／取消者结清身份，稍后 timeout 无第二次效果。原路径仅观察资源不足时沿其既有安全转发／故障合同并记录覆盖不足；代理已经取得合法请求但容量不足时，能答复则返回 SERVFAIL，不能答复则记录运输／资源失败。不得伪造政策拒绝或无匹配。

cache 同时限制条数和实际字节，优先丢弃过期项，再按有界最近使用驱逐；驱逐不影响独立两小时关联或已有流事实。TLS 和 codec 的实际内存也必须通过固定配置、连接数与计量证明有界，不以“第三方库负责”免除资源验收。

### 14. 实施顺序与完成资格

第一条端到端闭环同时覆盖 Root／VPN 原路径、UDP／TCP、IPv4／IPv6、可靠调用者允许／拒绝、Unknown 放行、普通 RR 兼容、可得 CNAME 检查、观察和停止。可内部逐步实现 UDP，但 UDP 单独通过不能作为这一闭环完成。

随后接入完整消息代理、普通 DNS 客户端、数据 cache、内网例外、DoT／DoH 和相关失败／取消／回送。后续连接的直接域名扩展与关联证据继续属于完整目标；可以按依赖独立切片，不要求先决定后置的跨应用关联范围。

每条实施任务从本规格及其明确验收范围开始，测试只证明其真实来源和覆盖。尚未运行的部分不写已验收；完整首版结项不能用一条切片的成功替代，也不能用附带的 TCP 上游能力冒充 TCP 入口覆盖。

## Testing Decisions

1. **两个验证层次共同采用。** 主要语义测试通过共享 DNS Core 的消息／上下文／时间／事件 Interface 验证实际处理结果；运输、政策和时钟依赖通过既有或必要的私有可控接点提供。另以现有 Product graph 和 Root／VPN 真实 Adapter 验证接入、回送、配置与清理。只为两个真实 Adapter 的差异建立接点，不公开每个 helper。
2. **测试外部行为。** 观察实际原路径 verdict、代理答复、原 resolver 收到的请求、当前 rule winner、解析数据复用、关联资格及资源结清；不锁定容器类型、循环展开、函数次数或第三方库内部布局。
3. **复用现有先例。** 沿现有 Host C 语义／ABI、VPP graph、Root NFQUEUE、VPN TUN／HEV、平台授权和 Rust／SQLite 观察验收方式扩展。Host 结果不代替 Device／wire；原始 source／artifact／generation／配置身份与失败均保留。

| 场景 | 必须证明的行为 |
| --- | --- |
| 入口组合 | Root／VPN × IPv4／IPv6 × UDP／TCP；公网、自建 LAN 与产品代理地址；未替换时目的地及允许原 wire 保持 |
| 调用者 | 可靠直接 App 按其规则；系统 UID 已知但原 App 未知不套猜测政策；Unknown 不等待；独立通用规则仍执行 |
| 完整规则 | 所选名单 any-match、显式 AND／OR／NOT、Rank 顺序交换、observe mode；QName 在甲／alias 在乙不拼成 AND |
| 事实来源 | QName 不填 SNI，RDATA 不替换包目的 IP；业务端口条件不删去；显式 SNI whole-rule applicability 不被 OR 绕过 |
| CNAME | 新查询首次 alias 命中、长链、环、重复 owner、无关 additional；判断前名单事实已就绪；alias ALLOW／DROP 均按 Rank |
| 原路径 TCP | 长度头和 QName 拆段、合帧、连续 query、乱序、重传、midstream、超限；首次可证明拒绝 DROP，不承诺撤回已转发字节 |
| 代理拒绝 | query 拒绝不查数据 cache、不出上游，返回 REFUSED；CNAME 拒绝无原答案／关联刷新；同 TCP 会话其他允许 query 可完成 |
| 解析错误 | 本地政策 REFUSED、上游有效 RCODE、全部运输失败的 SERVFAIL、FORMERR／NOTIMP 来源分明，不误算政策命中 |
| RR／EDNS | A／AAAA、TXT／MX／SRV／HTTPS、未知 RR、DO／CD、不同 Question 大小写及未知 EDNS；不丢不理解的数据，不误缓存 |
| UDP／TCP兼容 | UDP TC 后在同 resolver 继续 TCP；客户端 UDP 容量限制、合法 TC 回送和后续完整 TCP 答案，原 ID／Question 对应正确 |
| cache／当前政策 | 同数据在不同 App 下分别决定；等待时改规则；cache 命中后新增 alias 拒绝；被拒 App 不污染其他允许请求 |
| TTL／负缓存／Age | TTL 0／1、不同 RR TTL、SOA 两种期限、NXDOMAIN／NODATA、DoH Age 超过 TTL；无固定17秒／最低60秒或过期救援 |
| 解析视图 | 同名公网／内网不同答案、同网络更换 resolver、例外重叠／冲突、换网旧事件晚到；数据不串视图 |
| 主备 | 主超时备成功、冷却后恢复原顺序、有效 NXDOMAIN 不打备、全失败不降级、总期限不被逐次重置、取消不标故障 |
| bootstrap／TLS | 域名、IP、配置连接IP、原网络引导、防递归、protect／bind、证书／身份失败和 late broker；未认证不发应用 DNS |
| DoH | HTTP 部分读写、合法 framing、错误 Content-Type／状态、过大头/body、Age、无支持 ALPN／HTTP2-only、deadline 与取消 |
| 关联资格 | 只取真实相关地址；拒绝答案保留观察而无活跃关联；两小时逐 pair 更新、旧地址独立保留、业务使用不续期、0／多候选不可用 |
| 连接域名 | SNI pending／有名／终结无名，直接名优先；HTTP 逐请求及 IP 型目标、SOCKS 名字／IP 目标、DTLS 真实分片事实；后置范围不偷选 |
| 多 owner／容量 | N=1 与代表性 N>1，owner 身份、cache 隔离、每类上限及总量、热规则／视图更新、有限日志与导出背压 |
| 取消／停止／重启 | response、timeout、cancel 同轮，最后 waiter 取消，握手中停止、旧 ID／token／incarnation、late callback；每个义务一次结清，资源回到可证明基线 |
| 普通使用入口 | 使用当前正常启动／停止和配置路径验证，包含 Root 授权与 VPN protect；不以诊断专用旁路冒充普通功能 |

4. **定向回归。** 保持已有 TLS／QUIC SNI、统一规则／快照、CT／Flow、归属 Unknown、正常观察、Root 故障处置和 VPN return 证据边界。DNS 协议标签仍不是 DNS 功能通过的证明。
5. **故障与安全输入。** 对 wire 长度／压缩指针／CNAME／HTTP 输入作有界畸形、截断及 fuzz 验证；强制低容量验证实际资源行为。不得将 parser 错误或观察缺口归为成功无匹配。
6. **设备和构建约束。** 使用 Product 持久缓存；不变更的第二次构建应无编译，再开展重复构建。Android 操作使用仓库包装器，Root 权限失败先核实授权。该规格发布本身不包含构建、安装或设备实验。
7. **证据资格。** 将普通 App 自查、系统代查、产品代理、cache、真实 wire 与注入夹具分别标识；每项报告列实际模式、覆盖、未运行项和限制。没有跨应用范围决定时，关联消费的该部分不宣称完整验收。

## Out of Scope

- KSU／libnetd、Xposed 等系统 hook 的实现、安装器与跨进程政策投影。
- 恢复、参考或移植已删除 C++ 产品；直接导入 POC 或 Portmaster Go 实现；新增独立 DNS daemon／运行时。
- 通过猜测恢复系统 IPC 原 App，或承诺系统／App cache 中每次查询都能在答复前拦截。
- 决定关联的跨应用／profile 使用范围；在决定前启用隐含全局共享或同 App 限制的执法。
- SIP 目标域名扩展、加密应用数据解密、完整识别全部外部 DoH／DoT、自动启用外部加密 DNS 阻断。
- Fake-IP、政策性替代地址、主动 TCP RST、选择性 TCP 字节／HTTP 请求删除、原路径持包等待识别。
- 自建 mDNS resolver、DoQ、H2／H3-only DoH endpoint 的未验证兼容、自动 DNSSEC 验证承诺、递归权威 resolver。
- 正式 UI／交互改版、公开发布、签名发布资格及新性能／功耗实验；不重启已暂停或收口的性能工作。
- 将当前暂停的 UID resolver 职责重构变为 DNS 的预设前置；为本规格自动创建实施子票。

## Further Notes

本规格将 PM 优先落实到可比流程，并给出必要适配；不追求完全等价。独立研究固定到 PM 的 cc164c7df617ecdb41a766edf88f8bf3fd741a85，核对33个相关源码文件。PM 的本地 UDP-only 接管、CNAME 事实准备／名单加载缺口、固定 TTL、stale 和最近域名选择，均不是本产品应自动继承的资格或最佳实践。

代理 REFUSED 是本次依据研究形成的规格选择，取代旧代理静默 DROP；原路径 DROP、上游失败 SERVFAIL、真实 DNS 结果、一般包规则保持分别定义。此前临时技术选择已经按研究重审：保留两小时作为临时参数、逐 pair 更新、旧地址和连接内事实的独立寿命；不会仅因曾经回答过 yes 就冻结以后改进。

关联跨应用范围是明确的后置产品决定。产生证据、记录来源、查询／答复过滤、直接协议域名及代理可以独立实施；完整关联回退的最终范围资格由后续明确决定补齐，不能用这份规格替用户决定或冒认交付。
