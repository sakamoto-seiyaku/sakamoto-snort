## 五种窗口与布局职责

| 模式 | 参考尺寸 | 布局与平台语义 |
| --- | --- | --- |
| Android 平板竖屏 | 820×1180 | 窄导航栏与触控内容；图和贡献、记录和所选事实共享范围。保留个人/工作资料及共享 UID 边界。 |
| Android 平板横屏 | 1180×820 | 利用横向空间并排核对；主次围绕同一对象，保持 Android 身份和触控操作。 |
| Linux PC | 1440×900 | 完整侧栏、图/贡献及列表/所选事实；可见选择、鼠标和键盘操作。控制范围依据 Linux 身份。 |
| Linux 触控/竖屏 | 820×1180 | 窄导航栏与触控密度；保留 Linux 的用户/控制身份，不因竖屏变成 Android。 |
| Linux 小窗口 | 640×760 | 顶部工作导航、单栏逐级；选事实后明确进入、返回列表恢复原对象和范围。 |

模式切换属于参考板外层；窗口原尺寸与显示缩放分别表达。缩放用于查看参考，不改变产品布局的目标尺寸。

## 四种视图怎样利用空间

- **概览：**变化图与同段贡献应用相邻，选时段直接改变贡献；应用一次点击进入自己的活动。查询、连接和字节保持各自口径。
- **应用活动：**固定身份、时段和类型，列表与选中事实并排；当前设置与旧事实分别说明。窄窗口进入事实再返回，保留选择与范围。
- **名单内容：**匹配名称与真实用途互相可见。频率、检查、暂停/停止属于来源维护，完整分配/顺序属于使用关系，不重新混进主正文。
- **更新审阅：**同一候选的差异、本地补充/排除和消费者用途并排核对；暂缓与采用有明确对象，资料保存与实际使用不混为一个结果。

Linux 示意中的识别程序可以帮助认出活动，控制范围仍以真实身份表达。同一用户身份涉及的程序不能被画成已经能够独立控制的应用；Android 的资料身份也不能直接搬到 Linux。

## 实际核验与限度

主评审对最终画板做了五窗口 × 四视图的20次渲染捕获：原框尺寸正确，没有页面脚本错误或框内横向溢出。实际查看了平板竖屏概览/审阅、平板横屏应用、Linux桌面概览/审阅、Linux触控应用、小窗列表/独立事实等代表画面。结果与截图见[跨平台截图](assets/2026-09-30-jobs-second-debate/screenshots-large/)。

操作路径核验包括选09:21–09:26的800 KB收到/1.3 MB发出与2.1 MB总贡献、一次点击进入天气并保留范围、查询类型切换、键盘选择同步事实、小窗事实/列表返回、来源核对返回同候选、暂缓再审阅/采用、Linux共享身份与Android当前应用的决定范围。全部在本地示意状态中进行；没有真实订阅、配置写入或网络控制。

完整规则/有效顺序等部分深入入口仍只说明设计意图，没有实现完整规则页；没有把点击提示当成完整消费者核对流程。小窗口和Linux触控布局保持Linux语义，但本轮没有实际触屏硬件、全键盘/读屏或完整状态矩阵验收。原产品原型的核心文件未变。

这份补充是布局与交互参考，不能证明全部功能、真实设备执行、Linux 程序归属或完整无障碍操作已经具备。
