## 三个真正在操作的候选
A．**联网表格**：横向网络、纵向应用，点格子允许／禁止；拖选整片，深入某格分出域名子格。
它胜在音乐App案例只需两格，A/B/C也能多选；难点不是字段多，而是第二支不限App的OR必须跨整列，NOT后的空白究竟继承还是取反很难稳定解释。
若扩大成无限维透视表，换轴会让同一个决定改变位置，先后又要另开列表；六项工作中第3、4项会把主要语言撕开，故落选。
B．**访问分流图**：用户把“移动网络”等判断放到线路上，YES／NO出口接允许、禁止或下一个判断；拖线改路径。
它能精确表示NOT和顺序，主例拉两条出口即可；但A/B/C共用一路、A/d改道后，修改共同节点会不会改变支路，需要同时理解路径与引用。
手机上跨应用OR还须合流；同一条件重用、短路、共享维护变成布线工作。它是最强反方案，因为判断路径比任意括号更易逐步验算，但大批维护的选择成本高。
C．**选中一类访问，再标处理**：像筛选文件、选照片后执行操作，先缩小／合并选取范围，再点允许或禁止；已经做过的处理能重新打开选区、重排先后。
我选C。熟悉经验来自“看见自己选了什么再行动”，不是“选区”这个名称；不能把真实流量当作全体未来访问，也不能假装人人会图像编辑。

## 两段一手阅读怎样改变选择

在线完整读档案的1983 Aspen演讲节选（从代际开场到结尾问答）及2007 iPhone发布前员工讲话完整节选；未声称看过完整视频或未经编辑原稿。
1983节选中Jobs从简单指令讲到人的使用，明确说人希望使用电脑；我因此删掉候选B原本要求先放“起点／终点”的步骤：它没有替人完成任何联网决定。[档案节选](https://book.stevejobsarchive.com/)
2007员工讲话以已有却难发现的电话会议功能为例；我因此把“再选一批”“只保留”“排除这块”放在当前选区旁，否决靠长按手势才出现组合能力。[档案节选](https://book.stevejobsarchive.com/)
以上是Jobs发言的转述及我的设计推论；页面标题／日期说明来自编者，史料不证明本方案必胜。

## 用户眼前的核心及一致动作

主对象是**一块明确选中的访问范围和给它的处理**。范围可以有过去记录，也可以只有条件；两者不能混为一谈。
主要操作始终是选中→缩小／再选／排除→允许或禁止→放到处理顺序中；回来修改仍选择同一块，不先找规则类型。
规则Tab首屏保留具体处理内容，以从上到下“遇到多项符合时，先用上面一项”呈现；内容旁是选区小图，不用伪造流量面积代表匹配规模。
进入App是已有选区“仅这个App”；主动新建则是“所有访问”。用户可以先选择网络、名单或协议，App没有固定根层地位。
选区图是有明确边界的盒子而非文氏图：盒内“同时满足”是AND；并列盒间“任一块”是OR；带排除标题的子盒是NOT。点盒边框才选中整块。
盒子可折叠为内容摘要，手机纵向展开；点“进入这块”只编辑该块并保持上方完整路径，返回仍见原位置。不要求精确拖拽小点。
这会挑战已接受的“先选动作”创建顺序；换成先确定范围，收益是动作前就知道影响谁。现有导航、三层整套组织限制与App内修改边界不必改变。

## 首次工作的十步：音乐App移动网络禁止、Wi-Fi允许

1．用户只知道音乐App和两种网络，不知道域名；从首页应用列表点音乐图标，进入真实流与当前处理摘要。
2．点“选择要处理的访问”，出现预选的“音乐App”，页底明确“包括以后符合的访问”，不是多选日志。
3．点“只保留”，出现常用可选内容；点“网络→移动网络”，选区读回“音乐App，同时是移动网络”。
4．点底部“禁止”；选区获得禁止标记，尚未使用，已有处理顺序在下方显示。
5．点“保存并使用”；新装空配置时只有该项，不要求优先级数字；若已有相反重叠项，显示两项供选择谁先。
6．在完成后的同一内容上点“再做一项”，范围回到音乐App，先前决定保留在下方。
7．点“只保留→网络→Wi-Fi”，点“允许”；这是显式允许，不把缺少禁止冒充已设置。
8．点“保存并使用”；两块网络范围互斥，界面直接显示“移动网络 禁止；Wi-Fi 允许”。
9．点其中“看看当前怎样处理”，使用所选网络做明确标注的当前预计检查，不显示虚构连接或成功播放。
10．返回音乐App；原时间范围和真实流仍在。摘要显示已保存且正在使用，实际新记录发生后才出现对应允许／禁止结果。

```text
音乐App                         已保存 · 正在使用
选择要处理的访问
┌ 选中范围 ─────────────────────────┐
│ 同时满足： [音乐App] [移动网络]      │
│ [只保留…] [再选一批…] [排除…]       │
└─────────────────────────────────┘
给选中范围： [允许] [禁止 ✓]
处理顺序（先符合的决定结果）
  ≡ 禁止  音乐App · 移动网络
  ≡ 允许  音乐App · Wi-Fi
[再做一项]                [查看实际记录]
```

## 共用与个别：不靠“局部天然赢”

在规则Tab选App A/B/C，再只保留名单L，点禁止并保存使用；页面读回“A、B、C符合L时禁止”，无需先建名字或应用组。
从A真实d.example记录进入同一选取操作，范围明确“A且d.example”；点允许，系统展示其与共用禁止重叠，让用户点“放在这项之前”。
这生成独立的A处理，并保存“因名单L处理而调整”的双向关联；它不是父规则私有入口，也不拥有自动胜出权。反向共同允许、A/d禁止完全同构。
A页并列显示共同处理和“A/d先处理”的连线说明；点“撤回这次调整”会先显示按当前名单及顺序的预计结果，再删除A项及该关联。
共同内容只能多走一步进入规则Tab；那里显示A/B/C及相关个别调整。共同内容更新后关联仍在；若d已不在L，标记“原重叠已消失，A决定仍在使用”。
这是明确代价：独立调整可能继续允许未来重新进入名单的d；不能偷偷自动删掉或只在L内有效，用户可把L也加进A选区来选择后者。

## 无活动的复杂表达与精确改正

规则Tab点新建，先“只保留AppA”，再“只保留域名在L”；点根部“再选一批”，从所有访问新建第二盒，依次只保留Wi-Fi、UDP、目的端口443。
根部始终写“任一块”；第二盒没有App条件，明确显示“所有App”。此时按允许／禁止才给整个联合范围处理，保存待用不启用。
要加NOT，点第二盒的边框，再点“排除”，在其中建立“域名在M且AppB”子盒；排除作用于整个子盒，不只最后一个词。
得到 (AppA AND L) OR (Wi-Fi AND UDP AND dst443 AND NOT(M AND AppB))；点排除盒内“任一项／同时满足”可精确改其内部关系。
需要 NOT(Wi-Fi AND UDP AND dst443) 时，选第二盒→“反选这块”，标题变成“不满足以下整块”；根部另一支不动，完整括号立即读回。
不是只有三种固定嵌套：任一盒均可建立AND／OR子盒及反选；深层缩进超屏时进入该盒，顶端固定显示它的父关系和NOT状态。

```text
准备待用                        尚未使用
选中以下任一块                         [折叠]
┌ 同时满足 ──────────────────────────┐
│ AppA；域名在 L                     │
└──────────────────────────────────┘
                  或者
┌ 同时满足                   所有App ┐
│ Wi-Fi；UDP；目的端口443             │
│ 排除 ┌同时满足：域名在M；AppB────┐  │
│      └────────────────────────┘  │
│ [只保留] [再选一批] [排除]          │
└──────────────────────────────────┘
选中范围的处理： [允许 ✓] [禁止]
[查看完整括号]          [保存待用]
```

## 顺序、整套与一个月后

P允许与Q禁止同时匹配时，打开该访问的“当前预计”，只列符合项且保持真实顺序；P在前即允许，移Q到P前即禁止。未符合项可展开，不参与这次结论。
移动是明确的“放在P之前／之后”，不以细节数量决定。全局编辑显示影响应用；App内移动只创建该App的顺序差异，保存前列“A改为Q→P；B/C仍P→Q”。
共享P内容不被复制或重排；A的有效顺序视图显示“仅A改变顺序”，可恢复共同顺序。该建议挑战规格单一逻辑顺序的直接呈现，需明确批准后另定实现合同。
整套：在连续制作页选中多项→“收成一套”，此时才可命名；套内仍是相同选区和先后操作，不增加另一种规则语言。
套的公共范围选择为持续的外层选区，页头写“套内每项都先限于这里”；因此明确选择了持续约束而非批量编辑捷径，仍是待确认建议。
用于另一批App时，先选择套外层范围，再显示哪些内部仍指名AppA；不能默默替换任意App条件。可点具体App条件换人，也可保留不限App分支。
共同使用从规则Tab建立，显示各处范围；单项可单独使用，个别内容调整仍生成有关联的新项并明确顺序。套的排列是组织，实际胜出仍按有效顺序展示，不能把套当不可分割优先块。
一个月后先看“当前在用”的内容；点名单L能看到最新成员及受影响的个别调整。原d记录保留当时真实决定，旁边另有“按当前内容预计”，两者不可覆盖彼此。
“已保存待用／正在使用／本时段无实际记录”分开显示；无记录的选区不画零大小、不变灰成失效，仍可打开修改。

## 我会怎样放弃它

选取经验只迁移到最初三步；多层NOT、动态名单和覆盖顺序仍须学，不能用“像选照片”掩盖这一点。实际记录只辅助看范围，绝不是范围的定义。
最强反方案仍是分流图：若新手在两次教学后仍把“排除整块”读成“排除任一词”，但能正确沿YES／NO路径完成同题，我会改选图，即使编辑更慢。
另外若用户普遍认为新标记必然覆盖旧标记，C的操作隐喻就误导先后；不能补一句说明了事，应放弃涂色暗示，将本方案判负于显式路径操作。

## 阶段二：真实交叉质询后的改判

四席都采用范围块＋处理先后，属于**一个范围编辑家族**；四人相同选择不构成四份易用性证据。
我撤回“像选照片”作为核心依据：无活动时不存在可被直接选取的访问实物，用户操作的是一份范围说明。
AND改叫“只保留”也不是新范式；真正值得测试的是可选择整个边界、修改边界后看见范围变化，而非是否给规则换了名字。
阶段一的“排除／反选”双词存在歧义，最终版本统一为明确的“删除这块／不满足这一整块”；二者分别删分支、否定分支。

### 空白首屏的实际材料，取代照片隐喻

```text
哪些访问要这样处理？
┌ 尚未限定范围 ─────────────────────┐
│ [选择应用] [Wi-Fi] [移动网络]       │
│ [名单L] [更多名单] [协议与端口]     │
└─────────────────────────────────┘
处理： [允许] [禁止]        [保存待用]
```
点Wi-Fi，中央成为“网络为Wi-Fi”，下面明确“任意应用；任意目标”；再点名单L，成为“同时满足Wi-Fi、域名在L”，应用仍不限。
材料是设备上已知应用、网络类型、现有名单及可输入的协议端口；中央是待保存说明。范围不是“目前显示0条所以什么也没选中”。
此页不混排历史记录；从记录发起则先出现“采用哪些事实”，App／域名／网络分别点选，进入同一范围说明后才选处理。
这项结构隔离让“过去发生的一次”与“要定义的一类”经过可见转换；不靠一句“以后符合”承担全部解释，也不拿合成记录填空。

### 已实际问答，不以代答冒充讨论

A问B：对含跨App OR的X，NOT第二整块与Q先于P到底改几处？图若能一次反转整段，范围块的优势是什么？
B实际答：段内问题沿是／否相接，所有分歧收拢成符合／不符合两出口；选段后反转出口即可整段NOT，不必逐线改。Q→先问这个→P三点即可重排，自动重接未符合出口。
我据此撤回“布线工作足以淘汰图”的判断。强图的对象是可展开的问题段；范围编辑的可观察优势只剩多支并排扫读，尚未测得。
A向B唯一追问共同误伤与复用；B实际答：A/d新判断插在L前，是去允许、否接L，仅A保存，双方保留“因L误伤”关联。
B续答：用于D/E时只替换明确可换的App问题槽，不限App支路明确保留；硬编码App若需改则独立副本，不能偷偷改共同正文。
我接受：图已演通误伤与复用；可替换槽增加维护负担，但范围编辑同样有这项负担，不能拿它单方面判图负。
A问C：无活动到底选什么？与同样边界的规则编辑器有何额外学习迁移？
C实际答：只有范围描述，没有访问实物，本质是结构化范围编辑器；筛选迁移仅浅层成立，NOT仍须学。句子版本若仍选整段／包边界，也只算同家族排版。
我接受此答，不再把“范围”“句子”“选区”作为三种竞争者；首选保留范围编辑，但其理由收窄为已演通的完整性，尚无易学冠军证据。
C问A：最多三步把第二块改为NOT整块，如何避免“Wi-Fi那种情况不要”的歧义？
我实际答：①点第二块常驻“改范围”；②选“不满足这一整块”；③看同屏旧新式与“将包括全部非Wi-Fi，以及Wi-Fi上非UDP443”后应用。另列“删除这一分支：仅剩A且L”，不猜用户话意。
这补充了阶段一缺失的后果表达：只把边框染色不足以教NOT。实际界面不能把“不是整块”收成一个看不懂的符号。
D问A：给空白首屏及两次点击，并承认是不是填条件。我的实际答即上面第三幅图；是范围表达编辑，图与它都需学习，不再以熟悉照片否决图。

### 两强方案按同任务比较，保留改选可能

NOT：范围编辑选第二框→不满足整块→核对；图选第二判断段→反转出口→核对。两边都要表达“非Wi-Fi也进入”，无固有胜负。
先后：范围编辑移Q到P前；图把Q段先问并自动重接。两者都须明示仅A或共同修改，图不能靠路上更近、范围不能靠更具体偷赢。
误伤：范围编辑从A/d事实建新范围并显式提前，旧共同L及关联同屏；图需要把A/d判断放在共同L前、保留关联。这里真正比较的是修改后找回两者，不是节点数。
复用：二者都要显式选择要替换的App条件并保留不限App分支；图的入口不能默认罩一层D/E，否则已改掉第二分支的原意。
候选局部次序、关联调整、持续共同外框均未获批准；范围与图可采用同样候选语义，因此这些能力也不能当选区独有优点。
目前我保留**范围编辑**与**判断路线**两个强候选；不再单凭手机线长淘汰后者。结果格盘最多作为两维批量任务的半种补充，不另造第三全能编辑器。
下一次应给同一批新手相同OR/NOT、误伤、换顺序和一月回读任务；比较错改范围／错改他人／能否解释当前结果，再看点击数。此处是验证建议，未实施测试。
