## 五项具体问题

### 1. 手机应用页未按进入任务组织历史解释与当前管理（结构，优先讨论）

**动作 / 证据：** 393 首页选 09:21–09:26→贡献天气→`app-detail.html?id=s4`。首屏先给“09:41 快照”、两条连接的时段量/最新状态/累计量和“我的联网设置”；DNS 后才是本时段 1.3 MB、曲线及查询数量。见[手机首屏](assets/2026-09-30-jobs-debate/logic/01-android393-selected-time.png)。下方时段摘要与地图入口确实存在，并非能力缺失。

**任务 / 代价：** 此时人的问题是“刚才的发送变化由天气的什么活动造成”，不是首先修改当前总体安排。连接行已有本时段线索，但最新快照与当前管理插在历史解释主线，用户要滚动、拼回选择原因。820/1440 的时段摘要与连接并排减轻这个成本；640 Linux 小窗口也先给时段摘要，问题不能泛化到所有窄屏。

**结构选项：** A 保留一个应用页，来自时段的入口先排时段摘要和该时段记录，当前快照作为记录内的第二层，当前安排保持一条明确入口；来自首页当前应用则先排最新活动。B 将应用固定分为“活动”和“联网安排”，活动内统一图、类型切换、地图与记录，安排页保留完整控制入口。

**代价 / 改判：** A 同页随入口改变次序，需要稳定标题与来源；B 更可预测，但增加切换，也可能切断事实→决定。因此不能仅因模块多就拆页，更不能删掉流量理解或当前快照。

### 2. 应用的完整控制与设备共享资产被放进同一组标签，切换时作用域悄然扩大（结构，优先讨论）

**动作 / 证据：** 音乐→`app-controls.html`→完整规则，标题是“音乐的规则”，有“返回音乐”。点击“规则组”进入 `groups.html`，URL 丢失 `app/from`，页面展示日常联网组；深入后实际分配为 Firefox、Signal。点击“域名列表”同样进入全设备资料。393 和 Linux640 均复现，见[共享组页面](assets/2026-09-30-jobs-debate/logic/02-linux640-shared-scope.png)。

**任务 / 代价：** 标签看起来是同一任务的三种内容，却从“我安排音乐怎样联网”转到“我管理设备可复用资产”；没有说明扩大范围，也没有音乐返回入口。共享能力本身应保留，问题是任务边界和返回承诺。

**结构选项：** A 应用控制只列该应用实际使用的规则、组、资料，在相关项旁提供“打开共享资料”；全局规则入口单独管理资产。B 保留三标签，但统一显式作用域切换“音乐 / 全设备”，切换标签保留来源与返回。

**代价 / 改判：** A 需要“使用关系”和“资产库”两种列表，但理解清楚；B 更紧凑，却要求用户额外判断作用域。若刻意把此处定义为全设备工作台，应在进入时完成转场，不能借音乐标题暗示局部管理。源码佐证：`rules.js:59–72` 仅为规则页注入应用上下文。

### 3. 就地安排很近，解除同一安排却进入三个技术对象（结构）

**动作 / 证据：** 393 音乐单次连接→开始阻止；解除时实走“查看我的设置”→该规则→“音乐 / 执行规则”→通用“规则分配”→解除这项分配→确认→保存结果→返回。分配页先要求规则类型、资产选择和全部应用勾选，解除入口需继续滚动。见[解除前的通用编辑页](assets/2026-09-30-jobs-debate/logic/03-android393-revoke-path.png)。解除成功后原资产仍保留且明确“不参与判断”，不是缺少解除能力。

**任务 / 代价：** 用户表达的是“撤掉我刚给音乐的这个安排”，却必须理解规则、分配、执行方式的关系。“再调整”提供阻止/允许，允许也不等于恢复撤销前的其他规则判断。

**结构选项：** 在当前应用安排中将“改为允许 / 修改范围 / 解除此应用的安排”组织为同一对象的操作；共享安排明确显示涉及应用，保留“打开共享规则”继续编辑。资产删除继续留在全局管理，不把解除等同删除。

**代价 / 改判：** 新增局部解除表达，需要显示解除后其他设置继续适用；复杂组分配仍可能需要解释。当前相关页面未找到就地解除入口，只能断言已走路径的成本，不能声称全产品不存在任何其他入口。

### 4. 再次调整没有恢复子域名范围，正常保存会缩小决定（已复现，优先修正）

**动作 / 证据：** Linux1440 音乐连接列表选 artwork→调整→展开范围→勾“包含这个名称下的子域名”→保存。重开同一调整，勾选为 false，句子由“名称及子域名”变成“名称”；再次保存后列表详情明确“artwork.example.net / 仅此名称”。见[重开范围](assets/2026-09-30-jobs-debate/logic/04-linux1440-readjust-scope.png)。主评审另用新会话独立核验配置 JSON：初存 entries[0].mode 为 descendants，再开未勾选，再存变 exact。

**任务 / 代价：** 用户检查或修改动作时，界面静默改变既有范围；“再调整这项设置”失去准确性。这不是专业选项隐藏问题，而是已选意图没有被完整重现。

**收敛改法 / 代价：** 重开从实际安排加载动作、通道、名称范围与应用范围；保存前展示本次范围变化。无需增加页面。`experience.js:569–594` 恢复 action/channel，未恢复 checkbox；`network-data.js:331–341` 的 lastDecision 未保存 descendants，`:323–327` 再保存会覆盖资料为 exact。应验证动作修改不附带范围缩小。

### 5. “核对这项决定”打开整个应用的后续活动，未把决定对象带进核对任务（结构）

**动作 / 证据：** 393 天气 metrics 的阻止查询→保存允许→“新设置已生效 · 查看后续活动”。新页标题“天气的活动”，类型“全部”，没有目标名称或允许意图；本次为空，明确表示未有新记录。URL 保留 app/after，却清除时段、设 type=all 且无目标筛选。见[后续活动页](assets/2026-09-30-jobs-debate/logic/05-android393-verification.png)。清除历史时段以查看新事实合理，不应被批成返回故障。

**任务 / 代价：** 用户要核对 metrics 查询的局部允许；当前入口却需要重新找到目标与类型，未来其他活动可能加入同一列表。本次没有新记录，未观察到误判执行结果，风险为任务表达与筛选范围推论。

**结构选项：** 默认给“天气 · metrics · 查询 · 设置生效后”的核对视图，顶部保留安排摘要，再提供“查看天气全部后续活动”；对包含子域名/两个通道的决定按原范围展开。

**代价 / 改判：** 需要同时保留决定范围与浏览范围，不能只用简单字符串搜索代替关联判断；完整应用观察仍可达。源码 `experience.js:537–545` 只带 app/type=all/after；`:278–282` 分别执行目标搜索与生效后时间筛选，当前跳转未携带搜索。

## 保留点与提案边界

- 首页点击熟悉应用一次即进入；应用不是图表筛选项。音乐连接、DNS 和地图路径都有独立可达入口。
- 单次连接提供应用、目标、协议、时间经过；地址协议可以展开。就地决定明确应用、名称、查询/连接及子域名范围，不宜一概批为“用户拼规则引擎”。
- 原型区分查询阻止与连接事实；保留没有关联记录的情形，没有强行伪造联系。
- 保存反馈保留原始历史结果，提示当前新设置与后续事实；本次后续为空也没有冒充执行成功。
- 1440 的列表单击更新右侧 artwork 对象，保留列表与选中反馈；不能泛化为“双击隐藏详情”。独立完整事实入口补充经过与依据。
- 图、地图、当前控制、完整条件、规则组、共享资料均保留。相同目标的“数量→列表”和“查看全部”各有位置价值；较具体的疑点是桌面“我的联网设置”和“适用规则”承诺不同却都到 app-controls。

有限的整体对照方案是：先做“应用活动 / 应用安排 / 设备共享管理”三个任务边界，再决定它们在宽屏并排、窄屏分层，或保留应用页按来源排序。它是待比较的产品提案，不宣称完整能力应被压成三页。订阅维护、导入、运行恢复、身份诊断等任务组合本次未实走，不对其完整性下结论。

## 阶段 C 最值得辩论的命题

1. 应用页应按来源任务重排，还是固定拆成活动与安排？393 历史探索的顺序有代价，820/1440 并排同时给事实和决定又有价值。
2. 应用完整控制与共享资产应分成两个任务工作台，还是用明确作用域保留一个？当前标签切换真实丢失 app/from 与返回，不能只调标题收口。
3. 一项就地决定应拥有就地解除和按原范围核对的闭环，还是继续复用全局规则/分配/活动编辑器？现路径能力存在，理解与返回成本也存在。

## 阶段 C 辩论收敛

A→B 两轮：A 指出同名页动态换序伤害位置记忆；B 将固定“活动 / 联网安排”列为优先比较候选，身份/时间/任务入口固定，局部决定留在活动内，完整管理承担一次明确切换。动态来意重排降为备选；三类来意的定位/切换成本仍待比较。
核对仅解释原范围内新事实，必须同屏保留范围/动作/版本时点、其他限制概要、范围外活动摘要；无记录为缺证，实际关联的 DNS/连接分别给结果与依据。A 撤回“窄视图必然丢上下文”的泛化反对；若主要来意是恢复且缺少关联事实，则改用恢复诊断。
B→设计席：质询“设备/应用/规则与资料”如何维持全设备活动的发现与返回，不能让设备同时含糊承诺恢复查询和回概览。设计席接受独立应用入口尚未证明收益，改以“设备/活动/规则与资料＋固定应用目录/搜索”为优先比较基线，应用主入口作为挑战者。
挑战者须在393持续显示概览/活动/统计/地图，设备恢复原子视图、概览明确直达；设备/应用/生效后核对分别保存查询，返回保留筛选、时段、选择及位置，来源事实显式刷新。代价是常驻一行、额外总体动作及更多状态，不能据此宣称已验证。
收口保留分歧：固定边界若增加反复切换可改用固定壳内重排；独立应用入口须改善未活跃应用查找，且不伤害未知变化与持续活动。以准确率、定位及恢复成本比较，不按页数或 Jobs 背书裁胜负；本轮未改原型。
