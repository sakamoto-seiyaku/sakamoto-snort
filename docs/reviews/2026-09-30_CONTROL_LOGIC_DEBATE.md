# 控制决定的精确性：不预设一条独立控制线

2026-09-30 · B 组 · gpt-6.1-sol / high。
范围是第一版理解、改变、验证及已有完整编辑/快捷限制/排序/方式/默认动作/预演/提交/解除/输入/导入的整条交互，规则、组、DNS、名单、地图不是封闭名单。本轮只写本报告；没有改产品、旧报告、设备、tracker 或提交。

**主张：**不保留独立“控制线”或第三主导航作为前提。设备与活动承担理解；应用、一次事实和命名共享对象承担改变；本次结果与后续事实承担验证。精确语义由适合任务的完整输入、关系与影响承担，不要求用户先走规则→组→binding 的后台目录。

## 一手哲学与模型权威的边界

[1984 Macintosh 访谈](https://book.stevejobsarchive.com/#on-the-macintosh) 用熟悉操作释放表达，[2001商店导览](https://book.stevejobsarchive.com/#speech-apple-store-2001) 把试用、求助、专业用途分别组织。本席据此优先熟悉对象、直接操作和情境控制；这些材料不决定页数，也不能让漂亮短语覆盖实际动作。
已读当前[TMP](2026-09-30_UI_INTERACTION_DECISIONS_TMP.md)、[统一规格](../product/UNIFIED_RULE_ENGINE_SPEC.md)、[ADR0009](../adr/0009-unified-rules-and-vpp-owned-configuration.md)、T04/T06/T07/T08/T18/T19，以及当前 interface map、VPP API、rule-config/SNI typed headers。未使用被移除 C++。
模型约束是 API 含义，不是页面目录。前轮导航和独立完整规则页也可重审；设计席可最终取舍形态，不能用其身份覆盖下列硬事实。旧 HTML 能点、mock 能算或历史 PASS 均不证明目标契约完整。

特别是 descendant 集合内排除一个 exact 名称，删正向entry不等价。转成各consumer的 AND NOT SNI 会改变规则定义/版本与所有引用，也不能天然覆盖未来DNS消费者。真正名单排除及候选/来源契约需明确，不暗增第二editable model。当前typed配置接口可提交完整图、表达式、资料并返回保存/使用版本；本次未找到独立完整候选＋输入＋版本选择的生产预演API，内部matcher seam不是这项UI契约。

## 没有独立控制线的强替代：全部能力怎样留下

**入口选择：**设备/活动两项工作；设备固定全部应用（无记录照列、多选）及＋，固定范围、预演、导入与保存/使用状态。统一对象搜索帮助找到命名规则/组/名单，但不是唯一发现入口。运行修复直接到未能使用的内容，不能先要求有流量或恢复保护。

**理解→改变：**应用身份持续给准确当前短语与管理；事实持续给当时结果、名称/地址/输入来源。点事实改变以后处理，点应用管理就地看该身份的实际顺序与全部使用关系。完整树、排序、共享对象编辑是有名字的编辑任务，未规定必须modal或独立规则页。

**共享与无使用者：**＋可新建稍后使用的规则/组/资料，未分配不是错误；固定“共享内容”入口与对象引用可查目录、复制、编辑、嵌套、分配/解除和删除。专家连续切命名对象与最近使用，不强迫每次绕天气；代价是首访多一层及少一张常驻后台式工作台。

**排序/方式/默认：**本对象去重实际规则按真Rank只读可解释，每行同屏有条件短语、“命中后”实际方式和多来源数量；展开各来源行才解除/改显式binding。末尾明确默认ALLOW或实际catch-all DROP。共享排序用明确编辑＋所有使用对象/竞争位置，不默认拖动制造局部顺序。

**预演→提交→验证：**预演从决定、命名内容和设备均可主动进入，先选查询/连接与事实来源及配置版本；保留输入、不发真实请求、不成为第二生产匹配器。提交完整候选前审阅实际变化，冲突定位来源；保存结果独立于开始使用，再去同范围后续事实。无新记录仍缺证，不给成功恢复故事。

**取消/导入/失败：**条件与来源子编辑都回同一未提交输入，不暗中子发布。取消整个决定回原事实且当前配置不变；保存失败留输入，版本冲突先读最新状态。整套导入有具名审阅任务，不经局部名称面偷替换全局；compile失败留新保存/旧使用，修复可直接到具体项。没有恢复checkpoint的新要求。

## 真实互相反驳与取舍

| 真实往返 | 明确主张、反方案与改判 |
| --- | --- |
| A问多来源去重/解除；B答 | B优先实际一行＋同屏多来源短签，非来源重复列表；点关系才解除，接受普通人需要理解一条行为可由几处使用。A的两布局竞争，不因模块存在增第三入口。 |
| A问执行/观察冲突；B反驳 | A备选按对象/规则统一observe会连带组其他成员；B选逐实际来源。A明确撤回一键统一，接受完整绑定/其他成员/对象影响。 |

**最强对手：**保留一个按控制身份的独立安排空间，提供稳定有效顺序、使用关系及专业批量维护，事实入口仍直达局部决定；它不应先堆rule/group/binding目录。收益是无记录、重复共享维护和大型配置修复少一次寻找；代价是普通人多学一处工作空间，理解与改变较容易被拆成两线。我当前不选，但不会仅用两个导航更少就否定它。

**最终偏好与保留异议：**接受没有独立第三控制导航，但保留完整命名对象编辑、实际使用关系和从零发现；不把API实体变目录、不把少入口当品味。支持情境化精确决定，不支持未经输入/顺序证明的“一键允许”或“只观察不影响阻止”。设计席最终构图取舍可接受或不接受本席布局，不能覆盖API语义；名单排除、DNS与完整预演需诚实记为目标契约，不能既删体验又虚报现接口已承接。
