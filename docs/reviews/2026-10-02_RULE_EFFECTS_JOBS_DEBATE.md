# 规则与规则组执行效果的品味取舍

2026-10-02。用户接受单规则与规则组查看实际执行效果，明确整组效果与成员规则效果分开，并规定最多三层规则组；随后确认最外层算第1层，单条规则不占组层级。[确认基线](../product/NETWORK_CONTROL_PRODUCT_VISION.md#2026-10-02-规则执行效果与规则组嵌套)
本轮沿用两席 gpt-6-astra／low／priority（fast），先独立推演，再各向对方实际提出并回答两问。下面是主代理按乔布斯式品味作出的新建议，具体查看、展开与返回交互尚未由用户确认。

## 我的选择

**规则内容和实际效果在同一处；点内容，就理解或展开内容；点有单位的结果，就看对应的实际活动。**
单条规则与规则组都保持这个关系。组的成员已经是可读内容，效果就接在这些成员旁；无需再进入一个“效果模式”，也不另摆一份重复的成员排行榜。
我接受具体规则可能藏在子组里、需要主动展开的代价。默认摊开全部三层会让组织抢走内容主位，默认增加统计中转又会让查看一条实际结果绕路；当前选择让动作紧贴眼前对象。

## 示例数字与正在看的对象

以下为纸面示例，数字不是真机测量；“过去1小时”也是演练时段，不据此批准产品默认时段。
规则 R 阻止 Wi-Fi 下的对外 UDP 目的端口443，实际阻止16条连接：浏览器8、邮件4、视频4。规则组 G办公给浏览器、邮件使用，因此 R 在 G 范围内的效果为12条，视频的4条在 G 外。
G还有名单规则D，实际阻止6次域名查询；G含H网络限制，H含K连接控制，K含R，形成三层组。H也直接引用同一个R，以检验重复引用；两条引用不能让12变24。
16条连接均被实际阻止是阶段二明确补充的示例输入，不是依据R的名称推断。查询、连接活动与报文命中分别有单位，不能相互改名或混成一个总数。

## 打开单条规则

用户先读懂R的实际决定，旁边看见当前使用状态、这次选择的时段与效果范围。例如：

> Wi-Fi 下，阻止对外 UDP 目的端口443。
>
> 用于：浏览器、邮件、视频。
>
> 过去1小时 · 全部使用范围：已阻止16条连接，涉及3个应用。

点“16条连接”，直接进入这16条实际活动。每条能认出应用、真实目标、发生时间与实际处理，继续点开可读具体事实；无需先经过应用贡献页面。
返回恢复原列表位置，再返回同一条规则。途中主动改为“今天”，这条查看链就明确采用今天重新查询，不能继续把旧16当今天的结果；记录本身仍保留真实发生时间。

## 打开规则组

用户打开G办公，读到这套内容以及当前给哪些应用使用。整体效果紧挨着内容，成员仍按原组织呈现：

| 当前内容 | 在G办公内过去1小时的效果 |
| --- | --- |
| G办公整体 | 阻止12条连接；阻止6次域名查询 |
| 名单规则D | 阻止6次域名查询 |
| 子组H网络限制 | 阻止12条连接 |

点整体的12，直接看G范围内的连接记录；点6，直接看查询记录。点H的内容则展开H，继续认出R和K；点H旁的12仍是对应范围的实际记录。
这样，想看一件发生过的事就点结果，想知道整套由什么组成就展开内容。记录里的实际处理规则也能直接打开，不必补走尚未进入的组层级。
H内直接R与K涉及题设同一批12条连接，整体仍为12。只在记录能够确认同批时这样表达；一般情况下说明成员活动可能重叠，不能仅因数字相同就称同批。
成员效果不是互斥份额：同一规则的重复引用以及不同规则对同一活动的处理都可能重叠。因此整体效果不能简单求和，也不宜用暗示份额互斥的贡献饼图。来源细节按需查看，不在首层铺满引用路径。

## 从组内规则到应用和实际记录

从G深入R时，默认保留这次查看的问题：R在G内的效果。时段与范围直接可读，数字不会静默从12跳成16。

| 用户所在的位置或动作 | 应保留或明确改变的范围 |
| --- | --- |
| 在G里打开R | “R在G办公中的效果 · 过去1小时 · 阻止12条连接” |
| 收窄到浏览器 | “浏览器 · R在G办公中的效果 · 过去1小时”，对应8条活动 |
| 打开一条实际记录 | 记录自己的时间、目标、应用、实际处理及当时规则身份，同时保留来自G的查看线索 |
| 主动选择“查看R全部使用范围” | 明确切为R全部范围，示例中为16条，并出现G外视频的4条 |
| 返回 | 恢复实际走过的列表、对象与选择；不要求再经过没走过的组层级 |

从效果记录认出应用后，可以继续进入该应用；若主动查看应用的全部活动，应明确显示范围已经扩大。只按应用收窄当前效果时，仍保留G、R和时段，不把一次筛选悄悄换成应用全部历史。
恢复的是查看范围和位置，不是把示例数字固定住。记录有刷新时按该范围显示真实结果；用户主动改变的时段也应在这次查看链中保持可见。

## 查看范围不缩小共同修改的影响

在G里查看R的12条效果，只限制这次历史查看。用户选择“修改共同内容”后，进入当前R的内容工作，明确显示它实际作用的全部应用及应用组，包括G外的视频。
此时当前规则与全部影响成为主位；原来的“来自G办公的效果”保留为返回线索，不再并排摆两套同权范围面板。用户应能清楚理解：刚才只看G内，接下来改的是这条共同规则。
保存后显示当前内容与真实使用结果，再回原效果查看；时段、G范围和列表位置保持。历史记录仍按当时规则理解，不用修改后的条件替换过去发生的事情。
如果所选时段横跨一次修改，效果提示“包含修改前的处理”，并允许查看修改后的结果。完整旧条件不可用时如实说明，已有旧记录不能被当作新内容已经执行的证据。

## 状态与三层上限的读法

尚未使用、正在使用但本时段暂无记录、记录不完整，分别表达。可靠计数确实为零时可以显示0；缺少记录或覆盖不完整不能凭空改成0，也不能据此宣称规则未生效。
效果说明实际发生的政策处理。仅匹配、只观察、实际阻止、实际放行与传输失败按真实含义区分；放行不是远端访问成功的承诺。已有报文命中计数仍使用报文单位，不直接称为连接数。
合法层级为“G第1层 → H第2层 → K第3层 → 单条R”。在K内仍可添加单条规则；继续添加或引用子组会形成第4层，应在操作处说明已达到上限，并让超限选择不可执行。
引用已有组或从别处修改共用组，也按修改后实际最长组链遵守三层限制。不能因为独立打开K就把其现有外层引用忽略，也不自动扁平化、删子组或改变内容来绕过约束；具体提示形式仍是建议。
