# 第一版完整控制产品线：能力归宿与真实互辩

2026-09-30，C 完整链路观察席，gpt-6.1-sol / high。范围是第一版控制/规则交互相关的全部已有能力及已授权目标，下面的例子不是封闭清单。只写本稿；未修原型、改后端/愿景、操作设备或 tracker。

**首选：让人从认识对象、表达改变、核对结果出发，不设必经的独立控制世界或永久第三主入口。** 同时，主动安排不必依赖已发生流量；固定“＋创建改变／全部控制对象／管理共同内容”必须能打开和持续完成未来工作。完整表达、共享维护、发布修复有明确任务边界，实体存在不推出实体主页必须存在。

## 阅读、盘点与效力

先核对 [app-first README](../../app/design/prototypes/2026-09-29-interaction-directions/app-first/README.md)、`pages.json`、`js/pages.js` 的实际分派及 `experience/apps/rules/domains/manage/explore/activity/model` 源码，再读 [TMP](2026-09-14_RULE_ENGINE_DISCUSSION_TMP.md)、[统一规格](../product/UNIFIED_RULE_ENGINE_SPEC.md)、[功能盘点](2026-09-29_UI_FUNCTIONAL_INVENTORY.md)。只取当前有效产品语义，不恢复退休 C++ 或 checkpoint。
按用户前提，设计不因接口未接而删能力。下面 C＝现行合同可以表示的语义，P＝当前前端样例路径，T＝已授权目标但当前合同资料不能证明已承接；三者都不等于真实实现验收。特别是 T18/T19 正向名单与 V2 本地排除、订阅维护不是同一份已完成契约；DNS 目标照常设计，不用历史范围否定后续授权。
“认识／改变／核对／维护”也是用途检验，不是四个后台模块或四个必建页面。[Jobs 1997](https://book.stevejobsarchive.com/#speech-apple-1997)启发组合可解释性，[2007](https://book.stevejobsarchive.com/#speech-apple-2007)启发复杂能力须可发现；页数、能力数量与席位头衔不替产品取舍。

## 新实证：局部漂亮没有保住整条意图

- **批量：**选 Firefox/Signal 后逐项已生效，但 `save-batch` 因异步 `e.currentTarget` 为 null 报错并保持 disabled，需 reload 才能再次解除；日常 `apps` 也没有批量入口，只有总览 gallery 明确链接。应保留可发现多选、逐项后续处理与可重复操作，而非把成功行当完成。
- **复杂创建可以走：**about→协议目录 SSH→Firefox observe→AND Wi-Fi→priority5/order77→已保存 v44、仍用 v42→重试使用 v44→回协议目录。不能只优化名称例外；此输入、执行方式、顺序和修复路径都要保住。当前 `stats` 未接协议/效果视图，旧函数存在不能算覆盖。
- **重新编辑丢模式：**`r4` 原 Firefox observe，新增 Signal enforce 合法；只改规则名称并保存后 Signal 也变 observe。编辑器从首条 direct mode 取值并合并分配。新设计须维持每条使用关系，改变未选择字段不能顺带改变模式。
- **地图换题：**`map?app=s4&type=dns&result=blocked&window=15,20` 仍显示两条连接/1.3MB；URL 字段留下，正文却未表达被筛掉的查询。投影必须兑现类型、结果、目标和时间或明确未入图，不能只保 app/time。
- 复现脚本 `/tmp/whole61-control-inventory.js`、`/tmp/whole61-mode-preservation.js`；仅本地前端样例。此前 DNS 规则预演范围、分配计数、名称子域重开等断点继续成立；不再扩展找 bug。

## 逐屏链一：没有近期活动，也能主动建立并维护未来安排

以下是目标组织，不声称当前原型整链走通。
1. 首屏固定全部对象/＋，在管理在线但无近期流量时选两个可独立控制身份；批量处理已有快捷限制逐项给结果，不以临时禁止当永久方案。
2. 表达“未命中其他允许时阻止”→最低优先显式兜底 DROP；协议选择 SSH，另建更早 ALLOW；网络、端口、方向/CT 与完整树在同一具名编辑任务展开，尚未使用内容也能保存/再找到。
3. 看每个对象拍平后的实际顺序和模式；若最高快捷 DROP 仍在，不许局部 ALLOW 冒充解除。priority/order 可改，成员组织不伪装优先权。
4. 命名可复用内容、包含嵌套组、选择两对象使用；同源同对象 observe/enforce 冲突指出两条路径，让人显式调整；未选的其他关系保持原意。
5. 预演选择本次输入与明确合成事实；真实 observe 若采用，则承诺实际允许与真实赢家，不是离线试算。缺事实不推断成功。
6. 提交失败留工作；保存未使用时旧使用版仍可见，修正/retry 回本次任务。启动配置失败从状态修复后显式启动；不偷偷恢复 checkpoint。
7. 使用后按对应对象/条件/活动通道/生效后范围核对；再把 Firefox 从这项使用移除，Signal 保留、Firefox 其他安排继续。只从组中移除某规则对一个对象，须明示分离必要引用链及未再共享部分。
8. 完整配置导入是另一项替换任务；暂留/放弃本次输入明确选择，导入后基线变化重新核对。返回仍找到原命名工作与对象，不让专业作者每步重新搜索。

## 逐屏链二：地图选目标，复杂改变与资料更新后仍能核对

1. 同一调查范围看地图与精确目标表。地区只筛选；0B、private/未知、IPv4/6 与无地址查询的未入图范围保留。地理资料标来源/更新时间；当前补标不能冒充当时位置。
2. 选 Firefox→IP-A、Signal→IP-B，默认冻结“身份→地址集合”配对；不能自动形成两应用×两地址交叉。Linux 若同 UID，先显露共享身份，用户接受其所有程序的范围才提交。
3. 从精确地址行改变以后访问，默认 /32 或 /128；名称有证据才供另选 DNS/SNI，CDN/anycast 不证明名称因果。扩为前缀、交叉使用或共享内容是显式修改。
4. 专业编辑保留该输入快照，增加完整树/网络/顺序/模式；取消回原地图选择。预演可比较草稿与使用版，完整输入与未知分别表达；保存/生效/失败修正沿同一任务。
5. 后续核对按原身份→精确地址/条件/通道→生效后时间，不能继续用“国家=日本”筛选；GeoIP 变更、CDN 搬移、新 IPv6 不会自动进入原精确规则。
6. 若转维护共享名单，当前 positive 名单、目标本地排除及仅应用允许分别表达；来源候选审阅保留本地修改、全部消费者与实际模式；自动采用依明确偏好，不假称 T18 已支持整套订阅合同。
7. 完整替换/来源更新的保存和使用结果可追踪，失败保留旧实际范围；有后续实际记录才核对。普通未来窗口仍是活动观察；需要额外证据才启动临时诊断，不用静态预演解释过去真实路径。
8. 返回原调查恢复筛选/时段/目标选择和位置。旧记录保留当时事实；当前名单/位置/允许决定不能替换其原因，旧条件无据就说明无法重建。

## 393 与 1440：关联承担复杂性

393 日常首屏先真实记录状态、时段与变化，再认出贡献应用；全部对象与＋常驻，无流量也可开始改变。短局部改变就地，复杂表达进入具名任务，头部保留控制身份、活动通道、范围和本次工作状态；树、实际顺序、共享使用、预演为该任务的有名步骤。
393 未来工作进入后，首屏展示选定对象、本次未提交/已存未用与实际生效影响；未使用内容固定可达。完整导入、采用候选与修复是明确开始/退出任务。地图控制从目标表开始，地图帮助空间定位，地区不直接出现阻止开关。
1440 观察时地图/变化与等价目标/贡献并排；编辑时组成或使用关系在左、选中完整条件与真实有效顺序在右，预演/修改影响在需要时并列。先显露共同使用者再编辑；宽度扩大关联空间，不另设组优先级或假独立程序控制。
