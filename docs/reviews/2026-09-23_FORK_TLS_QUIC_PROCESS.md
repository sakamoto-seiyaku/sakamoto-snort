## TLS: concrete packet-to-field sequence

1. Node entry requires both `TAG_VAL_TCP_SEGMENT` and `TAG_VAL_L7PROTO_TLS`; it clears the TLS tag before decoding. “SSL prerequisite” is conceptual shorthand, not the literal gate here. [TLS node](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder_node.c:558)
2. Decoder requires a session, skips pseudo packets, creates session context, then consumes the linked `tcp_segment` list. No segment means no decoding. [session and segments](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:771)
3. Each segment updates an identification buffer, reconstructs TLS record headers/bodies, then handshake messages. Incomplete headers/bodies return with retained state; changing direction frees both record and handshake trunks. [record progression](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:624) [handshake fragmentation](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:420)
4. Only a complete ClientHello body enters the common parser. Success emits a ClientHello and marks `is_decoded_chello`; failure emits a ClientHello event with `is_malformed_hello=true`, not a no-SNI event. [ClientHello completion](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:460)
5. A nonempty message array is attached to the current buffer and restores its TLS tag. Scanner then publishes fields: malformed has its own branch; valid ClientHello with null/empty SNI sets `TLS_NO_SNI=true`, otherwise false, alongside `TLS_SNI`. [message attachment](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:817) [scanner distinction](/home/js/backup/backup/Git/vpp/src/plugins/stellar_scanner/stellar_scanner_plugin.c:1005)

## TLS: waiting, ownership, release, end

- Need-more is represented by partial headers/trunks and absence of a complete message, not a unified published “need-more” field. Invalid record-version alignment clears partial trunks and returns; parser errors and identification retry limits do not form a clean, universal terminal-result API. [record error and wait paths](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:665)
- Fork TLS owns its own record and handshake byte trunks **in addition to** upstream TCP reassembly. Partial ClientHello conditions claim original packet buffers. [claim conditions](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:807)
- The node stores claimed buffers and withholds forwarding. When the current packet is not detained (including detention-cap exhaustion), it drains prior buffers before forwarding the current one. Prior pseudo buffers are freed. This release is not gated exclusively on successful SNI extraction. [detain capacity](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:828) [drain and forward](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder_node.c:575)
- Parsed TLS messages are packet-owned and their free callback releases parsed hello objects. Session cleanup frees both byte trunks and any still-detained original packets. There is no explicit final “no SNI” publication in this cleanup path. [packet cleanup](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:862) [session cleanup](/home/js/backup/backup/Git/vpp/src/plugins/stellar_tls_decoder/stellar_tls_decoder.c:917)

## QUIC: concrete packet-to-field sequence

1. The node first requires a QUIC tag, clears it, then requires a session, known C2S/S2C direction, non-pseudo UDP packet, and nonempty UDP payload. Both directions can enter. [node gate](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:298) [entry prerequisites](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:209)
2. First session entry probes a supported QUIC version; unknown creates an ignored context. Existing ignored or already-published sessions return `ERROR` as a fast-path sentinel. [session entry](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1180)
3. Each attempt increments packet and payload accounting. The protected-version path requires a long Initial header, removes protection/decrypts, checks Initial encryption level, and suppresses duplicate packet numbers. [accounting](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1049) [Initial processing](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:911)
4. It stores decrypted frame payload fragments in a QUIC-owned bounded byte buffer. Frame joining places CRYPTO/legacy STREAM data at frame offsets in temporary storage, then feeds the shared TLS ClientHello parser. This is the actual implementation; it is not evidence of a complete gap/overlap-aware CRYPTO assembler contract. [fragment buffer](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:839) [frame joining](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:187) [shared ClientHello parser](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:377)
5. ClientHello length mismatch returns `CHLO_NOT_COMPLETED`; shared-parser failure returns `VERSION`. Successful parse copies SNI and fingerprints to session-owned QUIC info. Publication tests `sni != NULL`, not explicitly nonempty length or `CLIENT_HELLO` result. [parse results](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:377) [publication gate](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1074)
6. Publishing attaches a borrowed session-info pointer to the current packet and restores the QUIC tag. Scanner obtains the hello and publishes `QUIC_SNI`; the getter hides a hello when both SNI and user-agent pointers are null. No equivalent explicit `QUIC_NO_SNI` branch appears in this scan function. [attach](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:253) [getter](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:343) [scanner fields](/home/js/backup/backup/Git/vpp/src/plugins/stellar_scanner/stellar_scanner_plugin.c:3338)

## QUIC: waiting, errors, release, end

- `CHLO_NOT_COMPLETED` claims the original packet in a per-direction session list. Any non-claimed packet through the node drains the current direction's earlier claims, then forwards itself; successful SNI is not required. [claim lists](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:137) [result-to-claim](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:243) [drain](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:163) [forwarding](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_node.c:307)
- Decryption, fragment overflow, frame-join failure, and close frames can reach `ERROR`. In `quic_dissect_packet`, the error stop check compares `PARSE_RESULT_ERROR` to **version**, not returned `ret`. Therefore these errors must not be described as uniformly stopping further parsing; they do release claims on that packet's direction. [close/join failure](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:230) [decrypt error](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:959) [stop check](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1068)
- Exceeding packet or payload limits publishes version/info once when known, sets `ignore_session`, and returns `PAYLOAD`. This is an exhausted-budget outcome, not proof of a valid hello without SNI. [limits](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1055)
- Session destruction frees QUIC metadata/fragment bytes and, via a separate session exdata callback, remaining original buffers in both directions. Packet-info cleanup is deliberately a no-op because session owns it. No final no-SNI event is emitted here. [metadata cleanup](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder.c:1252) [packet and claim cleanup](/home/js/backup/backup/Git/vpp/src/plugins/stellar_quic_decoder/stellar_quic_decoder_plugin.c:342)

## Accepted product differences, not fork facts

- Product forwards original packets without waiting for SNI; do not reproduce either fork detention mechanism.
- Product has one bounded TCP byte cache owned by reassembly; TLS references that cache rather than owning duplicate byte trunks.
- Product QUIC owns CRYPTO assembly separately from TCP reassembly.
- Product v1 excludes tunnel-inner parsing; this narrow inspection makes no tunnel-support claim.
- Numeric limits remain open. The fork supplies implementation examples, not frozen product values.
- A product-level result model that reliably separates need-more, valid-no-SNI, parse/decrypt failure, stopped, and ended still needs an explicit contract. TLS already supplies the useful valid-no-SNI/malformed distinction; QUIC and teardown do not establish the complete distinction set.
