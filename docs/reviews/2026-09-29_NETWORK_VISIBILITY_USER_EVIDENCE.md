# 设备网络可见性：公开用户问题的一手样本

日期：2026-09-29。用途：为[设备网络掌控愿景](../product/NETWORK_CONTROL_PRODUCT_VISION.md)和应用优先原型讨论提供可回查的用户问题；本文不是需求投票、竞品评分或实现规格。

## 取样与证据边界

本次人工选择 17 条公开、可回查、由提问者本人写出的帖子或 issue。读取的是原始问题及必要的后续澄清，不从产品宣传页推导用户需求。每行只计一个独立帖子；未核对跨帖作者唯一性，不能视为 17 名独立受访者。GitHub issue 和支持论坛偏向故障、困惑、主动研究的用户；沉默且满意的使用者、未使用这些产品的人和不公开求助的人没有进入样本。年份较早的帖子反映当时的产品与系统，不证明今天仍有相同缺陷。论坛只显示相对时间的行明确写“约”；其中 NextDNS 页面可能显示更新时间，因此这些约年仅用于大致时间背景，不视为精确发帖日期。不能由 17 条样本推出“用户最关心”的客观排序、比例或平台普遍性。

[Portmaster 官方 2025 调查招募说明](https://safing.io/blog/2025/08/26/survey/)和[官方结果摘要](https://safing.io/blog/2025/10/24/survey-results/)另作背景：团队称收到超过 300 份匿名反馈，向现有免费与付费用户开放、需要登录 Safing 账户，问题大多可跳过；结果摘要提到临时暂停、活动自动刷新、VPN 兼容与配置管理。它没有公布各题分母、完整分布、招募响应率或可复核的排序。这个自愿参与的现有用户调查不能和下表散帖合并计算频率；“VPN 兼容最突出”等说法只属于该团队对自身调查的概括。

## 按使用时机整理的问题

1. **察觉变化时**：状态栏、费用、变慢或图上的峰值让人先问“这台设备发生了什么、由谁造成”。#1、#9、#10、#11、#17 指向设备总览与应用归因的连续路径；没有证据表明所有人会先搜索域名。
2. **某个功能坏了时**：用户先想恢复登录、网页、同步或教材音频，再追问是哪项控制所致。#2、#8、#12、#13、#14 显示单次结果、原因、当前作用范围和调整入口需要连在一起。
3. **核对控制时**：#7、#10、#12 的作者会拿上游日志、图表或应用行为与产品状态互证。DNS 查询、连接尝试、实际传输、被阻止后的零连接是不同事实；图表不能替代“是否真的执行”的答案。
4. **平时未出事时**：#5 和 #12 表明提醒或列表可以比网络本身更扰人。只说“有活动”或把未尝试访问的项目写成“Blocked”，都可能制造无从行动的工作。静稳状态应轻，但可直接展开详细证据。
5. **深入调查时**：#3、#4、#15、#16 需要保留历史、按应用或阻止来源筛选、从聚合走到原始事实。此类要求不能反推所有用户都想把详细技术列摆在首页。

这些是**问题类型，不是出现频率排名**。同一人可在不同时间经历几种问题；帖子也没有统一的任务、设备或提问方式可供做比例比较。

## 反例与取舍

- #17 和 #6 的作者要应用累计数字，并未要求识别每个域名；#12 想从少量自己设置的阻止项快速定位问题，不想在一个更大的“全面”列表中寻找。整体可见性不应默认等于更多细节、更多提醒。
- #3、#15、#16 代表会主动核对导出物、处理原因和名单来源的深入探索者。克制的首层仍要允许这些人从汇总走到原始事实，不能把精确度藏到不可到达。
- #11 涉及家庭网络，而 Sakamoto 愿景是当前 Android 或 Linux 设备；不能由此帖推导本产品必须承诺路由器或其他设备的观测。

## 对当前应用优先原型的启发与待验证假设

现有 `app-first` 原型以应用为默认入口，设备页已有总收发量、应用列表与可点时段，应用页也把 DNS 查询数与连接数分开。上述问题提示下一轮走查应重点检验：设备页能否让人从“今天的变化”立即定位造成变化的应用；图旁能否直接读到该时段数值与实际传输口径；从阻止或故障结果能否看见原因、资料来源和之后是否仍有成功连接；正常时页面是否安静而仍让人查证。这里提出的是设计假设，不能仅凭竞品帖子断言现原型已满足或未满足真实用户。

低成本的验证方式是让少量 Android 手机/平板与 Linux PC 使用者只看原型，分别回答四个情境：**“刚才流量突然变大，谁造成？”“登录失败，是否有控制挡住？”“我刚阻止的访问还会出去吗？”“现在一切正常，我需要做什么吗？”** 记录他们第一眼看的位置、所点路径、是否把 DNS 请求误当连接或流量、是否把图形峰值误当实际送达，以及何时需要展开详情。再用相同任务比较带/不带设备整体数值、应用归因和就地原因的版本；访谈中允许“我不想每天管这些”的回答。它比从散帖数量决定首页优先级更可靠。
