# 联网决定的交互结构与品味取舍

2026-09-30。本轮延续六席互相反驳与独立设计推演，重新审查第一版中所有认识、改变和核对联网行为的能力。规则、规则组、DNS 域名名单、拦截与地图只是其中一部分；连“控制／规则”是否应成为独立交互线，也作为问题讨论。

续审说明：本文记录上一轮收口。2026-10-01用户质疑其从使用体验推导形式的充分性，要求重新思考；下述三个目的位置作为待审方案，首页和应用详情已成立的内部关系保留。[新一手方法复查](2026-10-01_JOBS_EXPERIENCE_METHOD_RETHINK.md)区别功能／状态正确与整体体验成立，本文不作为冻结导航规格。

**最终选择三个稳定目的位置：网络、编写、深入检查。** 网络延续认识对象、就地改变和实际核对；编写承接从零与大量规则的持续工作；深入检查承接健康时也可主动使用的 Debug 额外证据。同一个人可以快速决定，也可以完整构建和深入观察，功能不按用户等级降格。

本轮最初的无第三入口方案，经健康 Debug、大量编写和整体兼容反证后改判；独立反方随后提出同等完整的固定任务壳。最终比较的是稳定用途名称、正文来源和持续工作工艺，导航数和设计席身份都不是胜因。

最终结构、30项完整归宿与两条跨线压力旅程见[整体深度裁决](2026-09-30_DEPTH_DESIGN_VERDICT.md)，可查看[交互参考板](assets/2026-09-30-control-debate/control-reference.html)。当前产品原型没有按此改版；参考板的内存样例不是真实配置、网络活动或接口验收。

## 裁决按什么判断

用户最后明确的尺度是乔布斯的设计哲学与品味。设计席可以推演，也必须接受反证；它不能因为被称为“乔布斯”就获胜。我们使用已读一手材料提出检查问题，再承担今天的具体选择。

| 一手材料支持的判断尺度 | 本轮怎样使用它 | 不能据此直接推出什么 |
| --- | --- | --- |
| 熟悉经验与一致操作机制 | 先认设备、应用和实际目标；动作说明改变哪个对象、什么范围，深入仍围绕同一问题。 | 只能有两项导航，或所有任务必须同页。 |
| 形式表达用途，精度匹配尺度 | 条件树保留分组；使用方式与定义动作分清；手机主动作说出真实影响，宽屏让相关内容相邻。 | 留白、少按钮或字体漂亮就证明直觉。 |
| 聚焦同时包含改善和补缺 | 挑战独立控制入口，同时追查批量、协议、未使用内容、修复等能力是否失去归宿。 | 精简等于删掉专业能力。 |
| 能力要被发现并实际使用 | 空设备有可见起点；查询、编辑、核对、提交、失败修正及返回组成完整任务。 | 文件存在或 API 可调用就是功能已获得。 |

实际阅读范围与来源见[品味](2026-09-30_JOBS_TASTE_PRIMARY_RESEARCH.md)、[逻辑](2026-09-30_JOBS_LOGIC_PRIMARY_RESEARCH.md)和[整体](2026-09-30_JOBS_WHOLE_PRIMARY_RESEARCH.md)研究。Jobs 发言、Ive 回忆与档案编者解释分别处理。上述页面和导航是我们的推演，材料没有直接规定本产品的形态。

## 目的位置经历了什么反驳

上一轮“概览／活动／联网安排”是临时首选。本轮先撤掉独立控制线与资产主页必须存在的前提，六席实际交换方案，第一轮选择连续网络空间及明确任务壳，见[当时裁决](2026-09-30_CONTROL_DESIGN_VERDICT.md)。

健康 Debug 与从零大量规则工作进一步挑战了它。只靠＋、搜索或一次进入，不能代替持续工作首屏。三席随后真实改判；输入、使用关系、预演、提交与修复应连续，Debug 的实际证据源独立，并且正常运行时可主动开始。

随后另一席提出更强的反案：固定三个任务位置，空位启动、活跃继续、结束呈结果；同样完整保留大量输入、有界 Debug、版本和返回。设计席承认它与三个目的位在几何与能力上基本等价，撤回先前“双套指路”“结束后移位”的误判；A、C 两席也撤回“三目的必然拆成第三世界”的指控。

**最终采用稳定的用途名称，实例状态作短提示，完整题目、范围与版本进入正文。** 它承担常驻位置及学习候选／实际区别的成本。A、C 两席更偏连续空间和实例状态措辞，异议保留；固定壳采用同样的目的、状态与正文关系，也可以成为等价落实。

规则、组、名单依然表达真实内容与引用，但不因后端有这些对象就各占一处主导航。全部应用、就地创建及对象搜索加速快速决定；完整工作在固定“编写”位置持续。

## 一套结构承接全部深度

| 稳定位置 | 完整工作与主位 | 与其他任务的关系 |
| --- | --- | --- |
| 网络 | 可信时段、图与同段贡献、完整活动、应用、统计及地图；事实上的局部决定与后续核对。 | 无活动对象也可进入；复杂决定将同一输入带入编写，返回原调查。普通未来窗口仍是网络事实。 |
| 编写 | 从零、大量添加／导入、集合与所选定义、完整条件、顺序、共同使用、名单维护、批配、预演、整配置提交与修复。 | 一个完整候选、明确保存基线；切位置保留输入与选择。预演是预计，不能改名成为 Debug 实际证据。 |
| 深入检查 | 健康时选择实际身份、范围与额外证据，开始／继续／结束单个有界 Debug 会话，查看与导出原证据。 | 规则执行／observe、Root／VPN 与额外证据分别表达。编写／发布不结束会话；结束只停止额外证据，普通记录继续。 |

没有把用户分成一个简单产品和一个专业产品。同一个人可写一条或五十条、看普通事实或深入判断；完整表达与直接操作都属于主产品。

共同状态包括真实身份与目标、观察范围、本次输入、已保存、正在使用、资料候选和 Debug 会话。每条实际证据保留自己的当时版本；晚到旧版记录不随当前配置改写。候选预演与运行证据可以关联并列，各自有标题和来源。

有未提交输入时，整套导入明确替换本次候选或取消保留。名单采用或外部保存改变基线，则保留输入、标原审阅过期，读取最新保存／使用内容并重新核对引用、模式、顺序与影响；不能仅换一个版本数字继续旧候选。

## 真正改变了方案的反驳

| 实际反证 | 最终处理与所付代价 |
| --- | --- |
| 无第三入口若只剩搜索，新人不知道可以批量、按协议或从零创建。 | 撤回“搜索足够”，保留可见目录、多选、意图式创建、设备任务和未使用内容；占用必要空间。 |
| 一条去重规则的观察开关可能修改整个组的使用方式，连带其他成员。 | 模式落在真实使用关系；隐式直接使用与可编辑绑定分清。多一次来源核对，换取真实影响。 |
| 新增同条件观察副本也可能排在原阻止之前成为允许赢家。 | 主动作检查并调整已有使用；复制是明确的新身份与次选，展示顺序和实际结果，不能承诺同时保持阻止与影子观察。 |
| “给 Firefox 例外”可能指一个名称，也可能指完全退出共享规则。 | 特定事实用本身份普通规则；停止具名组关系只撤那条关系；彻底退出某成员则明确分离必要引用链、重绑及审阅残留来源。分离部分不再跟随原组更新。 |
| 最高快捷限制仍在时，新局部允许可能不改变实际处理。 | 首先显露真实赢家及解除的范围，明确解除后返回同一输入；其他规则继续判断，高级保存不冒称恢复。 |
| 地图分别勾应用集和地址集会形成未经选择的组合。 | 按真实控制身份与 IP 的配对快照选择；地域与精确清单相邻，提交逐项核对，不产生笛卡尔积。 |
| 批量、协议和规则效果只在旧文件或总览里存在，日常路径可能失联。 | 新结构必须给主动任务固定起点；以真实入口检验能力获得，旧函数数量不能证明覆盖。 |
| 共享规则只改名称，旧样例却可能把首个使用方式覆盖到其他身份。 | 定义编辑保留每条真实使用关系的方式，提交核对其影响。旧原型问题在此作为设计反证记录。 |

这些来自实际消息交换、源码核对或浏览器操作；各席报告区分本人实证与收到的他席证据。没有编造一场一致同意的对话。

## 全部能力按人的任务安放

下表是归宿摘要；最终按三个目的位置汇总的30项能力见[整体深度裁决](2026-09-30_DEPTH_DESIGN_VERDICT.md)。字段、例外和状态的原始完整核对见[全线功能核对](2026-09-30_CONTROL_PRODUCT_LINE_DEBATE.md)与[任务覆盖答辩](2026-09-30_CONTROL_COVERAGE_DEBATE.md)。保留能力不等于保留第一版每一张页面。

| 人的任务 | 具体入口与深度 | 最终使用的能力 |
| --- | --- | --- |
| 认出谁、发生什么 | 图与同段贡献、完整活动、全部应用、统计／地图、事实深入 | 身份与范围、过滤排序、连接／查询结果、协议及规则效果、覆盖和历史依据。 |
| 改一个或一批对象 | 对象明确动作、无活动目录多选、设备创建任务 | 全部／分网络快捷限制、解除、多网络组合、有限身份批量、普通允许／阻止及真实使用方式。 |
| 精确表达以后怎样处理 | 固定编写位置，或由局部决定带同一输入进入；可先保存而暂不使用 | 创建／编辑／命名／来源／复制，AND／OR／NOT，地址端口、网络接口、方向、CT、发布协议、名字与 SNI 可用性，priority／order。 |
| 共同使用和局部调整 | 编写中的命名内容、组成与实际使用关系，同一任务连续核对 | 复用、组与嵌套、绑定、完整有效顺序、全部来源、观察冲突、解除、分离、删除引用处理。 |
| 维护匹配资料 | 编写中的内容、来源维护、真实用途及独立候选审阅 | 精确／子域、限定格式导入、规范化与错误、本地补充／排除、订阅检查及暂停／停止／采用目标。 |
| 试一个如果，核对真正结果 | 预演贴同一输入；网络核对实际后续；深入检查取得额外真实证据 | 合成输入与版本选择、缺事实理由；真实 observe 的赢家和动作；实际后续、普通未来窗口、额外诊断证据与导出。 |
| 保存、迁移和修正 | 本次结果及设备持续状态，无需借道某个应用 | 保存前校验、版本冲突、保存失败、已存未用、修正重试、启动修复、整套替换差异、导出／清空、输入取消与保留。 |

判断顺序始终由现有规则语义承担：priority、明确 order、稳定身份；组遍历不增加优先，完整无赢家默认允许，默认拒绝是普通末位 DROP。观察保留声明动作与赢家，实际允许；允许不是交付成功。

地图承担空间理解与同范围筛选。选择地区后，在精确配对清单直接选目标，再从有证据的 IP/CIDR、名称或现有使用关系作决定。未知位置、特殊地址、IPv6 及没有地址的 DNS 事实仍有归宿。地域不变成安全评级、服务身份或动态国家执行条件。

## API 约束语义而不划分界面

界面可以从一个用户动作组织完整配置读取、候选构造、校验、保存与发布，也可以把多种接口结果合成一个对象画面。它不建立第二套规则模型，更不把后端模块直接升为页面。

| 状态 | 本轮准确口径 |
| --- | --- |
| 已有语义与接口基础 | 完整规则／组／绑定／正向名称名单配置，条件表达、顺序、普通快捷限制、保存／使用结果、完整导入导出、Flow／SNI／观测与维护窗口。参见[T04](../interfaces/T04_RULE_GROUPS.md)、[T05](../interfaces/T05_NETWORK_DISABLE.md)、[T18](../interfaces/T18_DOMAIN_LISTS.md)、[T19](../interfaces/T19_CONFIGURATION_IMPORT.md)及[接口地图](../INTERFACE_SPECIFICATION.md)。 |
| 已授权设计目标及所需契约 | DNS 查询接入与关联、名单局部排除／来源调度／候选版本、组友好名称持久化、完整预演的输入与快照选择、地图 enrichment 与相应聚合、诊断额外证据。它们保留体验，当前接口或开发工具不自动证明产品契约完整。 |
| 不能凭界面外观增加的语义 | 国家匹配、独立 CIDR 名单后台、隐式组内优先级、继承成员排除开关、任意规则 enabled、影子 observe、未来未知身份自动加入当前批次、首版 checkpoint。 |

T18 的当前名单是正向 exact／descendants；T19 的限定导入拒绝不支持的例外语法。不能把一份子域集合内的局部排除假装为简单删除条目，也不能暗改所有消费者来冒称当前名单 API 已承接。具体契约仍保持统一权威模型。

Android 资料与完整 UID、共享 UID 成员，以及 Linux 实际控制身份贴在对象和提交处。程序名是观察线索，未自动获得独立控制权。“选择全部当前控制身份”只兑现本批，不能冒称覆盖未来和不可控未知身份的长期整机限制。

## 参考板实际核对

本轮于2026-10-01完成浏览器收口。四种窗口（Android手机／平板、Linux桌面／小窗口）各八个关键视图，共32个布局条件；六条有限内存路径通过，未出现页面脚本错误。关键图和收据见[截图目录](assets/2026-09-30-control-debate/screenshots/)与[验证记录](assets/2026-09-30-control-debate/screenshots/validation.json)。

实际路径包含旧查询→局部提交→后续→原事实；具名组解除→保存未用→重试与残余来源；observe冲突→明确调整；地图精确配对→提交→返回；健康D1→新增50项（含原有共54项）→保存43仍用42→修正44→晚到42／新44证据→结束后普通新记录→原输入；DNS-only地图保留未入图查询。

两席另实际查看整合板。有限核对指出候选预演回错任务面和普通未来样例始终为空，主评审已修正；再次操作确认源任务选择／位置恢复，结束 Debug 后普通新事实可见而旧 Debug 行不增加。反方保留设计偏好，同时认可连续输入、实际版本与 dirty 基线核对的收益。

参考板只验证构图、明确样例状态及这些路径；完整CRUD、任意表达式匹配、真实预演服务、Debug采集与生产API接线未由它证明。原产品原型保持本轮开始时的字节，正式实现与验收不在这次辩论范围。
