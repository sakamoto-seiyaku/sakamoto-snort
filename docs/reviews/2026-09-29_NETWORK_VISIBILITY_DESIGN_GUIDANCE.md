# 网络透视与直觉设计：收敛指导

日期：2026-09-29。性质：根据[网络透视研究综合](2026-09-29_NETWORK_VISIBILITY_RESEARCH_SYNTHESIS.md)、[产品愿景](../product/NETWORK_CONTROL_PRODUCT_VISION.md)、[手机首屏](../../app/design/prototypes/2026-09-29-interaction-directions/app-first/screenshots/phone-home.png)、[桌面首屏](../../app/design/prototypes/2026-09-29-interaction-directions/app-first/screenshots/desktop-home.png)，以及设计质询与用户证据质询两位代理已完成的三问对三问记录所作的**设计裁决**。这是下一轮原型指导，尚非用户测试结果或已确认页面规格。

**核心指导：首屏让整台设备的活动随时间可直接感知，并立刻连到熟悉的应用；选中一段或一个应用后，在同一可见范围里逐步看清事实、作决定、核对结果。**

我不采纳「短设备卡 → 应用列 → 整体图后置」作为手机最终方向。它可能让用户不用读图，却过于接近现有的“今日累计 40.3 MB + 最近应用”，仍使不知道应用的人缺少直接观察整机的入口。也不采纳把完整曲线变成首屏唯一主角：零字节 DNS 阻止、记录缺口和平静时段就难以得到恰当表达。建议在手机第一屏设置**一块紧凑、可触摸的整机时间带**，与第一批应用行同时可见。时间带用直观的发出／收到形状表现时间起伏，在同一范围单独标出 DNS／连接结果与观测缺口；时间带应能让人直接看出活动的起伏，并提供可读数值和等价文字入口；能否做到仍需原型走查。点时间带的任一段进入贡献视图；点应用行仍直入该应用。没有强行生成的“比前十分钟多多少”句子，也不因没有波峰而失去进入路径。[研究综合](2026-09-29_NETWORK_VISIBILITY_RESEARCH_SYNTHESIS.md)中的竞品联动和“未知应用来源”原帖支持要试这条路径，不能证明其布局已胜出。

## 六个真实质询焦点及裁决

下表概括两位代理互相提出的六个问题及逐题回应，不复述虚构台词。前两份临时对话记录中的改口与保留意见均已计入；这里明确作出取舍。

| 质询方向与焦点 | 互问带来的实质修正 | 本文裁决 |
| --- | --- | --- |
| 设计→证据：图先出现，会不会让用户先学“图的语言”？ | 证据方撤回“大图变化先行”，改短设备卡、应用列、图后置，随后补充一条可核验的时段变化／贡献者句。 | **拒绝图后置和每次自动写总结句。** 在应用之前给紧凑、可直接点选的整机时间带；标签用“发出／收到”、明确时间与单位，应用行紧跟其下。形状承担变化，简短事实承担准确性，不靠任意前段比较。 |
| 设计→证据：图、应用、记录、地图同步什么？ | 双方主张仅持久保留时间，避免多处高亮造成伪因果；地图需明确进入。 | **修正“只留时间”。** 持续的是可见的观察范围：时间，可逐步缩到应用或有证据的目标。天气→统计／地图／规则不得静默回到全设备。单条记录只是当前焦点；不让多个独立隐形筛选叠加。地图沿用明确范围，只给有位置依据的连接事实标位置及结果；不凭 DNS 查询或同时发生的活动画连线。 |
| 设计→证据：一小时平静时为何还值得打开？ | 双方接受稳定设备／应用主体，不制造异常；可点普通时段，深层地图与规则保留。 | **接受平静可探索，拒绝每次都必须“发现变化”。** 时间带在平静时仍显示连续观察范围、少量真实活动或明确的无活动状态；普通段与应用同样可点。若无可靠前段基线，绝不造比较和“正常”结论。 |
| 证据→设计：20 次 DNS 阻止、已记录 0 B、另有记录缺口，哪件事突出？ | 设计方撤回“字节图代表全部活动”，选 DNS 阻止为该情境主事实，缺口与零字节分开。 | **接受事实优先，不固定 DNS 永远优先。** 同一时间带有独立事件标记；该情境以“20 次域名查询被阻止”作可点事实，紧贴“已记录 0 B／某段记录不完整”。不用红色风险评分，也不把查询阻止画成传输峰值。 |
| 证据→设计：归属未知、多应用共同去向如何追？ | 双方承认未知不伪装成系统应用；同一目标需记录证据，不能把共时写成因果。 | **接受可证实的关系，拒绝自动因果故事。** 所选时段先列各应用贡献与“归属未确定”；共同去向为可主动进入的另一种整理，查询和连接按类型与结果区分，只有直接关联证据才链接两者。 |
| 证据→设计：共享订阅误拦如何既快又诚实地调整？ | 双方提议天气／单域名／DNS 的局部例外，提交后区分保存、生效、后续活动。 | **接受按事实限定范围与分阶段反馈，拒绝把该例外升级为全产品默认。** 若只证实 DNS 查询被挡，动作只能承诺该查询范围；若当前任务和证据是完整目标意图，沿用产品已接受的目标范围表达并交代关联连接。修改共享名单才审阅共享影响。原记录仍写当时结果；保存或生效均不冒充功能恢复。 |

## 用来否决页面方案的六条原则

1. **整体活动必须在手机首屏可见，应用也必须当场可认。** 可见行为：顶部短状态之后，一块整机时间带展示所选范围内发出／收到的时间形状及独立事件、覆盖标记；其下不远处即可看到真实应用图标、名称和相关事实，点时间段或点应用各有直接结果。否决信号：首屏只剩今日累计量加列表，或图独占首屏使应用必须滚动很久才出现。它回应当前[手机截图](../../app/design/prototypes/2026-09-29-interaction-directions/app-first/screenshots/phone-home.png)的具体缺口。
2. **先给可读的对象，再允许丰富探索。** 可见行为：时间带不是无解释折线；“发出／收到”、时间与选择范围靠近图形，应用图标出现在贡献列表中，选一段后再看记录、去向、地图、统计。手指点中一整段或等价文字入口，不必命中细线；键鼠有同等可见焦点。否决信号：靠颜色、悬停或懂协议才能找下一步，或为了“简洁”把探索工具藏到完全无关的设置层。《[On the Macintosh](https://book.stevejobsarchive.com/)》是 Jobs 本人的熟悉表达及表达丰富性的阐述；把它映射为本页面是我们的推论。
3. **一个可见范围贯穿全程，精确到当前任务所需。** 可见行为：所选 `09:20–09:30 · 天气` 始终可见并可逐项解除；进入该应用的统计、活动、规则或有依据的地图时保留范围，返回保留时段和滚动位置。全设备与单应用的数字有清楚标题，不能混用。否决信号：切页静默变全设备、点击应用只高亮却还需猜第二次点击、地图默认用无证据的地理点解释 DNS。Jobs 在[1984 年 Moritz 访谈](https://book.stevejobsarchive.com/)谈适合物件尺度的精确与持续打磨；这里的范围语义是产品推论，不是他对网络 UI 的意见。
4. **事实的形态决定视觉分量，未知保持未知。** 可见行为：DNS 查询数、连接数、实际收发字节、阻止／失败结果及记录覆盖各有自己的单位和形态；选中零字节 DNS 阻止段仍能看到可点事件；观察暂停、记录缺口、真实零值分开。只有同范围、同口径且覆盖足够时才可选地给前后比较；陌生去向或尖峰仅是探索线索。否决信号：自动“异常”或绿色安全分、把字节为零写成安全、把首次观测说成首次发生。[Aretha 实地研究](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)提示陌生目标会吸引注意，却不能证成风险；本项目无需借此造评分。
5. **控制入口直接，范围与结果说清楚。** 可见行为：从具体记录进入决定时先见应用、目标、DNS／连接适用类型及受影响范围；必要时才展开共享来源。提交后明确未保存／已保存未生效／已生效，随后回到原记录或所选时段检查新活动，旧记录不改。否决信号：“一键修复”跨越未证实的连接、改动整份共享订阅却不说明其他使用者、查看后续活动暗中制造样例。[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)显示后果不清会阻碍实际使用；反馈路径属于本产品的取舍。
6. **克制体现在分量和手感，不靠删能力。** 可见行为：首屏只有一个整体观察面与应用列表形成明确读序；数字、动效、图标和颜色服务选区及结果，同一事实不重复写成长句；选时间时内容在原处响应且焦点不突然跳走。地图、完整规则、名单、趋势、统计和诊断有清楚入口，深入后仍可返回原问题。否决信号：六张等权卡片、三个竞争主按钮、为“显得智能”强写解释句、深层能力被删除。Jobs 在[1997 员工讲话及 1998 Macworld 演讲](https://book.stevejobsarchive.com/)谈聚焦产品线，并非要求在单个工具中砍掉用户任务；[Jony Ive 的回忆](https://stevejobsarchive.com/stories/objects-of-our-life)与 Archive 编者的故事也应和 Jobs 本人的话分开。这里的审美与操作标准由我们负责，需在原型中反复打磨。

观察范围的连续性也包含页面含义：进入当前规则或名单时，保留来源应用、时段和返回位置，但配置页明确显示当前保存／生效状态，不把历史时段当作当前配置的筛选条件。历史记录的处理依据仍指向当时使用的规则与资料；改变现有配置不会改写它。完整目标控制是用户可以明确选择的意图，单条 DNS 记录不能代替用户决定所有后续连接的范围。

## 手机首屏与一条完整任务

**393×852 的稳定读序**：① 顶部“这台设备”与简短、可核实的运行／观测状态及最新记录时间；② “最近 30 分钟”整机时间带（仅为演示初值，默认窗口长度待验证），发出和收到分明，DNS／连接结果与缺口用独立小标记，普通时间段也可点；③ 与默认时间范围一致的熟悉应用行，第一批图标、名称、最后活动及合适单位在首屏露出。选中时间段后先显示该段的贡献应用和“归属未确定”，再进应用或单条记录。读完①②便能感到活动在时间中变化；不操作时间带也可直接点天气。窗口上部避免大面积空白和只有“今日总量”的英雄数字，选区有明确视觉回声而非突然整页跳转。平静时不强行生成“变化”文案，显示真实状态、可进入的普通时段和应用。

**演示任务：**用户只说“刚才网络好像忙了一阵，不知道哪个应用”。首屏时间带上 09:20–09:30 一段发出较多，旁边还有该段的 DNS 阻止标记；没有“异常”字样，也不声称它比任意基线危险。点此段，页面保留 `09:20–09:30 · 全设备`，列出**已记录**发出 1.4 MB 的贡献：天气 0.9 MB、音乐 0.4 MB、归属未确定 0.1 MB，另列 20 次域名查询被阻止；若 09:24–09:26 有记录缺口，同时标出，所有数值只覆盖已记录部分。点天气后范围变为 `09:20–09:30 · 天气`，可看其收发、DNS、连接各自的事实；不能因天气贡献了字节，便把同段所有 DNS 阻止说成它造成。点一条**确归天气**的域名查询阻止记录，看到当时命中的共享名单。用户可审阅对此记录可证明范围的决定；此例没有关联连接证据时，不能承诺连接或音频已恢复。保存、生效和后来是否有新活动分别反馈；返回仍在天气的同一时段，再退一步仍在整机的同一时段。若该段只有 20 次被阻止查询、已记录 0 B，这条时间入口和 DNS 记录仍可到达。整个过程既能从整机出发，也允许一开始就点已知的天气应用。

## Android 平板与 Linux

Android 平板用宽度容纳**同一范围的并排关系**：整机时间带与贡献应用在左，所选应用／记录在右；时间和应用范围显示在共同的上方，右侧变化不冲掉左侧选区。Linux 宽窗也并排，但保留 Linux 的导航、键鼠焦点和本机语义；可通过键盘选时间段、切贡献应用、进入详情和返回。Linux 窄窗按手机的逐层阅读顺序折叠，仍用 Linux 的身份和控件语义。三者都不能依赖悬停才能解释阻止或未知，也不能让地图一打开就抹去当前应用；地图有有据的位置时呈现连接尝试或实际连接的**真实结果**，没有地理证据时明确不画位置。平台不改变 DNS 查询、连接、传输量的单位和事实口径。[产品愿景](../product/NETWORK_CONTROL_PRODUCT_VISION.md)。

## 本轮取舍

| 采纳 | 拒绝 | 留给下一轮原型判断 |
| --- | --- | --- |
| 手机首屏一块可触摸整机时间带，应用行仍首屏可见；已知应用直接进入，未知来源先按时段看贡献。 | 现有总字节加列表的轻微改版；图后置到应用列表之后；巨幅纯字节曲线占满首屏。 | 时间带的高度、条形／面积／短曲线哪种形态最不需学习，同时容得下第一批应用。 |
| 时间与已选应用组成可见观察范围，沿统计、活动、地图、规则与返回保持；未知归属单列。 | “只持久保留时间”；隐形多重筛选；自动把共时与共同去向画成因果。 | 手机进入贡献视图时，是原处展开还是整页进入能更好保留位置与触感。 |
| DNS、连接、传输与覆盖独立表达；正常时段可主动探索；按真实对象限定操作范围并核对执行结果。 | 每次自动比较前十分钟并生成贡献总结句；流量尖峰风险评分；DNS-only 例外作为所有控制的默认；地图仅允许画已建立连接。 | 在真实一瞥、零字节阻止、缺口与失败恢复任务中，事件标记何时需进入主视线；不能仅凭视觉偏好定阈值。 |

以上审美推论与用户研究各有边界：Jobs 本人的已编辑讲话和访谈提供熟悉、精确、聚焦及表现力的设计质询，Archive 的编辑叙述及 Ive 回忆是另一个视角；竞品、公开原帖和小样本认知研究提供问题与风险，均未证明本首屏一定可用。下一轮以同一批事实在 Android 手机／平板与 Linux 宽／窄窗比较，优先看用户能否**不猜应用地找到那一段、认出贡献者、正确说出阻止与记录缺口、完成调整并返回核对**。[研究综合](2026-09-29_NETWORK_VISIBILITY_RESEARCH_SYNTHESIS.md)。
