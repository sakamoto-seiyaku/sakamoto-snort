# 网络透视：认知与使用心理证据

日期：2026-09-29。本文为[产品愿景](../product/NETWORK_CONTROL_PRODUCT_VISION.md)及[应用优先阶段一原型](../../app/design/prototypes/2026-09-29-interaction-directions/app-first/README.md)提供设计证据，不评价现有代码是否已实现目标能力。研究对象是 Android 手机／平板和 Linux PC 上的**设备网络行为透视**：用户尚不知道是哪一个应用引起变化时，也应能从整体观察走到对象、时间、去向、处理结果及可采取的决定。假设应用身份、DNS 与 IP／连接事实可用；流量理解和控制同等重要。乔布斯式的熟悉、直觉、聚焦、精确、克制、连贯是本产品的设计约束，不作为实证来源。

## 证据如何使用

以下选用六项一手用户研究和两篇提出框架的原文。访谈、焦点小组与探索性部署可揭示人们怎样解释经历、希望获得什么及使用时的阻碍，不能证明某种界面会使全体用户表现更好。实验／现场观察提供其特定任务、设备与样本下的行为证据，不能直接换算成 Sakamoto 的转化率或告警阈值。两篇框架仅用于组织设计与测试问题，不是本产品的用户实测。七项已核对论文全文；Endsley 的扫描版全文未能完整读取，仅依据作者原文中可检索的三层定义和论文摘要使用该框架，未借此补造实验结果。

## 从证据到本产品的判断

**应用熟悉感是有价值的起点，尚未被这些研究证明为唯一或最优入口。** Kang 的访谈说明互联网内部参与者常不在非技术用户模型里；Aretha 的实地观察说明“去向”会激发进一步提问，但陌生目标也可能吸走对大规模熟悉目标的注意。我们据此提出：用户已有应用线索时从应用进入；只有“刚才感觉不对”而不知应用时，从可选时间窗的设备整体活动进入，再看到贡献应用、去向和结果。两条路应在同一组事实汇合。此为设计推论，需用任务测试，不能称为研究已证实的用户习惯。[Kang 等](https://www.usenix.org/system/files/conference/soups2015/soups15-paper-kang.pdf)；[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)。

**透视不等于一个“安全分数”。** Endsley 的模型提醒区分看见、理解与推测；Aretha 也显示元数据能揭示去向，却不能说出加密内容。首页可说“正在观测／观测到何时／这一时段发生了什么／哪些对象贡献了变化”，但没有记录、观测中断、身份未知和确实为零须分开。未知不能用绿色安全评价或“已保护”替代；同理，字节尖峰和陌生域名只能提示可检查的事实，不能直接诊断恶意。[Endsley](https://doi.org/10.1518/001872095779049543)；[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)；[NIST IR 8330](https://nvlpubs.nist.gov/nistpubs/ir/2020/NIST.IR.8330.pdf)。

**行动必须连着解释和实际反馈。** Aretha 中规则入口虽存在，因目标多和功能损伤顾虑仍少有人使用；其作者明确建议显示阻断后果并支持故障后修正。Sakamoto 的“决定”应就地呈现作用对象、DNS／连接类型、目标和影响范围；保存、生效状态以及后续真实结果应与原记录相连，历史结果不被新规则重写。若无法预知某应用会不会坏，只能说明可能的影响与撤销方法，不能保证“安全阻断”。这是研究启发加产品约束，不是已验证的本产品结果。[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)；[Shneiderman](https://hci.stanford.edu/courses/cs448b/papers/shneiderman96eyes.pdf)。

**正常态要能安静地供人检查，变化也要能被发现。** 对于未主动寻找的用户，旧 SSL 警告的高忽视率、较强警告对正常任务的妨碍，以及手机权限提示重复后效果下降，均反对将所有流量变化升级为中断。另一方面，权限提示研究显示具体事实和可行动路径可能促使复查；高级用户的焦点小组则要求按去向和对象自主探索。建议同时测“被动一瞥”“无目标追查”和“主动钻研”，而非把人固定分成小白与专家。[Sunshine 等](https://www.usenix.org/legacy/event/sec09/tech/full_papers/sec09_browser.pdf)；[Almuhimedi 等](https://www.cs.cmu.edu/~halmuhim/MobileAppPrivacyNudging_CHI2015.pdf)；[Park 等](https://www.usenix.org/system/files/soups2023-park.pdf)。

## 六个可证伪的设计假设

以下均是**待验证假设**，不是上述论文的已测结果。比较时使用相同真实或忠实模拟的 DNS、连接与传输量资料；Android 手机、平板和 Linux PC 分别测试。访谈中同时纳入只想看当前情况的人和愿意研究网络流的爱好者，避免一种平均值掩盖两种任务。

1. **无已知应用时，先给同一时间轴上的设备变化与应用贡献，会比只给“今日累计量 + 最近应用列表”更容易定位对象。** 任务口令：“刚才感觉网络行为不对，但不知道哪个应用。”让用户选时间窗、发现发生变化的事实、指出相关应用并说明证据。测定位正确率、首次有效操作时间、误将大流量或陌生目标定为威胁的比例。若正确率无改善或误判升高，假设失败。时间轴表达的是相对变化，不能自行判定异常。[Endsley](https://doi.org/10.1518/001872095779049543)；[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)。
2. **在整体趋势上选时段后，于原处联动显示贡献应用与活动类型，再进入应用详情，比直接跳原始记录表更有助于解释“那一段发生了什么”。** 保留筛选时间，分开 DNS 查询数、连接数与传输量；用明确结果区分允许、阻止、失败。测正确说出对象／时段／类型／结果的比例、回退次数与上下文丢失率。若聚合误导因果归属或损害查单条记录效率，需调整联动粒度。[Shneiderman](https://hci.stanford.edu/courses/cs448b/papers/shneiderman96eyes.pdf)；[Endsley](https://doi.org/10.1518/001872095779049543)。
3. **正常首屏呈现“运行与观测范围 + 一件可解释的最近变化 + 深入入口”，会比泛化安全分数更能校准信任且不增加负担。** 设置无记录、观测中断、应用身份未知、真实零值四种样例；测用户能否分别说明“知道什么／不知道什么”，并记录把未知误读为安全的比例、一瞥任务耗时与主观负担。若用户读不出正常状态或误判增加，假设失败。[NIST IR 8330](https://nvlpubs.nist.gov/nistpubs/ir/2020/NIST.IR.8330.pdf)；[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)。
4. **通知只围绕可核实的状态故障、用户规则未按预期生效、或用户明确关注对象的变化，比定时报告所有流量尖峰更可能被理解且少打扰。** 在多日使用中比较：正确理解通知理由、采取有效动作、漏掉预设重要事件、误扰与关闭通知的比例；允许高级用户自行订阅更细事件。只要某事件仅是量变，没有足够证据便不贴“风险”标签。若漏报上升或理解不佳，触发条件与解释都需重设。[Sunshine 等](https://www.usenix.org/legacy/event/sec09/tech/full_papers/sec09_browser.pdf)；[Almuhimedi 等](https://www.cs.cmu.edu/~halmuhim/MobileAppPrivacyNudging_CHI2015.pdf)。
5. **具体活动旁的控制若先显示对象、范围与可能副作用，并在原处展示保存／生效／后续记录与撤销入口，会比只有允许／阻止按钮更支持谨慎行动。** 任务包含阻断后应用功能受损、设置已保存但未生效、规则优先级影响实际结果；测用户能否事前预测作用范围、事后找到真实原因和恢复方法，以及错误扩大阻断的比例。若操作时间明显增长却没有降低范围误解，收敛文案和层次。[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)；[Shneiderman](https://hci.stanford.edu/courses/cs448b/papers/shneiderman96eyes.pdf)。
6. **总览、地图、按应用／去向／时间筛选、完整规则与历史相互通达，会同时服务无目标探索和有目标的高级追查。** 分别让用户查一段未知变化、跨应用共同去向及一条规则为何生效；测任务完成率、路径长度、能否恢复原筛选、探索后对事实与未知的辨认，以及有经验用户是否觉得能继续深挖。若高级任务只能离开原上下文重新查找，或新手被默认密度压倒，说明层次失败；不能据此删除深层能力。[Park 等](https://www.usenix.org/system/files/soups2023-park.pdf)；[Shneiderman](https://hci.stanford.edu/courses/cs448b/papers/shneiderman96eyes.pdf)。

这组证据最强地支持的不是某个固定页面，而是一个需要实测的连续路径：**发现可观察的变化 → 定位应用／去向与时间 → 辨明记录类型和实际结果 → 在明确范围内决定 → 回原处核对与调整**。对于已知应用，入口可以从中段开始；对于未知原因，必须留有整体入口。任何一步的事实缺失都应诚实呈现，而不以确定语气填补。[Aretha](https://www.cs.ox.ac.uk/files/11850/Aretha.pdf)；[Endsley](https://doi.org/10.1518/001872095779049543)；[Shneiderman](https://hci.stanford.edu/courses/cs448b/papers/shneiderman96eyes.pdf)。
