## 哲学推论和实际合同分别约束什么

沿用已读的[Macintosh访谈](https://book.stevejobsarchive.com/#on-the-macintosh)与[商店导览](https://book.stevejobsarchive.com/#speech-apple-store-2001)：熟悉对象释放表达、不同用途有可发现的位置。本席据此主张明确任务、情境控制、连续输入与事实；没有由 Jobs 本人规定三入口，也没有用名称简短代替完整能力。
已核读[统一规格§10/§12及debug边界](../product/UNIFIED_RULE_ENGINE_SPEC.md)、[T28](../interfaces/T28_DASHBOARD_QUERY.md)、[功能盘点G/H11](2026-09-29_UI_FUNCTIONAL_INVENTORY.md)、当前VPP API、observation/ABI headers、RuntimeProfile/RuntimeControlProtocol、ReleaseDiagnosticsExport。

| 实际语义 / 现有接口 | 目标 Debug 不能偷换的含义 |
| --- | --- |
| Root/VPN是互斥捕获/运行profile | 启动Debug不自动切profile；切profile或运行代际改变须准确说明会话连续性，不能旧范围偷偷接新实例。 |
| 显式binding enforce/observe决定规则的有效动作；observe命中实际ALLOW | Debug是额外证据深度，不改所有规则为observe，不以关闭阻止换取“采集成功”。 |
| T28/Flow/SNI/normal健康查询已有权威状态和当前事实 | 可查配置/运行/通道、当前端点/归因/协议可用性。多页Flow查询是动态样本，不是冻结全量；缺节或错误不冒充空成功。 |
| 当前normal记录无payload/完整源条件；4个normal通道及其loss/capacity可查 | 不把既有四通道说成完整Debug payload；额外判断/阶段trace、会话控制、证据导出仍需对应目标契约。 |
| normal与未来debug有独立有界通道/丢失统计；单会话、真实证据是已定边界 | 不以额外生产器未接为理由删任务；也不将普通记录筛选或debug-only故障注入改名成完整用户模式。 |
| 当前诊断导出有runtime及所选应用信息、不含payload/keys，部分旧投影 | 这是材料，不是完整新Debug出口；UID/包名仍存在。目标导出须预览实际包含的证据与缺失，不宣称匿名或完整抓包。 |

规格§12要求权威typed查询，不靠抓日志拼真相；fault hooks是开发控制输入，不是可提供证据清单。用户Debug模式可以由后端提供，但start/scope/capability/status/stop/export、逐事件版本及额外证据深度必须真实有契约。本报告设计它们的完整目标，未声称现接口全齐。

## 健康主动任务：明确开始、证据与结束

| 步骤 | 固定构图、动作与结果 |
| --- | --- |
| 1. 找到任务 | 深入检查第一层固定Debug；网络的应用/所选事实也直接到同一设置，不要求已有故障或记录。正在运行会话在所有工作区有持续状态与一动作回到/结束。 |
| 2. 定范围 | 身份/目标范围→本次可提供的判断/阶段证据类型→时限/容量。实际UID与程序名线索分开；选具体连接带generation/owner/slot/incarnation，不把复用槽当原连接。 |
| 3. 开始 | 明确开始额外证据会话，不自动发送测试流量或改变规则。已有会话主动作继续；“结束这次，再新开”明确第二步，不并发叠预算或默换范围。 |
| 4. 看真实过程 | 固定会话ID/范围/进行中及覆盖，主体是实际输入、判定和已取得阶段事实；每条附当时实际使用配置/规则版本、声明及实际动作。缺失、解析停止、丢失各给真实状态，不凑一条完整故事。 |
| 5. 读而不中断 | “暂停跟随”仅停滚动，采集继续、新证据提示可见；它不是后台暂停普通消费。若另做暂停采集，须定义缺口/计时/恢复，不能借现开发pause hook直接许诺。 |
| 6. 中途编写 | 可从事实进入编写50条/批量加入/改条件顺序/分配/候选预演/完整提交；Debug继续。候选预计只属明确候选，真实证据只属实际snapshot，不共用大绿色结论或单版本标题。 |
| 7. 结束与导出 | “结束深入检查”只止额外证据，普通控制与记录继续；保存已取得证据及缺口/结束原因。预览实际导出内容、选择导出；结束不保证补齐落失数据，回复不确定先查会话状态。 |
| 8. 完成与返回 | 完成回启动来源的问题、原应用/目标/时段/选择/位置；再回编写保留dirty输入与基线。会话未来范围不覆盖原五分钟调查；导出不是自动发送给别人。 |

本次结束后保留的会话证据仍有容量与保留边界，不能借导出需求偷造无限历史库；具体保留合同另行明确。普通未来窗口仍是日常持续记录的范围选择，不造Debug开始/报告；Debug则有可理解的额外证据目的和独立会话生命周期。能力不足时明确哪些证据本次无法取得，保留任务与所需契约；已有即时事实可查看，但不能谎称额外采集已启动。

## 与集中编写共存：一条压力链，不拼三条孤路

健康D1 → 从真实事实建立/导入50条 → 连续条件/顺序及批量使用 → 候选预演 → 全配置提交 → D1真实旧/新使用版证据 → 结束D1 → 原调查/原编写输入。批量工作有持续工作集合、完整错误定位、使用影响与整套审阅，不循环单条然后笼统成功。

候选/已保存v43编译失败而实际仍v42，两者同时准确显示；修复发布v44是可说明的边界，保存不是。发布后晚到42记录仍按自身42归类，不能拿横幅44补旧行。当时完整条件不可取得就标在该42证据旁，仍保已知winner/版本/实际结果并导出；“查看现在定义44”是不同对象的次动作。

不偷加永久旧条件库。若目标Debug能取得有界会话内源快照，明确本次取得的版本/范围/容量；没有就保持缺失。原始发生、接收/展示顺序不混同；时点未知不从到达顺序推断。js UID1000实际范围也不因天气名线索缩成独立天气控制。

整套导入/名单采用改变保存基线时，保留正在写的输入并明确基线过期、重新核对；不存在隐形merge API，也不沿独立路线静默覆盖。DEBUG控制、候选配置和普通观察共用问题上下文，但各自有作用范围、版本与来源。
