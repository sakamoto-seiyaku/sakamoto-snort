## 共同工作一：零规则，浏览器移动网络不访问 L

已有自维护名单 L，用户明确只要这一项控制；强 C 在空起点直接允许独立创建这一条，没有先建 G 或命名用途，不能把用途优先解释成首条必绕组。
他选阻止 L 中的名称，网络条件选移动，使用对象选浏览器；读回“浏览器在移动网络阻止 L”，保存并使用，不把已有名单当成已经控制联网。
从这条内容核对浏览器本次移动活动中的真实域名与结果，无记录则尚未核对；完成回 R，资料 L 保持自维护来源，不补一个虚构用途包。
同任务的 A 是空内容→新建 R→选择上述内容与对象→采用→核对；B 是新建当前 R→完整表达移动／L／阻止／浏览器→采用→核对，二者也无需组。
C 在这里没有整套用途收益，A／B／C 可以同样短；三者都须理解“L 提供名称，R 决定处理”，不能把这项真实知识成本单算给 B 或替 C 虚构一次组织判断。

## 共同工作二：跨两组的复杂 R 只改一个条件分支

统一固定 R 为阻止“移动命中 L，或 Wi-Fi UDP443”，两支都排除 E；只有规则组 G 办公（浏览器／邮件）和 H 影音（视频／播客）采用，没有额外直接用户。
C 若记得目的就从 G 找 R，明确知道 R 则独立检索直达；完整读两支／E，只把 Wi-Fi 端口 443 替换为 8443，移动支、例外和动作不变，不扩为两个端口。
此刻明示 R 的实际作用对象：浏览器／邮件／视频／播客，及确实存在的作用 AppGroups；不把规则组 G／H 自动作应用组，更不从 G 起点缩成只改办公。
从 R 选择受影响对象核对新活动，然后回当前 R 继续共同工作；若本次 R 是活跃 G 内子任务，回 G 的 R 位置继续，单条任务则没有 G 的强制中转。
A 直接定位保存的 R 再进入完整编辑；B 定位当前 R 后直接保持两支／E 的完整表达并修改、核对。C 的目的组织在这项全局分支工作上帮助有限，专业作者重心已经转向 B 的强处。
必要知识是完整条件和例外的意义、此次只改哪支及谁受影响；C 没有消除它，还须防止父组造成窄范围的错觉。R 内容更新不是两组组成更新。

## 共同工作三：半年再找，随后从零做新 G

小林只记“办公的名单限制”和“未用的网络例外”；C 按办公到共用 G，读当前名单规则与资料来源，再按实际内容进入维护，目的名帮助定位但不代读条件。
待用复杂 Q 未入任何组：他用独立内容检索的网络／例外／未使用线索找 Q，完整重读条件及相关资料，决定继续待用或采用；不为找回先给它造一个组。
专属移动／Wi-Fi／有线／VPN 快控也按其真实行为找到，仍用直接修改动作；C 的整套首组织不能把它们藏掉，也不能虚构一份新规则补检索。
随后明确准备新“远程办公”G，C 直接从整套开始：在 G 补 Wi-Fi／UDP443／阻止的 R，以及移动时阻止 N 中名称的 D；D 需要 N 就在该任务内输入／导入域名，完成回 D／G。
读整套当前内容后保存待用，或选办公 AppGroup 明确采用，再按本次实际活动核对；共同深度修改从真正 R／N 继续，结束整套才回本次目的查询。

C 对目的找回和新整套创作最强，匿名 Q 与快控则需全局内容定位；A 首先承认混合内容的当前身份，B 首先承认作者表达，这是认识优先级，不能凭旁路名称推定额外知识或步骤。
