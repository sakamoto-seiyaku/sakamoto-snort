# 访问意图、默认能力与完整使用：整体席续辩

2026-10-01；整体席。只新增本报告，不改原型、生产代码、tracker或设备。读当前主线、产品愿景、统一规则§2–4/Out of Scope、方法复查、WHOLE_RETHINK、V3_WHOLE_REVIEW和TMP顶部；先独立方案，再真实对质，末端映射30项。以下是目标产品选择，不是接口、实现或验收完成。

**保留设备时间变化→同段贡献应用→应用目标/实际活动；访问意图先于查询/连接分类，但完整规则仍拥有精确含义。** 推荐初始化与预设可以让普通人几步获得帮助；同一个人以后进入完整条件、共享资料和健康Debug，仍在同一产品、同一对象上完成工作。

## 两段跨任务故事

**第一次：我想减少天气里的广告，又不影响找设备。** 首次打开先选“推荐方式”，看它能观察/控制的真实身份与主要范围，按要求授权；能力较少也能继续用已支持的观察和基本控制，不承诺每台设备等价。选择“限制广告跟踪名单中的名称”，核对来源、用途及不含页面元素隐藏的实际帮助，开始使用；“限制设备发现”另列mDNS/SSDP范围及投屏/查找代价，不自动捆绑。日常首页仍看时间图和同段天气贡献，点天气看到已知目标、真实IP地图、协议和实际结果；有证据才把查询与连接关联。点metrics.example表达以后怎样处理，精确名称/子域、真实身份和网络范围贴在动作旁，方式由可用能力支持的完整含义决定。若投屏受阻，回同一应用查看本次复试的受限发现请求，给此应用在当前网络的SSDP例外；多播请求不能假装只允许某台接收机。核对更早限制、保存/开始使用，再复试看发现请求及后续连接各自结果；旧阻止不改绿，无新事实仍待核对。返回保持原时段、对象及位置，其他应用和共同名单不被这次例外修改。

**后来：同一人要维护50条规则，换能力方式，并弄清为什么例外没有赢。** 直接打开“我的联网规则”，已有内容先可读，不重走初次向导；导入是完整替换，dirty时明确保留输入或替换。选原天气内容连续编辑AND/OR/NOT、CT、协议、网络、地址/端口、Rank及使用关系；共同广告资料自动采用D13时，保持50条输入与原问题，在相关引用核对D12→D13、补充/排除和全部消费者，再明确更新本次依据。用户主动换能力profile，核对它对既有完整条件的具体影响；推荐不能重写细条件，撤Root不能靠旧active假装仍运行。不可满足项可切回可用方式、申请真实缺权限或明确改这项限制；未确认与已知不执行分别呈现。健康时从这项内容“从现在记录实际怎样判断”，不用先造候选；实际记录只取正在使用的来源，预演只解释本次输入。一次提交完整候选，保存但未使用即收口已持久化工作并给重试；例外若仍输更早规则，沿赢家及全部来源回原项修正，而不私自提高优先级。新旧实际行各保版本，结束额外记录后普通活动继续；完成回已保存的原天气项/原目标，而不是复活旧输入。

## 关系与正向选择

| 关系 | 具体责任与本轮选择 |
| --- | --- |
| scope | 真实控制身份、名称/子域或地址、网络、条件及影响消费者构成范围；已知应用名不是独立控制身份的证明。共享UID变化一起核对。 |
| intent | 面向人的输入与可读摘要；不新增持久intent实体。复杂表达无法可靠总结时保命名题目与完整定义，不能继续称“全部禁止”。 |
| profile | 能力选择/权限及可用事实的组合，不能修改rule意义或Rank。首次推荐、主动更换、确知影响现有限制时呈现；正常地图/活动不被能力目录占据。 |
| preset | 选用已有规则/组/资料/用途的一次具名安装与维护动作，不先增第二规则库或新持久层。安装后同一源能完整读改。更新身份/来源如何写入现有权威合同仍待定义。 |
| source | 唯一权威的完整规则、引用与使用关系；资料更新和预设内容变更给实质差异，局部例外不自动升级，也不自动改所有消费者。 |
| compiled | VPP对同一源的保守有界计划，不拥有新的用户含义。完整Rank/有效方式/实际动作保持不变；无法编译不得截断发布。 |
| evidence | 当时事实、赢家/方式、版本及可得依据；当前源、候选预计和实际后果分别表达，历史资料缺失就保缺失。ALLOW不证明传输成功。 |

默认选择**以可验证能力完成尽量多的日常工作**：真实身份的基本联网控制、限定名称的广告/跟踪资料、确切发现协议限制，以及流量/目标/协议/地图理解。不是先让人选DNS/SNI，也不是让“禁止访问”覆盖所有无法判断的行为。
未来允许自动组合能证明不扩大声明范围的方式，包括关联用于观察；域名意图不能自动变为共享IP封禁。DNS对整名拒绝无法表达domain AND port443，就不把该完整规则放成DNS拒绝。SNI也不是一条连接上所有HTTP目标的证明。具体DNS/关联的目标合同仍需补充；UNIFIED现版default-off是现accepted边界，不能替未来默认裁决。
正常限制给准确对象/范围及持续可达的依据；仅在确知能力变化影响该项时就地显示“覆盖改变/目前不执行”，未知显示“无法确认”。全无可执行部分不能藏在全局健康页。地图表达实际IP地理与范围，未入图/私网/未知保留，不推安全结论。
预设安装主位读“将使用这组规则／哪些现有安排保持”，核对已有手写规则及推荐位置，明确“已有更早限制仍优先”，完整顺序可展开；更新审阅列名称、条件/范围、用途、资料与本地例外的实质变化。同源enforce/observe冲突必须定位，不用“预设优先”绕过。卸除一处用途与删除共同资产分开；停止订阅不取消现有匹配。

## 真实对质、改判与最强反案

设计席强问：撤Root且细条件/共享资料已变化，393上怎样保持同一输入而不自动弱化？答复接受完整源/Rank权威，首屏“运行范围改变／受影响限制”，原题进入逐项能力影响；切回方式或明确修改，保存/使用分开，无法确认不写已失效。接受；不能用旧snapshot掩盖平台前提已消失。
设计席反问：无扫描行为判断时是否收窄预设？例外输完整Rank怎样完成？本席选择确切发现协议预设；例外核对沿同应用完整有效顺序显示“已保存，但X仍优先阻止”，可明确改顺序或解除一处，残留来源可见，提交后回同对象实际核对；更新不偷偷抬例外优先级。
设计席同题跟进：更新把天气新目标加入后是否等待新DROP？接受静态/动态分界：源可证明相同条件的更早赢家，当前限制立即显示“此允许不会胜出，X优先”，标当前规则判断；动态事实不足仅“可能仍受其他限制”。部分重叠仅标该部分，不能扩为整项已拦；实际结果仍须新证据。
反案席强问：只有LAN事实时“禁止扫描”怎样形成正向产品？答复选择“限制设备发现（mDNS/SSDP）”，无该证据时另供“不联系局域网”并说明投屏/打印代价。完整跑通发现请求→本应用SSDP例外→复试→预设更新不扩大例外。**实际改判：撤我初案中仍过宽的“限制局域网探索”，采纳此名称与闭环。**
反案席反问能力profile会否绑架全产品，本席用地图正常使用反证常驻coverage行；对方实际撤每行固定“识别到名称才执行”，改为准确摘要、启用核对可回及确知失配才就地提示。本席接受其保留条件：已知完全不能执行必须当项显露。
平台席提供原始资料反证：KernelSU只是root/module基座，不提供未指定module的DNS语义；resolver知道caller UID不等于出站包保原UID，VPN归属可失败；同TLS/QUIC连接可承载多个authority。故自动组合不能自动扩大到共享IP/身份。本席曾把现版DNSIP default-off当未来限制，经质询撤回：未来默认可重审，范围等价与合同必须先成立。
最强反案仍是**面向结果的访问对象独立模型**：可让意图在方式切换时更稳定、简化预设维护。但引入第二权威与跨机制翻译会让完整条件及历史依据漂移；本轮选择现有源上可读输入，不先建设新模型。代价是某些意图只能得到明确限定的执行部分或需要一次核对，不能许诺所有方式等价。

平台事实由研究席实际读取并提供，本席不声称新读原文：[Android resolver](https://android.googlesource.com/platform/packages/modules/DnsResolver/+/refs/tags/android-16.0.0_r1/DnsProxyListener.cpp)、[HTTP/2连接复用](https://www.rfc-editor.org/rfc/rfc9113.html#section-9.1.1)、[HTTP/3连接复用](https://www.rfc-editor.org/rfc/rfc9114.html#section-3.3)。具体授权/module选型以及更高性能/省电尚待证，不纳入本轮完成事实。
