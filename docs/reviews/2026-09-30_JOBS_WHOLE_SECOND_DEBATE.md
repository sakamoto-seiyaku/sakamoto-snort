# 第二轮：名单作为物件，任务作为边界

2026-09-30，C 组整体研究席。结论是当前的设计偏好，尚未实施。

**我选择让日常名单成为清楚的匹配资料物件，手机更新另设审阅屏。** 共用资产需要完整关系，不需要所有字段同页并陈；精确应由名称旁的范围、用途的动词、版本的对应和动作边界承担。

## 现在选择的日常形态

1. **固定身份。** 名单名称、当前资料版本及出处短签同在顶部。未分配的名单显示“尚未使用”，内容仍成立；不把它称为“当前阻止范围”。
2. **关系先定性。** d1 紧接两行：连接 · Firefox/Signal · 命中后阻止；查询 · 天气 · 命中后阻止。它们表达规则使用方式，不给名单添加执行动作。观察方式须明确表达实际仅观察。
3. **内容迅速成为正文。** 精确名称、是否含子域、来源条目、本地补充和排除贴着相应内容表达；不把决定范围塞进末尾小字。完整条目可查，不缩成只有数量。
4. **来源与使用关系真正深入。** 检查频率、暂停、停止、自动采用进入来源管理；完整规则、分配、顺序和创建规则进入“使用此名单”。这两个子任务各自有开始、提交、取消和返回。

“共用资产”要求看见它匹配什么、从哪里来、被怎样使用，并能沿关系核对；并不要求日常页同时编辑全部来源参数和规则条件树。完整性跨任务成立，页面只承担明确意图。

## 大动作必须赚到位置

| 动作 | 位置与存在理由 |
| --- | --- |
| 修改本列表内容 | 内容区的明确入口；进入本地补充/排除编辑，是改变匹配资料的提交任务。 |
| 立即检查 | 来源管理的维护动作；日常保留检查状态，默认不放大蓝按钮。 |
| 审阅新版本 | 有候选时的显著入口；进入尚未采用的决定任务，不能与再次检查混成主动作。 |
| 暂停检查 / 停止订阅 | 来源管理；各自表达对未来检查、来源关系和保留资料的后果，不称通用“关闭”。 |
| 用于规则 / 创建规则 | 使用页；把资料接到规则的通道、动作及对象，避免创建资料即默认启用阻止。 |
| 删除名单 | 对象更多操作；先处理引用关系，不与日常查内容、创建规则并列为大按钮。 |

## 独立审阅的收益与代价

手机审阅围绕一个决定：是否采用这份候选。固定名单身份，以明确对应的当前/候选版本和精确增删范围组织正文；本地补充/排除的保留或冲突，以及消费者的通道、实际模式、对象共同成为决定依据。资料差异不冒充全部规则效果。

来源地址可以就地核对，完整消费者条件可以深入；无需把检查频率、完整条件树和删除资料也带进审阅。消费者核对后返回恢复候选身份、位置、展开项及未提交状态；候选或用途变化时重新核对，不能沿用过期依据提交。

我愿付日常来源/完整用途多一次深入、审阅导航与状态维护的成本，换取资料正文和采用决定各自有清楚形状。大屏可把差异与用途并排；不为跨端一致强迫相同排布。

若一个功能只有通过长免责声明才说得清，先检查它是否放错任务、动词是否误导、输入范围是否不匹配。保留高级能力不等于保留杂糅位置；聚焦也不能删掉观察、控制或验证来掩盖缺项。
