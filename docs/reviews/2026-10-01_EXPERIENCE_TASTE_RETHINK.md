## 正向选择与 393 第一眼

同一个人打开产品，是要认出这一段设备做了什么，或决定以后怎样联网。先看到设备及熟悉应用；具体事实带出改变，长期维护面对可读的“联网规则”，Debug 面对从现在开始的一次实际过程。
**设备首屏：**“我的网络／最近30分钟／真实覆盖”→同刻度收发时间图→独立查询线索→同段贡献应用。关系保持既定；设备对象的可见动作给“联网规则”“从现在记录实际判断”，不先要求选择深浅角色。
**应用首屏：**固定身份/范围→当前安排短句→所选类型的主事实→实际记录；类型是明确选择，来路不重排画布。旧事实、新决定与实际后续各有自己的时态。
**长期规则物件的可见原词：**
> 联网规则
> 正在使用 v42 ｜ 已保存 v43·尚未开始使用
> 查看这台设备当前怎样判断 ›
> 已保存规则50条·8条尚未分配　添加／导入
> 本次修改3项·未提交　继续修改 ›
“联网规则”是持续可读对象；当前使用入口看真实有效关系，已保存集合明确自己的版本。一次未提交输入只是其“本次修改”；不存在时才给“添加第一条规则／导入现有规则”。未分配不等于失效，也不冒充正在判断。

## 情境一：天气的一次查询为什么被阻止，改变以后

1. 同段贡献点天气；原应用画布保持范围。选择查询，点实际被阻止的 `metrics.example.net`，面对的是天气这一次查询，而非一个规则模块。
2. “查看当时依据”给已存的赢家、声明/实际方式、使用版本与资料；缺失就标不可取得，不能新开 Debug 补采过去。主动作“改变以后的此名称查询”自然接在事实后。
3. 决定面保持天气、查询通道、精确名称/子域选择；局部允许只改变天气以后，不偷偷修改共享列表或升顺序。最高快捷 DROP 等约束需在此核对，保存不保证恢复。
4. 如需核对“跟踪域名”，393 真换标题为该共同物件，先显示连接供 Firefox/Signal、查询供天气，再精确条目；小来路“回天气这次决定”保输入。1440 可局部事实/输入左，共同物件/全部用途右。
5. 完成查看回同一局部输入；真改共同内容先完成共同影响，再回天气核对过期。局部提交给本次保存/开始使用结果，后续只看真实新查询；完成回原查询或应用范围，旧阻止事实不粘新的允许卡。

## 情境二：无事件，从零 50 条、共享资料到健康实际证据

1. 空设备仍能打开“联网规则”；首屏是现有使用/保存状态和可读集合，不像首次设置向导。没有规则才添加第一条或导入，已有内容直接继续查看与修改。
2. 添加规则先表达遇到哪些活动、哪些条件成立、想怎样处理及供谁使用；完整树、优先级/顺序在同一对象深入。暂不分配的 SSH 规则能保存备用；不因设备是来路就声称影响此设备。
3. 50 条导入同一本次修改，集合/引用/所选项持续可读；共享规则、组与域名列表是真物件，从关系直接打开。组复用不赋胜出，定义修改不覆盖 Firefox observe/Signal enforce。
4. “从现在记录实际判断（Debug）”在健康设备可启动，明确真实 UID/目标、起始时刻、额外证据及边界。已有旧依据与未来采集分形态；此会话不改变 Root/VPN、使用模式或普通记录。
5. 继续规则集合：候选预演只解释本次输入。393 主位仍是规则/本次修改，实际会话短条可继续；1440 候选预计与实际证据分列，标题、范围和版本独立，不共用绿色成功。
6. 一次完整提交。假定保存43但使用仍42，实际会话按42；发布44后各记录依实际取得快照标版，迟到42不重标。未分配内容仍未分配，保存备用、发布配置与访问成功是不同结果。
7. 完成回原规则集合/所选项；取消未提交修改也回它。停止 Debug 只止额外通道，普通记录继续，证据回启动问题。dirty 遇完整导入先处理替换/取消；名单采用改变基线则保输入、重核引用/预演与影响。

## 工艺反证、实际答辩与成本

旧三目的的强反证：“网络”是对象，“编写”是动作，“深入”是深度；分类可讲清，尚未让健康采集→批量修改→发布→核对自然完成。本轮不拿它生成 UI，也不因此自动裁一或二入口。
代价是设备动作占空间、规则的当前/保存/本次修改须可辨、共同物件要一次明确扩大范围再返回；这些成本换取动作兑现。坚持已成立的首页/应用内部关系，不迎合全推翻。
本席不接受共享修改默默纳入天气例外、不接受用“准备/内容”掩掉长期领域物件，也不接受新 Debug 回填旧依据；领域名可清楚，后台类别仍不决定整套布局。
真实交流：C 接受实例不是第一眼物件，反问局部→共同如何显范围；本席选共同画布及全体用途，C 明确采纳。设计席接受三目的不应作生成前提，反问未使用 SSH 的设备来路；本席改持续“联网规则”，其补充 root 精度也要求相同物件/编辑区分。一轮各一问一答，未伪造共识。
root 的长期维护反证使本席撤永久“本次准备”；已真实转给 C/设计席。新方法席收到本席形式质疑：连续问题不意味着对象永不切换，固定动作也不能混过去依据与未来采集；未把该方法当人物权威。
