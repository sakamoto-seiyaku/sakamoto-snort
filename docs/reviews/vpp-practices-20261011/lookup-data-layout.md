# VPP 查表流水线与数据布局审查

2026-10-11；产品基线 `54f2566f26cbbd2ae2cdfd3a1796e4e0f19041e6`，VPP pin `9258530f3804a152578ce11cc7c8a1e9eab88ed0`。仅静态审查，未改产品、运行设备、测试或基准。对照 `build-output/pinned-vpp-clean` 的 Git 原始文件；ACL node、session 布局、bihash、buffer API 相对该 pin 的 diff 为空。此报告不使用已移除的 C++ 或 POC 实现作参考。

**已使用的机制。** 主线具备 native vector nodes、一次共享解析、一次 canonical assignment、56-byte inline packet overlay、worker 私有 FlowRuntime 与 policy cache，以及启动时预分配的槽、bucket、timer。metadata 恢复只按保存的 projection 取地址、端口和 typed key，没有再次解析、canonicalize、hash 或选择 owner；不能将这些描述成缺失。[overlay 与恢复](../../../src/product/vpp/product_packet_graph.c#L84)、[固定容量分配](../../../src/product/vpp/product_flow_entry.c#L386)、[worker cache](../../../src/product/vpp/product_packet_graph.c#L241)。规则单 key 已有编译器 NEON 证据；源码没有显式 intrinsics 不意味着二进制没有 SIMD，本次机会是组织独立查询。[已有证据](../../testing/2026-10-11_PIXEL6A_INCREMENTAL_BATCH.md#L296)

**上游对照。** FD.io 官方文档明确建议在一个 vector 内提前计算查表输入，再依次预取 bucket、data page，最后用已计算的 hash 查找。[官方 bihash 文档](https://docs.fd.io/vpp/25.10/developer/corearchitecture/bihash.html#bihash-vector-processing)。固定 pin 的 ACL 先 `vlib_get_buffers`，在 worker 工作区准备 tuple/hash，再流水预取 bucket、索引数据和 session，复杂更新仍按包执行。[准备](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/plugins/acl/dataplane_node.c#L243)、[查找流水线](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/plugins/acl/dataplane_node.c#L352)。这说明批处理不以跨包 SIMD 状态机为前提，也不要求照搬 ACL 生命周期或全局 session hash。

1. **缺失：整帧准备与分层查表预取。** `admit`、`policy` 目前逐项取 buffer，随后完成该包全部准备、规则查询和状态更新；`product_packet_graph.c` 没有 `vlib_get_buffers` 或显式 prefetch 调用。Flow 和 matcher 的接口也都接受单 assignment/packet。[admit](../../../src/product/vpp/product_packet_graph.c#L1254)、[policy](../../../src/product/vpp/product_packet_graph.c#L1596)、[matcher](../../../src/product/vpp/product_l4_policy.c#L901)。可在 graph 增加有界 worker 工作区，先整帧取得 buffer pointers、投影静态输入并复用保存的 canonical hash；FlowRuntime 自己提供 bucket/index/state 的准备与预取，保持 table/pool opaque。规则模块可复用 PRE/POST 的静态 projection，但 UID subject/mask 等 snapshot 相关准备必须留在该包受保护的 bank 生命周期内；POST 仍在该包 tracker/LPI 更新后补入动态事实。先预取、顺序查找即可，不必提前固化命中结果。固定 VPP 的 bulk API 可供这种工作区使用。[buffer API](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/vlib/buffer_funcs.h#L185)

2. **未充分使用：紧凑查表索引与冷热分离。** 当前 `flow_slot_t` 把 `next` 放在完整 entry 后面；查找沿 bucket 链跳到各槽，比较前部 hash/key，再取远端的 `next`。每个 entry 都保留 TCP/QUIC union，其中 TCP byte cache 的 `bytes[2][4096]` 单纯字节数组已为 `2 × 4096 = 8192` bytes；这是源码数组下界，不是猜测 `sizeof(entry)`。不是每次 lookup 都读取全部缓存，但索引的步长与链节点布局由大对象决定。[链布局](../../../src/product/vpp/product_flow_entry.c#L8)、[查找](../../../src/product/vpp/product_flow_entry.c#L71)、[entry](../../../src/product/vpp/product_flow_entry.h#L100)、[缓存](../../../src/product/vpp/product_sni.h#L21)。优先在 FlowRuntime 内抽离启动预分配的紧凑 `hash/key/next/slot` 索引，命中后才取协议状态，原 entry 与 FlowEnd 槽位可先保持。上游 ACL 将 session 固定为 128 bytes，并把整帧临时 tuple/hash 独立放在 worker 工作区，支持这个布局方向。[session 与工作区](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/plugins/acl/fa_node.h#L105)。bihash 可以作为索引候选，但其 bucket 分裂和 backing-page 分配不能自动满足本产品运行期冻结容量；无需为了采用名字而替换现有固定索引。[官方分裂说明](https://docs.fd.io/vpp/25.10/developer/corearchitecture/bihash.html#discussion-of-the-algorithm)

3. **未充分使用：同包 Flow 查询结果复用。** 在 product VPN mode，包为 `VPN_TUN/OUTPUT`、完整 TCP/UDP typed assignment、已有未到期流、UID known、未发生冲突/替换、策略允许观察流、Flow Stack driver enabled 时，一条路径可到达六次同 tuple 的 key-table 查询：① resolver lookup 内 current，② graph current，③ enrich 内 find，④ observe 内 find，⑤ refresh 内 current 校验，⑥ egress current；不是每个包固定六次。[①](../../../src/product/vpp/product_vpn_uid_resolver.c#L229)、[②③调用](../../../src/product/vpp/product_packet_graph.c#L1673)、[③查找](../../../src/product/vpp/product_flow_entry.c#L109)、[④](../../../src/product/vpp/product_flow_entry.c#L494)、[⑤](../../../src/product/vpp/product_vpn_uid_resolver.c#L260)、[⑥](../../../src/product/vpp/product_packet_graph.c#L1809)。可先把同一同步 policy 调用中的查询与 enrichment 合成 FlowRuntime 操作，返回带 owner/generation/slot/incarnation 的短寿命 typed 结果，让 resolver 的重复确认走受检槽位访问。跨 node 延用须重新验证 linked、逻辑 deadline 与 incarnation；不能传裸 entry 指针，也不能让 UID 冲突关闭、TCP 替换或提前 DROP 使用旧结果创建新流。此项应与第一项共用查询准备接口，而非另建 tuple side table。

4. **未充分使用：按 stage 投影 metadata。** 普通 Root 路径在 policy、consumer、terminal 各重建完整 lease；VPN TUN 路径再加 egress。恢复函数每次归零完整对象、复制地址并重建 key；consumer 主要只需 provenance、intent 和 END 分支。恢复函数本身已取 platform facts，policy/consumer 随后又取一次。[恢复](../../../src/product/vpp/product_packet_graph.c#L782)、[policy](../../../src/product/vpp/product_packet_graph.c#L1631)、[consumer](../../../src/product/vpp/product_packet_graph.c#L1762)、[terminal](../../../src/product/vpp/product_packet_graph.c#L1992)。可由 metadata 模块提供经过同等 span/generation 校验的 routing/terminal 小视图，完整 facts/key 留给实际需要的 policy/egress 与 trace。不得扩大 opaque、新增每包 heap 或跳过 invalid-envelope 检查；重组和 trace 仍要保留完整事实。这是 parse-once 的进一步利用，不是修复重复 parser。

5. **受约束：immutable bank 的读取成本仍逐包。** 当前 policy 调用每包 acquire/release 一个 bank，分别对共享 reader count 做 SC RMW；worker 私有 cache 已有，但并不取消 bank 生命周期保护。[claim](../../../src/product/vpp/product_packet_graph.c#L435)、[release](../../../src/product/vpp/product_packet_graph.c#L481)、[调用](../../../src/product/vpp/product_packet_graph.c#L3899)。本报告不建议直接改为一帧取得一次 snapshot：尚未建立这种 publication/reader lifetime 语义。第一项中的 snapshot 相关只读准备仍要保留该包 generation/revision/hash、mode 和 PRE/POST 身份。后续若考虑 worker 读取登记方案，须先证明 delayed claim、bank reuse、每包 Apply 可见性与 stop/drain，再讨论成本。共享 readers 是配置保护，不是共享 mutable flow state；Pixel NUMA 收益没有证据，不列为建议。

**不可跨越的提交边界。** 保留 frame 原顺序，前包建流必须立即对后包可见，前包结束/替换必须使后续 hint 失效；非相邻同流同样适用。CT、LPI、SNI 和策略 guard 只能使用该包更新后的事实，不能预填整帧 POST verdict。上游也特意修正前包删除/创建 session 后的下一包预测。[删除修正](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/plugins/acl/dataplane_node.c#L442)、[创建修正](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/plugins/acl/dataplane_node.c#L527)。产品还要保持先 unlink/timer removal、后 FlowEnd、native free 后归槽，逻辑 expiry 不等待物理回收，以及重组首片事实和唯一 assignment。[所有权契约](../../decisions/PER_WORKER_FLOW_OWNERSHIP.md)、[metadata 契约](../../decisions/VPP_PACKET_METADATA_OWNERSHIP.md)。不引入 zero-copy、flow migration、owner 重算或单独 hash 微优化。

**前三优先级：** ① FlowRuntime 紧凑索引与有界查询准备接口，② graph/规则/Flow 的整帧静态准备和分层预取、按原顺序提交，③ 合并同包重复 Flow 查询并复用受检结果。四、五可随后独立评估。此排序是模块依赖与可审查性判断，不是热点测量或速度预测；后续收益只能由独立包、多包同流、首次创建、替换/expiry、PRE DROP、动态事实变化等正确性验证及新测量决定。
