## 3. Primary 与 completion 的 bounded per-target window

拟议私有接口为 `product_primary_flush(vm,node,window,failed)` 和 `product_completion_flush(vm,node,window,failed)`：窗口只在当前 node 调用中存在，保存 `bi,target,owner` 与必要的按值 trace/terminal 投影，底层仍调已有 `vlib_buffer_enqueue_to_thread_retained(...,n,failed_bis)`。Primary 容量 `W <= min(VLIB_FRAME_SIZE,当前 handoff credit limit)`；completion 窗口受 frame/既有 admitted population 与执行 budget 约束，不另扣 primary credits。W 的具体值是后续实验选择，不在本报告冻结。此候选用短窗口小投影控制 stack 成本，避免整 frame 大 `PacketLease` 阵列；跨 node 保留 borrowed pointer 则仍违反既有 lifetime 约束。

Primary 在原顺序完成 assignment 后向对应 target 的窗口 append；逐包 reserve 先保留也能使用 bulk，随后才考虑 `reserve_up_to(owner,wanted)` 用一次 CAS 扣多个 **packet** credits。窗口满、credit 压力、frame 尾部及 stage/generation 边界都 flush；没有最小批量等待。特别是不能先保留全 frame 的 remote credits、处理到第 33 包才统一 publish：当前默认只有 32 credits，这会自行制造 bypass。遇到无 credit 且本 target 窗口非空时先发布已经保留的窗口，然后做一次有界的当前 admission 决定，不 spin 等 receiver、不借其他 owner 的余量。

当前 primary FQ 64 slots、completion FQ 128 slots，native ring-full 条件 `new_tail >= head + nelts` 使可用 elements 为 63/127；slots 是 carrier frame-elements，packet credits 与其不同量纲。一个 bulk element 可承载多个 packet，却不能把 32 credits 改为 32 frames，或因此提高 admission 上限。[产品 FQ 配置:4680](../../../src/product/vpp/product_packet_graph.c#L4680)、[官方 ring 条件:272](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/vlib/buffer_funcs.c#L272)

publication 前为每个 buffer 写 HANDOFF_CREDIT/完整 completion overlay，准备好所有后续 trace 所需值，提交生命周期债务；之后只处理 `failed_bis`。混合 targets 可部分成功，返回 `n_enqueued` 不是“前 n 个成功”：failed 输出按 target groups compact，必须用当前 scratch 的 `bi→原窗口位置/owner` 映射或失败 bitmap 找回原 records。只有失败 buffers 可以重新读写 metadata、清 credit flag、归还其 owner credits，并执行原 bypass；需要 lease 时由既有 `product_lease_from_metadata:782` 从保留的 overlay/span 恢复，不为全 frame 保留大 lease 数组或再解析/hash。成功项不 load、不 prefetch、不 free、不再拿 pointer。每个 target 的输入相对次序保持稳定；跨 target 不要求构造全局顺序。`primary_published/rejected` 可以按结果一次增计，trace 仍从保存的值逐项发出。

Terminal 的拟议步骤为“准备 completion → 计债 → local indexes 聚合 / remote target 窗口 → flush → failed 加现有 backlog”。32-byte completion 仍在同一 buffer 的 `opaque2`，不另做 return object；remote 成功后旧 packet metadata lifetime 已结束。重组 fanout 每个 original 仍独立 completion，只在当前同步发出阶段聚合，generation 与所有原始 identity 不折叠。[terminal transition:2112](../../../src/product/vpp/product_packet_graph.c#L2112)、[completion 布局](../../../src/product/vpp/product_packet_completion.h#L12)

## 4. Retry compact batch 与 origin 准备/回收

Retry 可增加 `product_completion_retry_window(vm,node,budget)`，继续使用同一 512-index storage 和本轮扫描预算 64：先取有界前缀、批量获得 pointers 并复制 completion headers；held 项保持拥有权；其余按 origin target stable compact，调用 retained bulk。成功项从 backlog 移除、`completion_pending_returns` 按成功 packet 数减计，失败项在原 storage 稳定保留：前缀先复制进 scratch，设成功 a、held h，将 failed survivors 写到 `old_head+a+h`，head 前进 a+h、count 暂减 a+h，未扫描尾部不搬动；再按原次序 append held，最终 count 只减 a。这样保留既有 held 轮转，不让故意 held 的 return 堵住 original-capture completion。一个 target 拒绝不 break 其他 target 的尝试；保留每个 target 在 candidate 窗口内的次序，每轮每 candidate 至多一次 publication attempt。现行新 completion 会先直接 try、并未保证先 drain 旧 backlog；不得把全局 FIFO 当成已实现事实，也不在批处理时顺手引入新的队列顺序契约。未取得进展的 backlog 仍走既有 1 ms deadline，而非持续自 interrupt 或依赖后来包救活。retry counter 保留 packet-attempt 口径，不能无声改为 helper-call 数。

Pointer scratch 必须审计 padding：官方 `vlib_get_buffers_with_offset:194–210` 在动态 count、编译已知输出对象至少 64 pointers 且对象大小为 8 pointers 字节组倍数时，按 `round_pow2(count,8)` 读 indexes/写 pointers；这是对象 size 条件，不是 pointer 地址对齐要求。因此输入 `bi[]` 与输出 `bufs[]` 都覆盖 rounded count，n>0 时尾部可 duplicate 第一个 valid bi，只 consume/prefetch 真实 n，padding 不新增 buffer 引用或 obligation；n=0 直接跳过。不能直接交一个未 padding 的紧凑 retry 切片。[官方 pointer 批转换](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/vlib/buffer_funcs.h#L186)

Origin 可封装 `product_origin_complete_window(vm,node,from,n)`：按短窗口准备 buffer pointers，向后预取实际 header 与 `opaque2`，复制 32-byte headers，随后按原次序做 fragment 检查、adapter identity validation 和 settlement。**header prefetch 只取前 64 bytes，而 `opaque2` 在第二 cache line**；completion 路径须显式 `CLIB_PREFETCH(b->opaque2,...,LOAD)`。不预取用不到的 payload；只有待执行 TUN write 的有效 return 才准备 current-data span。END 没有 AdapterObligation，保留原专用路径；不能把新 metadata prepare 函数用于 END。[官方 buffer 布局:162](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/vlib/buffer.h#L162)、[header prefetch:215](https://github.com/FDio/vpp/blob/9258530f3804a152578ce11cc7c8a1e9eab88ed0/src/vlib/buffer.h#L215)

Root `product_root_nfqueue_complete_from_graph:895` 在 `:916–947` 校验 generation、lane、origin worker、pending token/carrier、replay 和 intent；`:949–953` 先消费 identity，`:960` 计 attempt，再 `:981` 一次 send。它最后 `:992` 归还 lane-local receive slot，即使 verdict 失败也 `return 1`。这个 bool 是“buffer 已回池”，绝非 verdict `SUCCEEDED`。拟议 Root seam 可为 `product_root_complete_batch(vm,bis,headers,n,returned_mask)`，内部封装 prepare/consume/attempt/reclaim，pending table 不暴露给 graph：纯 header/pending 预取提前，identity validation/消费和一包一次 syscall 保序执行，receive returns、lane/global outcome counters 汇总后更新；不得把有效 Root buffers 一起 `vlib_buffer_free`。合法 TUN completion 由 origin native free 后才释放 return stamp/credit，仍以保存的 completion 值调用 `product_vpn_tun_return_freed:292`；batch free 的清单要与 Root 回池、无效/replay carrier 区分，且不能跨 free 再读 buffer。[Root settlement](../../../src/product/vpp/product_root_nfqueue_adapter.c#L895)、[receive pool return](../../../src/product/vpp/product_root_receive_pool.h#L61)、[TUN settlement/credit](../../../src/product/vpp/product_vpn_tun_adapter.c#L220)

`product_nfqueue_send_verdict:629` 当前每包调用 `product_nfnl_fill_header:478` 清零并构造常量 netlink/NFGEN 部分，再填 verdict、packet ID、attribute。Root module 可在短 batch 内为每 lane 准备一份固定-size request template，后续只按已验证 item 填 `id/verdict`，继续一次 `sendto`；socket/generation/lane 和 send flags 仍逐 item 判定，不能把 template 当作跳过 identity 校验的授权。`returned_mask` 只报告 receive pool 回收，verdict attempt/succeeded/failed/unknown 另由 adapter 记录，graph 不能从回收 mask 推导平台 outcome。[verdict 构造](../../../src/product/vpp/product_root_nfqueue_adapter.c#L629)

Origin 可集中更新普通 graph 生命周期计数：buffers/completion carriers 对所有实际回收项扣数，obligations/settlements/returns 排除 replay；只有完成物理回收后才扣债。trace 所需 token、generation、source 保存于按值 scratch。中间 counter 快照和 fault/teardown 判断若依赖逐包可见性，必须保留其线性化位置，不能为了少几个 atomics 提前把全部 frame 记作已结清。terminal basic observation 仍在 fragment fanout 前按最终 logical IP packet 计一次，origin originals 数不能代替它。[现行 counters:2236](../../../src/product/vpp/product_packet_graph.c#L2236)、[logical observation:2049](../../../src/product/vpp/product_packet_graph.c#L2049)

首轮 batch 可以保留逐包 `sendto` verdict 和 `write` TUN syscall。NFQ header template/projection、prefetch 和 counters 的批准备已是独立机会。若后来研究 `sendmmsg`，必须单独验证发送前缀成功、未发送尾部、失败与 genuinely ambiguous outcome 的逐 identity 分类，以及不可重试物理 verdict 的 settlement；不能默认 bulk syscall 正确。`NFQNL_MSG_VERDICT_BATCH` 接收一个 max ID 和 verdict，对该 queue 中该范围的 entries 应用同一 verdict，不能替代任意 packet IDs/混合 intents 的批完成；这个接口语义由 Linux v6.1 源码核对，不是当前 Pixel kernel 的新增验收。该优化没有参考 fork 成熟实现或本轮设备证明，不列为这份设计图的既定依赖。[kernel batch 范围与 reinject:1018–1061](https://github.com/torvalds/linux/blob/v6.1/net/netfilter/nfnetlink_queue.c#L1018)

建议依赖顺序是入口提供可用多包 frame → publication 短窗口与 failed-subset credit mapping → 同 backlog compact retry → origin completion prepare/reclaim。各段可以独立设计，尤其 origin/FQ receiver 已可能收到聚合 frame；入口 singleton 不代表所有段均不能改进。第一轮继续保留 owner mapping、capacity bypass、native notification、generation teardown、fragment originals 与 platform one-attempt settlement，不用扩容换批量。静态结构只能证明机会和边界，不能排序真实热点或承诺加速比例。
