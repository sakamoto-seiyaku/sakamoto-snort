## 一手支持与推论边界

[1983 Aspen](https://book.stevejobsarchive.com/#speech-aspen-1983)把对象、软件和交互一并认真对待；[1984 Moritz](https://book.stevejobsarchive.com/#interview-michael-moritz-1984)把精度、尺度与同样功能联系起来；[Objects 的 Jobs 逐字稿](https://stevejobsarchive.com/stories/objects-of-our-life)强调已有经验、一致机制及丰富表达。[1997 访谈](https://book.stevejobsarchive.com/#interview-company-of-giants)同时承认理想可能妨碍实际改进。Ive 的创作回忆是其自己的证言，不能当 Jobs 的规则界面指令。
由此，本席追问：人能否先认出自己想改变的对象，形态能否表达条件、动作与使用的关系，深入是否增加能力而不强迫换成后台思维。它们不证明两导航、某种树或任何页面必然正确；下面是本席愿承担代价的选择。

## 撤回的前提与明确首选

撤回“必须存在第三联网安排入口、规则定义主页及独立控制线”。UI 不按 API 模块分区；有规则模型不等于用户需要一个规则后台。
**本席首选无第三控制导航：**概览/活动保留调查，应用与事实可直接改变以后的处理；固定对象搜索服务已知命名内容，可见目录和意图式新建负责发现能力。命名规则、组、名单可直接打开为对象，完整条件编写是该对象的一项有开始/结束的编辑任务。
**最强备选：**独立按对象的安排工作台，便于反复跨应用、共享内容、分配和顺序维护。它可减轻专业扫描成本，却要求普通人先把调查和决定分成两个世界。本席不因少一个入口而自动胜出，也不因后台有三个资产类别而保留它。
**代价：**专业作者找共享内容、跨规则扫描和集中分配多一步；概览要为目录与新建留固定空间。明示的改变任务仍存在，取消的是永久第三工作区，不能把编辑能力本身藏掉。

## 空设备怎样发现完整能力

393 首屏保留可信范围与时间，空态写“暂无活动记录”；固定“全部应用：查看与改变联网方式”，目录包含没有活动的应用，并可“选择多个应用”。不等待被阻止事件或搜索命中才出现控制。
点天气后，“改变以后的联网方式”先给人类意图：限制所有联网、在某些网络限制、只允许选定活动、先观察一类活动（不阻止）、详细表达；不先问选择规则/组/名单模板。
选择活动时显露名称、协议、地址、网络等真实条件。只允许选定活动须呈现普通 ALLOW 与末尾 catch-all DROP，不制造隐含白名单胜出。完成前选择只用于此应用、同时用于多个对象或命名保存供以后复用。
固定＋也允许“新建处理，稍后使用”“整理一起使用的处理”“添加匹配资料”。专业用户可从零创建未分配内容；搜索是捷径，不是发现深度的唯一办法。未使用是有效状态，不用警告色冒称失效。
**API 类型边界：**已有 IP/CIDR、协议谓词和名称名单，不据此发明独立 CIDR 名单资产。尚未使用的 CIDR/协议内容可是一条可复用普通规则；名称名单可以独立创建，创建不自动阻止。

## 真实模型怎样约束漂亮操作

- 应用实际顺序按 priority、明确 order、稳定逻辑身份；有效顺序默认只读。调整共享排序先列全部使用者；只改天气须明确复制局部规则并处理旧来源。拖动组成员不产生胜出优先级。
- 同规则/对象/有效模式重复引用执行一次，保留全部来源；不同身份即使条件相同也不合并。去重行不给含糊“关闭”，解除发生在真实使用关系；删除共享内容另外处理全部引用。
- 模式属于 binding，组内边继承它；改组 binding 可能影响其他成员。T04 的隐式 UID 使用固定 enforce，不能假装可直接切 observe；转换需明确可复用规则及相应 binding 的完整变更，或进入使用编辑。
- NOT 不把缺失变 true；确认无 SNI 是独立事实。含 SNI 规则顶端短签“需已识别 TLS/QUIC”，NOT 叶旁“未知不等于不满足”；有本次预演输入才标具体不足，不把定义无输入当语法错误。单条不足不伪造整个评估未知；可完成评估时仍给其他胜出规则及真实动作，未提供合成输入与已确认不可用分清。
- 当前全网快捷限制是最高普通 DROP。局部允许面板先说明“这条允许不会改变实际阻止”，给真实压住它的首项；明确解除快捷后回同一局部输入。高级作者仍可保存暂不能胜出的 ALLOW，但结果不叫恢复。
- 空集/完整全不命中默认 ALLOW 与显式最低 catch-all DROP 分别呈现；组没有默认动作。observe 的声明 DROP 不冒充实际丢包。

## 整个既有旅程的功能归宿

| 能力 | 无第三工作区下的明确归宿；保留的深度 |
| --- | --- |
| 快捷网络限制、批量、作用对象 | 应用/目录选择后的意图任务；显露资料/完整 UID 与共享身份影响，网络是条件，程序名不假装独立控制身份。 |
| 细条件、动作、排序、复制 | 命名处理对象编辑；保留 AND/OR/NOT、协议、SNI、地址/端口、方向等字段与可用性，复制产生真实新身份。 |
| 组成员、嵌套、组合管理 | 命名复用组合对象；组结构与全应用有效顺序分清，循环/缺引用错误定位，组不发明公共胜出或默认动作。 |
| 分配、仅观察、局部解除、共享修改 | 对象的真实使用关系；逐项或明确全部影响，组修改涵盖其他成员；解除不等于一律允许，删除不等于解除一处。 |
| 名称资料、导入、订阅、本地例外 | 匹配资料对象及明确来源/内容编辑/候选审阅；本名单排除不等于全设备放行，应用局部例外留在应用决定。 |
| 预演、observe、后续核对 | 本次决定及对象“更多检查”；预演区分通道和配置输入，observe 是真实使用模式；后续只以实际新事实核对，不由保存推出恢复。 |
| 保存、生效、纠错、配置导入导出 | 本次完成层与设备资料管理；完整替换审阅实质差异，保留旧使用快照/新保存输入，版本冲突与不确定回复不盲重试。 |
| 地图、统计与拦截证据 | 原观察范围到应用/真实连接/目标再决定；地理是位置，不是风险或已接受规则字段，DNS 阻止不画成已访问地图路径。 |

这是归宿提案，不是全功能验收；没有新增 checkpoint、计费、限速、定时、第二规则库或新持久“方案”类型。DNS 按目标能力设计，当前未接通不删体验；具体 DNS 后台合同未由此冻结。

## 实际互相反驳、改判与未接受的方案

| 真交流 | 对方反证/答复 | 本席判断 |
| --- | --- | --- |
| 本席→设计席两问 | 定义与使用应分任务但不必独立主页；observe DROP 先表达实际允许；最高快捷 DROP 不暗改成带例外规则，解除后回局部输入。 | 采纳；撤掉带例外快捷开关备选，它破坏简单开关含义，值得付一次明确解除。 |
| 本席→B 两问，B 实答 | 去重实际规则先显示全部来源；统一一条规则的 mode 会连带组内其他规则，漂亮 toggle 可能虚构能力。 | 采纳逐来源真实关系；收回按去重规则一键统一 observe，接受一行来源与组影响空间。 |
| B→本席两问，本席实答 | NOT 缺失与 SNI 整条前提必须显露；共享排序不能假装仅天气拖动。 | 选结构树/相关短签/输入理由；有效顺序只读，明确共享修改，局部复制有真实成本。 |
| 本席→B 的合同反证，B 实答 | 隐式 UID enforce 不能直接改 mode；B 明确接受并修正逐来源措辞。 | 转换须列实际完整变更；本席也接受单条不足不掩掉其他真实胜出结果，准确性不靠一张漂亮开关。 |
| root→本席→设计席 | 搜索不能让新人发现协议控制、默认 deny、批量。 | 撤搜索足够；加入空设备可见目录/批量与意图任务＋专业新建，承认必要的任务空间。 |
| 设计席→本席唯一反问 | 是否接受复用作者多一步；无对象时 CIDR/协议内容怎样创建。 | 接受深入成本；反对暗增 CIDR 资料类型，给未分配普通规则/真正名称名单路径，已真实发送。 |

设计席已明确选择无第三控制导航，并接受上述定义/使用关系及最高 DROP 语义；最终整线裁决仍由其给出。本席以具体理由反驳，不因其席位名称停止质疑，也不把未决误写为全体一致。
仍保留的最强反证是专业持续维护能否在对象入口下高效扫描、统一分配并发现全部深度；若这项工作需要固定空间，可保留有明确目的的维护任务面，不能偷偷把它变成所有用户的控制首页。此反证影响取舍，不取消当前无第三首选。
